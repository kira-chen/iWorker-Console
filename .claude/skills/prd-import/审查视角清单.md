# 审查视角清单（prd-import 阶段五「多视角验收」用；2026-09-17 由六个角色 agent 压缩而来）

用法：改造批次收口时，主流程按下表**每个视角派一个只读 agent**（任务书 = 本视角检查点 + 本批改动清单 + 权威基准路径），agent 以文本回报「结论（通过 / 需修改）+ 问题清单（页面/场景、现状、依据、严重度：阻塞/严重/一般/轻微）」；主流程汇总后按「实现缺陷 → 当场修」「口径问题 → 待办/03」「可选建议 → 记 commit message」分流。小批次（≤2 个页面、不涉共享层）可只派 A、B、F 三个视角。

agent 规则：只读、不改文件、不跑 git 写命令；每条发现带 `file:line` 或页面路径 + 复现步骤；**审查人 ≠ 作者**——派发时避开出该批次代码的 agent 上下文；不确定算问题，宁全勿漏。

## A 产品口径（原「产品经理」）

1. 页面文案、提示语、确认弹窗措辞与模块 md **逐字**对齐；差一个字算 B 类微差，差语义算 C 类。
2. 表单必填/选填、字数上限、错误提示逐字段对照《各模块必填选填字段一览表.md》。
3. 页面上「超出 md」的能力：先回查基线表起点以来的 commit 说明与「按 Qn」注，排除已拍板扩展，再定性为 E 类。
4. md 与近期负责人拍板冲突的点：**不定性、不取舍**，列出交裁决。
5. 状态流转（发布 / 审核中 / 撤回 / 停用等）的每条边与 md 状态机一致，缺边、多边都列。

## B 实走验收（原「测试工程师」）

1. 起 dev 服务用 Playwright **真实走一遍**改动路径（免登录直达 `/admin/...`），不只读模板；console / pageerror 必须零错误。
2. 交互流逐步取证：操作 → 期望结果 → 实际结果，附截图路径（会话临时目录，不入库）。
3. mock 语义：状态机流转、持久化 `persist()` 落盘与刷新读回、改种子后 version 是否 bump、`?resetMock=1` 能回初始。
4. 共享层（utils / 公共组件 / stores）被改时，抽 2 个非本批页面回归实走。
5. 单测：改动文件对应的 `__tests__` 有没有跟着改；新增行为有没有用例守；`skip/only/todo` 仍为 0。

## C 代码审查（原「架构师」）

1. 组件职责单一；页面不直连 mock，走 `api/xxx.js` 封装 + `USE_MOCK` 分流；mock 数据不散落进组件。
2. **共享层改动**（utils 枚举/纯函数、公共组件、tokens）：列出波及页面清单，确认全量 vitest 跑过；改公共件优先加参数而非分叉复制。
3. 不硬编码色值，只用语义令牌；Scoped CSS；Pinia 用法与既有 store 一致。
4. 可读性（工程大原则②）：新代码是否让研发一眼看懂——命名、注释密度与周边一致，没有为过测试而写的绕路逻辑，没有死代码/幽灵导出。
5. 不引后端、不引新技术栈、不引重型依赖；引新 npm 包要说明必要性。

## D 视觉与交互一致性（原「UI 设计师」）

1. 布局骨架与站内同类页面一致：容器限宽/居中/底色、卡片分区与区块头、表格密度、分页条位置。
2. 浅/暗双主题都截图看：无硬编码色、暗色下可读、输入框编辑态是白底可输入（只读逻辑泄漏高频点）。
3. 状态完整：loading / 空态 / 错误态 / 边界（超长文本、0 条、上限）都有呈现且与同类页面一致。
4. `docs/规范/UI/` 设计图仅作参考：列序、时间列、查询按钮以代码现状为准，不按图上数据对齐。
5. 同类操作处处一致（按钮位置、确认弹窗结构、状态标签配色）；不自创第三种范式。

## E 最终用户走查（原「最终用户」）

用最普通业务人员的眼睛、**大白话**回报，不接受技术术语。

1. 不看说明书，第一次用能不能完成核心操作？入口找不找得到？
2. 按钮、标签、提示里有没有看不懂的词（Skill / MCP / Token / 枚举值原文）？
3. 出错时提示能不能让我知道发生了什么、该怎么办？有没有错误码或技术描述漏出来？
4. 危险 / 不可逆操作（删除、提交、停用）有没有确认？办错了能不能撤回？
5. 空白状态有没有引导？等待有没有提示？相似操作在不同页面行为一不一样？
6. 终验标准：**拿着这个页面能不能直接向领导 / 客户演示**——卡壳、看不懂、报错即不通过。

## F 前端实现自检（原「前端开发」，由实施 agent 在交付前自己过）

1. `npm run test` 全量绿（改了共享层必须全量）；`npm run build` 通过。
2. 改动路径 Playwright 实走一遍并截图，与 md 描述比对。
3. loading / 空态 / 错误态齐；「AI 生成」类用本地模板模拟，不接真实模型。
4. 登录与权限已取消（`utils/demoIdentity.js` 内置演示管理员），勿恢复登录逻辑。
5. 与 md 有出入的实现问题：不自行改口径，列清单回主流程。
6. 需要别人处理的事：报主流程记入 `docs/产品经理待办任务/<人>.md`。
