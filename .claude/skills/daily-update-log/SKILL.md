# 改动与 PRD 对齐记录（docs/PRD-review）

按仓库约定（2026-09-01 起），改动记录统一写入 `docs/PRD-review/YYYY-MM-DD.md`，文件名取**北京时间**自然日。
`docs/update/` 与 `docs/API迭代需求/` 已停止更新，仅作历史存档，**不要再往里写**。

## 步骤

1. 取北京时间日期：`TZ=Asia/Shanghai date +%F`
2. 目标文件 `docs/PRD-review/<日期>.md`：存在则**追加**一节，不存在则新建
3. 用三段式写一节：

```markdown
## <模块>：<一句话标题>

**需求/问题**：为什么要改，触发点是什么

**方案**：实际怎么改的，关键取舍

**影响面**：动了哪些文件/组件/mock 数据；是否影响其他页面与既有行为
```

4. PRD 对齐类工作（照 `docs/prd/PRD-20260828/` 校对页面）额外附**差异清单**：
   逐项编号列出「与 PRD 仍有出入 / 需负责人拍板」的点，标明当前取舍，供逐项确认与销项。

## 硬约束

- **PRD 对齐铁律**（详见根 CLAUDE.md）：对齐基准 = 各模块 prd md + PRD-20260828 根目录《数字员工管理端-模型MCP用户-交互原型-v2.html》，两者应一致；截图只是参考。md 与交互原型不一致 = PRD 内部缺陷，记入差异清单待负责人裁决，不自行取舍
- 项目为纯前端 demo：影响面按「页面/组件/mock 数据层/全站共享层」口径写，不再涉及数据库表与对外契约
- 只记本次真实落地的改动，不写计划中或未验证的内容
