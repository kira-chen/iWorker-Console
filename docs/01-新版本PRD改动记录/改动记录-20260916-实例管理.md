## 2. 变动主题一：实例与会话收敛为实例管理

**需求/问题**：当前产品中一个会话对应一个任务，不存在一个会话承载多个任务的管理关系。会话运行状态又与任务状态高度重合，单独建设会话监控会造成管理对象和统计指标重复。

**方案**：模块名称统一为“实例管理”；保留按规格、按岗位、实例明细和实例详情；删除会话页签、会话汇总/明细/详情，以及实例中的任务情况、运行中任务数、排队任务数和关联会话入口。

**影响面**：管理菜单、路由、页面权限名称、实例管理页面、API/mock、测试和长期PRD。

## 3. 变动主题二：会话分析能力转移到独立模块

**需求/问题**：管理侧对会话的真正关注点是模型调用量、输入/输出Token、成本和异常消耗，不属于实例运行处置。

**方案**：本批不建设会话运行监控；后续由独立“Token用量与成本”模块按用户、岗位、模型和会话承载分析能力。

**影响面**：实例管理不再承担Token或成本统计；本批也不新增该独立模块。

## 4. 变动主题三：运行操作依赖服务端可操作状态

**需求/问题**：取消任务数量字段后，前端不能再用任务数推断实例是否可重启、重建或回收。

**方案**：运行操作以实例对象的`operable`和`operationHint`为准；前端操作前校验，接口执行时再次校验。Demo通过API/mock层表达该契约并使用浏览器本地持久化。

**影响面**：实例API/mock、页面按钮状态、确认弹窗和操作记录。
