## 连接器-API：鉴权新增 Bearer Token + 星火智能体平台接入样例（OpenAI 协议 v3）

**需求/问题**：iWorker 需通过 API 方式接入星火智能体平台已发布的智能体 / 任务链 / 知识库能力。
选型分析后拍板走 **v3 OpenAI 协议**（HTTP POST + `Authorization: Bearer appId:appSecret` 静态鉴权）：
原生 v2 是 WebSocket + HMAC-SHA256 逐请求动态签名，超出通用 API 连接器「静态配置」模型的表达能力，放弃。
当前鉴权类型仅「不鉴权 / API_KEY」，无法语义化表达 Bearer；样例数据也无智能体平台接入示例。

**方案**：

- 鉴权新增 **BEARER** 类型（标准通用设计，非星火专属）：单 Token、请求时自动以
  `Authorization: Bearer <token>` 请求头静态附加、无参数名/位置概念；Token 按敏感信息同规则处理
  （密码态输入、不回显明文、编辑留空=保留原值）。新增 `loadedAuthType` 记录详情加载时的鉴权类型：
  API_KEY↔BEARER 互切后「留空=保留原密钥」不再成立、必须填新值（顺带修正原 API_KEY 占位提示在
  类型切换场景下误示「留空保持不变」的问题）。
- **不做「固定参数/预设参数」能力**（拍板：页面保持通用 API 接入配置，不针对智能体平台特化）；
  bodyId / appId / stream 等接入期固定值写进 requestSchema 字段描述中说明。
- **mock 只加样例数据、不加后台逻辑**：新增服务提供系统 `pv_4 星火智能体平台` + 3 条 BEARER 鉴权
  API 种子（`api_1105` 智能体会话[已发布/健康]、`api_1106` 任务链执行[write、未发布待验证]、
  `api_1107` 知识库问答[已发布/健康]）；三者同一 v3 端点靠 bodyId 区分，request/responseSchema
  按 v3 协议字段完整声明（messages / sessionId 续聊 / choices.delta / usage 等）。

**影响面**：`utils/defValidate.js`（API_AUTH_TYPES 枚举 + mapApiAuthFromDetail 回填）、
`components/admin/ApiEditor.vue`（鉴权区三态分流 + 校验 + 请求组装）、`api/apiConnectorMock.js`
（validateApiPayload / connChanged / applyApiPayload 放行 BEARER + pv_4 与 3 条种子、psSeq/apiSeq 顶号）、
`utils/__tests__/defValidate.test.js`（补 BEARER 回填与未知类型兜底用例）。MCP Tab 与其他页面不受影响；
换 Token 同样触发连通性验证结果失效（与换 API KEY 同规则）。验证：vitest 1421 全绿、build 通过。
星火 v2/v3 协议文档已抓取分析，选型对比结论见本轮会话；MCP 方式接入（需外部桥接服务）整体后置。
