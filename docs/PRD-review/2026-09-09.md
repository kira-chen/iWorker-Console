## 前端改造：全站回归收口

**需求/问题**：复刻 4 批 + PRD 复核 2 波共 6 次提交后，需一次全站回归确认无破。

**方案**：派回归 agent 用 Playwright 覆盖 25 个列表页 + 岗位详情 10 页签 + 技能编辑/只读页 + 27 个抽屉弹窗 + 关键交互（MCP 三态筛选与查询、stdio env 三步式、岗位不完整保存出提示条、发布 toast 缺项并跳页签），共 105 张截图；另自查用户端四页与暗色主题。结果：**零 console error / 零 pageerror、全部页面无横向滚动与布局破损、暗色主题正常、用户端未被 `admin-scope` 越界影响、mock version 无撞号**。报出三个问题并当场修掉两个：

- **P1（严重）**：审核中心与我的申请的 API/MCP/业务系统/模型/知识库 5 类只读详情抽屉**内容恒为空**——审核人看到空白表单无从判断。根因：这 5 个编辑器的取数 watcher 都是「visible false→true 才 load」且缺 `immediate`，而 `GovObjectDetail` 是按 kind **条件挂载**、调用方又在同一 tick 同时置 kind 与 visible，子组件创建时 visible 已是 true，跃迁永不发生。对照可证：同一条数据从连接器页（常驻挂载）打开正常。修法：5 个 watcher 补 `{ immediate: true }`（load 内已有空 id 兜底，不污染新建态）。连带消除两个次生表现：API 抽屉误报「当前没有任何服务提供系统」、模型空表单仍渲染掩码密钥行。
- **P2（提示）**：MCP 三条 stdio 种子 env 全空，A11 新做的三步式「改值 / 待删除 / 撤销」开箱一个入口都点不到，演示易被误判为没做。修法：`local_files` 补两条 env 样例（一条平台值走掩码、一条客户端填写），补 `seedToMcp` 的 env 映射（原本种子字段会被丢弃），mock v4→5，并加种子护栏用例防回收。
- **P3（可忽略）**：字段字典页行内【编辑】非 `<button>` 结构，仅自动化可测性备注。

**影响面**：6 个文件；vitest 1882 全绿、build 通过；审核中心抽屉回填实测确认（名称/所属系统/图标/状态/描述/示例问题/请求配置全部有值）。git 5303c7c。

## 发布前测试审核轮：六路审查员 + 两批修复

**需求/问题**：负责人要求「组织团队针对 PRD 的描述对 frontend 代码做测试审核，尽可能完善掉，形成可发布版本」。此前 PRD 侧一致性整改已收官（02 底账 392 条全闭环），但那是**文档口径**的闭环，代码侧是否真的落到位、有没有 md 没覆盖到的真 bug，需要独立一轮实证。

**方案**：按模块切六路并行审查，每路都给「已知不必再报」清单（8 项既有裁决 + 上轮已修项）避免重复劳动：①岗位+岗位管理；②技能+专家+用户技能审核；③连接器(API/MCP/业务系统)+模型+知识库；④治理 5 模块+组织 2 模块；⑤运行时冒烟（Playwright 跑全站抓 console error/白屏/溢出）；⑥横向质量（mock persist 与 version、死代码、路由完整性、重复实现、build、密钥红线）。要求每条问题必须给 md 出处 + 代码位置 + 现状 + 应为 + 级别，只报实证过的。
