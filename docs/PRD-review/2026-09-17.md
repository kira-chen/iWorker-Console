# 2026-09-17 改动记录

## 岗位「人格」岗位名称迁移 + 「自动化任务」执行动作/执行模型

**需求/问题**：对照生产环境 `iworker-manage` 岗位工作台实际页面（负责人截图核对），岗位详情页顶栏的「岗位名称」编辑入口应收敛进「人格」页签，顶栏改为只读展示；「自动化任务」编辑表单缺少「执行动作」（触发时交给 Agent 还是按指定技能执行）与「执行模型」（该任务用哪个模型跑）两个配置区。同时，「执行动作」选 Agent 时应从该岗位已有 Agent 列表下拉选择（而非手填名称），单选标签用短标签「技能」/「Agent」；「执行模型」候选应为平台真实模型目录，而非占位用的境外模型名。

**方案**：
- 「人格」页签新增「岗位名称」卡片（必填、64 字上限），随顶部【保存】统一提交；顶栏「岗位名称」改为静态文本展示，编辑入口提示语指向人格页签。
- 「自动化任务」编辑表单新增两个配置区：「执行动作」（单选「技能」/「Agent」，选 Agent 时下拉选择该岗位下已有 Agent、下方提示「下发时会自动带上该 Agent 名下的已发布技能」）与「执行模型」（下拉可清空，候选 GLM5.3 / DeepSeek-V4-Flash（平台默认）/ GLM-5.2 / PaddleOCR-VL-1.6 / DeepSeek-v4-pro / Qwen3.6-35B-A3B（平台默认），默认空即跟随平台默认模型）。
- 表单字段 `execAgentName`（自由文本）改为 `execAgentId`（引用该岗位 Agent 的 `agentId`，与 `skillRefs.platformSkillId` 同一引用套路），mock 层 `toVO` / `normalizeUpsert` 同步改名。
- PRD md 同步改写 §2.1 岗位名称、§7.6 执行动作、§7.8 执行模型；执行模型候选在 PRD 里以「模型 — 标识」表格列出，供研发对齐下拉 value。

**影响面**：`frontend/src/components/position/PositionPersonaTab.vue`、`PositionDetailTabs.vue`、`SampleTaskEditor.vue`、`frontend/src/api/sampleTaskMock.js`；PRD 正本 `docs/PRD/数字员工管理端PRD/02岗位/岗位/prd.岗位.md`；测试同步补 `usePositionStore` 桩（`SampleTaskPrototype4B.test.js`、`SampleTaskEditorPrompt.test.js`、`positionDetailTabs.test.js`）。不涉及自动化任务其余 5 个配置区、不改「Agent 与技能」页签自身的 Agent 增删改逻辑。
