# PRD-20260904 md 与原型一致性审查结果（移交产品经理浦月确认）

> 建立于 2026-09-06。来源：负责人审阅《PRD-20260903-问题记录.md》后，将其中「PRD 文档侧需要修订/裁决」的条目指定汇总至本文件，提交产品经理浦月确认。每条注明来源问题编号（Q 号）与 demo 当前取舍；浦月确认后请直接修订 PRD（md/原型/一览表），修订结果将随下一版 PRD 导入流程回流核对。
>
> 说明：文中「md」指各模块 PRD 文字稿，「原型」指《数字员工管理端-模型MCP用户-交互原型-v2.html》（0904 版）。

## 一、待确认 / 待修订清单

### 1. API 编辑器「图标」字段去留（来源 Q1 余留半边）

- **矛盾**：prd-API.md 与《各模块必填选填字段一览表》均要求 API 图标**必填**；但 0904 原型的 API 编辑器**没有图标字段**（原型早期补丁层曾注入过，最终态移除）。
- **demo 现状**：保留图标字段且必填（2026-09-02 拍板加回）。
- **需要确认**：图标到底要不要？要 → 请补进原型；不要 → 请从 md 和一览表删掉必填要求。

### 2. 【待办】提供「示例问题」AI 生成的正式 prompt（来源 Q1 负责人拍板）

- **背景**：负责人已拍板——API/MCP/业务系统的示例问题**需要填写**，并且可以根据「名称 + 描述 + 具体配置」由 AI 生成。
- **demo 现状**：三处编辑器均已有【AI 生成】按钮，目前用的是本地模板占位生成（不是真实模型调用）。
- **需要浦月做**：提供生成示例问题的正式 prompt（说明用哪些字段作为输入、期望的输出风格与条数），供后续接入真实生成时使用。

### 3. 岗位发布：载体与校验范围双口径（来源 Q3 + Q12）

- **矛盾**：岗位 md 内部并存两套发布口径——
  - §3.7（0904 新增）：发布走**版本管理侧栏**，与版本管理共用校验（与 demo 现实现一致）；
  - §3.3 残留旧句：发布要"打开**发布前检查弹窗**"。
- 连带三个子矛盾：① 阻断校验 md §9.1 列 **7 项**（名称/图标/描述/认领说明≥1/示例问题3/SOP/采集字段），原型 validate() 只查 **4 项**（名称/描述/示例问题/SOP）；② md 写"Agent 与技能**不阻断**发布"，但原型旧发布弹窗含"≥1 Agent 且每 Agent ≥1 技能"硬阻断；③ 原型发布弹窗版本号为 v001-v999，与 md/现实现的语义化版本 vX.Y.Z 不一致。
- **demo 现状**：发布走版本侧栏 + 4 项校验 + 语义化版本。
- **需要确认**：删掉哪套口径、校验最终几项、版本号规则统一成哪种。

### 4. 岗位管理 md 引用截图缺失（来源 Q6）

- **问题**：prd.岗位管理.md 引用的 `岗位分配-申请审批列表页.png` 在 0903、0904 两版磁盘上都不存在（0904 版见 L94），引用悬空。
- **需要确认**：补图，或删掉该引用。

### 5. 岗位「认领说明」区命名两套措辞（来源 Q7）

- **矛盾**：md 叫「**岗位认领说明**」（新增/保存/取消/删除、空态文案一套）；原型终态叫「**领用页文案**」（行内编辑、toast「领用页文案已保存」，卡片头说明"员工领用时看到的卖点，可多条，最多 6 条"）。
- **demo 现状**：区块标题/空态/toast 用 md 措辞，卡片头说明文字用原型措辞——两套并存。
- **需要确认**：统一用哪套措辞。

### 6. 岗位「业务系统」页签形态（来源 Q8）

- **矛盾**：md §三.8 =【添加业务系统】按钮 / 可移除引用 / 列 = 名称、图标、描述、状态；原型 =「＋ 新业务系统」/ Picker 标题「引用业务系统」/ 列 = 登录地址、业务页、最近更新时间 / 仅【查看】不可移除。
- **demo 现状**：按 md。
- **需要确认**：以哪边为准，请把另一边改齐。

### 7. 知识库可见范围与岗位数据的关联口径（来源 Q11）

- **问题**：知识库演示数据里的岗位（销售顾问/HR 专员）与岗位模块演示数据（经营分析岗等）不同源，导致岗位工作台「知识」页签按可见范围过滤后为空态。PRD 未明确知识库可见范围选「岗位」时与岗位主数据如何关联。
- **需要确认**：PRD 明确关联口径（建议按岗位 id 关联），演示数据将随之统一。

### 8. 岗位申请可绑定岗位范围 + 置顶高亮解除时机（来源 Q13）

- **矛盾**：md §五写"可绑定岗位**仅包括已发布岗位**"；但原型演示种子里的申请指向的是**未发布**岗位（审批「通过」会绑到未发布岗位）。
- **另**：md 未定义审批列表「置顶高亮」何时解除（demo 现状 = 下一次查询/筛选/翻页时解除）。
- **需要确认**：种子数据与规则以哪边为准；置顶高亮解除时机请补进 md。

### 9. 原型 HTML 缺陷：审批表头 sort 按钮未闭合（来源 Q14）

- **问题**：原型（0903、0904 两版均在）审批列表表头 L1562 附近「提交时间」的 `<button class="sort">` 标签未闭合，属 HTML 笔误。
- **需要做**：修原型。demo 侧排序交互已按 md §4.1 文字稿实现，不受影响。

### 10. 知识库「可见范围」创建后可否修改自相矛盾（来源 Q16）

- **矛盾**：md §三.3.1 写专家/岗位可见范围均"创建后不可更改"；§三.5 又写"变更可见范围需重新发布"（暗示可改）；原型行为 = 专家锁定、岗位可改。
- **demo 现状**：按「专家建后锁、岗位可改且已发布的改动后回未发布」。
- **需要确认**：统一口径写进 md。

### 11. 知识库 MCP 超时默认值 md 缺数值（来源 Q22）

- **问题**：md §七.6 只写"必填，使用系统默认值并允许用户直接修改"，没给数值；0904 原型已明确默认 **10000ms**、范围 **1000～120000**。
- **demo 现状**：按 10000ms / 1000～120000。
- **需要做**：把数值写进 md（确认与原型一致即可）。

### 12. 知识库列表数据源连排的分隔样式（来源 Q23）

- **矛盾**：md/标准件口径 = 「上传 ×2 / API ×1」计数式；原型 = 各数据源名用「·」分隔连排。
- **demo 现状**：按标准件计数式。
- **需要确认**：以哪种展示为准。

### 13. 专家背景色演示数据全为默认色（来源 Q25）

- **问题**：0904 md 已定背景色为固定 7 色，但原型演示种子未给任何专家配 backgroundColor，归一化后全部落默认色，列表看不出着色差异。
- **需要确认**：演示数据是否应给不同专家配不同背景色（是 → 请在原型种子/PRD 示例中体现，demo 种子随之更新）。

### 14. 《AI生成按钮Prompt规范.md》与各模块 md 三处矛盾（来源 Q5）

需要分别拍板的三个子问题：

- **① AI 按钮的粒度**：专家/MCP/API 的 md 写"**每个输入框旁边各放一个**按钮，点一次生成 1 条"；规范文档与原型写"**整个示例问题区只放一个**按钮，点一次生成 3 条"。demo 现状 = 区级一个按钮、一次 3 条。→ 请定按钮按"每行一个"还是"每区一个"，并把另一侧文档改齐。
- **② 生成内容字数上限打架**：规范给 AI 生成内容定了通用上限（约 60 字）；但岗位 SOP 的生成要求是"不超过 400 汉字"，长文本套 60 字上限会把内容截没。demo 现状 = SOP 生成按 400 汉字口径、不套 60 字限制。→ 请在规范中明确长文本场景（如 SOP）按各自模块上限豁免通用上限。
- **③ 规范漏收"业务系统"场景**：业务系统 md 明确有 AI 生成按钮，但规范列举的 6 个使用场景不含业务系统。demo 现状 = 照业务系统 md 做了按钮。→ 请把业务系统补进规范（或明确它不该有 AI 按钮）。
