## 全站页头改为「标题 + 副文案」左右结构

**需求/问题**：负责人指示（附岗位管理页截图圈注）——页面标题与正文描述由上下结构改为左右结构，**所有页面都要改**。

**方案**：核查确认全站**全部走共享组件** `components/PageHeader.vue`，无一处手写页头，故一处改即全站生效，无需逐页改造。

改动仅两处 CSS：①`.page-header-text` 由默认块级堆叠改为 `display:flex + align-items:baseline + gap`，标题与副文案同行、基线对齐；**保留 `flex-wrap: wrap`**，窄屏副文案挤不下时自动折行，不硬挤两列。②`.page-header-sub` 去掉原 `margin-top`（纵向间距改由父容器 gap 承担，否则破坏基线对齐）。仅用语义令牌，无硬编码。

> 口径更正（负责人当场纠错）：原记「25 个管理端页面」不实。实际引用 PageHeader 的调用点 **26 处** = 左侧菜单内有实体页面的管理页 14 个（另 5 个菜单项是「开发中」占位）+ 菜单外管理页 5 个（报表 ×2、运行规格、知识库、用户反馈等）+ **员工端 7 个**（定时任务/任务详情/任务编辑/个人空间/个人记忆/设置/搭子）。原表述既把员工端页面算作管理页、数也不准；改动范围与结论不受影响（26 处全覆盖）。

**影响面**：1 个共享组件（波及 26 处调用点）；**vitest 149 文件 1838 条全绿、零断言改动**、build 通过。实走验证四种页头形态（纯标题+副文案 / 带操作按钮 / 带 emoji+徽标+作用域选择器 / 普通列表页）均同行渲染、基线对齐（标题 top 26 / 副文案 top 33、同行判定 true）、右侧操作区未被挤坏、零 console error。

## 列表页视觉对齐《列表页UI.png》+ 表格禁止换行

**需求/问题**：负责人提供 `docs/05-UI规范/列表页UI.png`，要求以此为准修改各列表页的**布局样式与视觉颜色**（不改文本内容）。追加指示：表格内**表头、定类型字段（版本号/整数/日期时间等）、操作项一律不换行**。同日确认 yuepu 09-10 提交的 `docs/UI设计规范.md` 作废并删除（内容仍可经 git 历史 `08b9c14` 取回），后续另行更新。

**方案**：

1. **取色不靠肉眼**：写脚本对设计稿逐区域采样（众数取底色、最深值取字色），拿到确定值后再落令牌——沿用 09-10「视觉对齐必须先全量对表、不得凭肉眼比对」的教训。实测值：操作链接蓝 `rgb(33,107,255)`、状态橙 `rgb(250,131,12)`、危险红 `rgb(250,57,70)`、主按钮近黑 `rgb(20,22,25)`、表头底 `rgb(247,247,247)`/字 `rgb(141,141,141)`、行分隔线 `rgb(235,237,240)`、页面底 `rgb(252,252,252)`、副文案 `rgb(142,142,142)`。
2. **改共享层，不逐页改**：全站列表页的分页/工具栏/操作列/表格样式均已收口到 4 个共享文件，故改 `tokens.css`（新增 `--c-admin-link` 等 8 个令牌 + 暗色映射）、`theme.css`（`.tbl-ops` 操作链接三档配色）、`admin-shell.css`（表头/分隔线/分页当前页描边框）、`list-page.css`（`.lt-create` 近黑主按钮）即全站生效。
3. **不动品牌绿**：稿面操作链接是蓝色，但 `--c-accent` 被全站主按钮、侧栏头像、聚焦环、标签共用，改它会把整个产品染蓝、远超列表页范围。故**操作链接单立 `--c-admin-link`**，品牌绿保持不变（标签、选中态仍是绿）。
4. **不换行分三条落**（不是一把梭给所有单元格——名称列/描述列/多标签列需要换行或省略，全表禁用会横向撑爆表格）：①表头全局 nowrap + 省略号；②操作列（右侧固定列）整列 nowrap；③定类型字段挂 `.col-nowrap`，共 49 列（15 个文件），类名常量 `COL_NOWRAP` 登记在 `tableLayout.js`。
5. **`AdminUsers` 归一**：该页操作列因「更多」下拉自定义了 `.users-actions`、不吃 `.tbl-ops` 配色（改后全站蓝、独它绿）。补挂 `tbl-ops` 类使其继承共享配色，本页仅保留特有的 gap 与下拉微调。

**影响面**：4 个共享样式文件 + `tableLayout.js` + 16 个列表页；**vitest 149 文件 1838 条全绿、零断言改动**、build 通过。

验证（脚本化，非肉眼）：①16 个后台页面实测 **零表头截断、零单元格换行、零新增横向溢出**；②改前先 `git stash` 跑同一脚本取基线比对——6 个页面的横向溢出（技能 1403px、运行规格 1360px 等）**改前就存在、非本次引入**，其中岗位页因本次列宽重定反而由 1273→1261px 收窄；③浅色/暗色双主题均验（暗色下近黑主按钮会与页底糊成一片，故暗色映射为浅底深字）；④员工端回归：`.list-pager` 类名与 `Space.vue`/`MemoryManage.vue` 的 scoped 同名类撞车，故后台分页改动全部限定 `body.admin-scope`，实测无 admin-scope 作用域下仍是原绿软底、零边框，员工端未受影响。

**遗留**：岗位/技能/模型/用户反馈/连接器/运行规格 6 页存在**改前既有**的表格横向溢出（列宽总和超视口），本次未处理——属列宽预算问题、与本次视觉对齐不同源，建议单独一轮按 `tableLayout.js` 重算列宽预算。

## 列表行高收紧至 48px 档 + 时间/标签字段完整展示

**需求/问题**：负责人指示——①列表行高调整为「icon 与文本高度 28px + 上下各 10px 间距」；②连接器、审核中心这类**两行数据的页面先保持不变**；③但时间字段要展示完整（审核中心提交时间当时被截成「2026-08-28 09:4…」）。

**方案**：

1. **行高 48px 档**：`td` 高度由固定 60px 改为 `height:48px`（EP 的 height 实为下限，内容更高自然撑开），`.cell` 给 `min-height:28px + padding:10px 16px`，精确表达「内容 28 + 上下各 10」。实测单行页内容高 28px、`.cell` 48px、行 49px（含 1px 行线）。
2. **行内图标统一压到 28px**：各页原本各自写 32px（`.ex-avatar`/`.pos-icon`/`.mc-icon`/`.sk-icon`/`.md-logo`…），32px 会把行顶到 52px 吃不到 48px 档。在共享层统一压 28px（字号 18→16px 防 emoji 贴边），**改一处覆盖各页**，各页的圆角/底色仍归各页自己管。
3. **两行页保持不变**：连接器/审核中心/知识库等「主名 + 副描述」结构退回「0 纵向内距 + 60px」档，与改造前**逐像素一致**。
4. **时间与标签放宽**：`COL.TIME` 152→168（时间实测需 156px，152 差 4px 致截断）、`COL.TAG` 104→136（审核中心「新版本发布」标签实测需 119px）；登录明细「终端」列由 `COL.STATUS` 改 `COL.TAG`（值是 Windows 标签不是状态词，84px 放不下）。

**影响面**：`admin-shell.css` + `tableLayout.js` + `AdminLoginLogs.vue`；**vitest 149 文件 1838 条全绿、零断言改动**、build 通过、暗色主题同验（行高/内距/图标与浅色一致）。

**验证**：15 个后台页面实测——单行页行高 48~49px 全部达标；连接器/审核中心稳定 60px 未变；**截断由改前 6 页 9 处降为 0 处**（改前：专家/技能/审核中心/我的申请/登录明细的时间被截、审核中心与我的申请的「新版本发布」被截、连接器 streamable-http 被截）。我的申请 62px、角色 109px、运行规格 63px 系内容本身较高（副描述/权限块）自然撑开，非未达标。

**踩坑记录（判据选错一次）**：区分「单行 vs 两行」最初用 `:has(> .cell > div)`——按"内部有无块级子元素"判定，结果**误伤一片**：用户页 `.users-role-tags`、技能页 `.sk-title`、模型页 `.md-name-cell` 都是单行内容却用 div 包着，被整片判成两行、卡在 60px 下不来。**结构标签不是"几行"的可靠信号**；改用「有没有副描述行」（`.mc-service-desc`/`.rev-desc`/`.kb-desc`）判定才准。教训同 09-10：凭结构猜语义会成片误判，必须实测逐页复核。

## 修两处遗漏：技能名未纵向居中 + 8 个页面操作配色漏改

**需求/问题**：负责人截图指出——①技能页「技能名」列文本不是纵向居中；②多个页面的操作按钮配色没换成新色。

**方案**：

1. **技能名纵向居中**：`.sk-title` 原写 `align-items: flex-start`。行高收到 28px 前不明显，收紧后图标 28px 而技能名 20px、状态标签 19px，顶对齐就让文字与标签贴着图标上沿。改 `center`。
   > 另三处 `flex-start`（`.biz-cell`/`.api-cell`/`.kb-name-cell`）**保持不动**：它们是「图标 + 名称/描述两行」结构，顶对齐才是对的，改了反而让图标相对两行文字偏下。

2. **操作配色漏改的根因是作用域取错**：上一轮把配色写成 `.tbl-ops .el-button`，而**只有一半页面用 `.tbl-ops` 容器**——审核中心 `.rev-ops`、我的申请 `.ma-ops`、用户技能审核 `.usr-ops`、运行规格 `.rs-actions` 各用各的类，技能页与岗位管理页更是裸挂 `.cell` 下没有容器类。**按容器类名收作用域必然漏网**，改用「后台表格内的链接按钮」这个不变量：`body.admin-scope .el-table .el-button.is-link`，一条规则覆盖全部列表页，新增页面自动继承。
   同时补了表格内的**行内 `<a>` 链接**：专家名原写 `var(--c-primary, #409eff)`（本站没有 `--c-primary` 这个令牌，恒回落到硬编码 EP 蓝）、「N 个专家引用」走品牌绿，一并收到操作链接蓝。

**影响面**：`theme.css` + `AdminSkillsUnified.vue`；**vitest 149 文件 1838 条全绿、零断言改动**、build 通过。

**验证**：写脚本扫全部 16 个后台页面的表格内链接色值，**漏改由 8 个页面降为 0**（专家/技能/审核中心/我的申请/用户技能审核/岗位管理/连接器/运行规格）。员工端回归：`/tasks`、`/space`、`/settings` 实测 `body` 无 `admin-scope`，新规则够不着，未受影响。

**教训（与上一条同源）**：上一轮按 `.tbl-ops` 收作用域、这一轮按 `:has(div)` 判两行，**两次都是拿"某个页面碰巧怎么写"当全站规律**，结果都成片漏网/误伤。共享层规则的作用域要挑真正的不变量（在不在后台表格里），不要挑各页自定的类名。
