## 规范：新版 PRD 导入两步流程定稿（负责人拍板）

**需求/问题**：docs/ 将持续接收新版 PRD（日期命名文件夹），需要固定的导入与协作流程，保证 PRD 演进可控、问题闭环可见。

**方案（负责人定义 + 三项执行口径经确认）**：
1. **prd 目录·增量核对（先于一切改造）**：新日期文件夹出现后，与上一版逐项对比核实纯增量（只增不改）；发现对已有内容的修改 → 在 docs/prd/ 下建对比分析文件列冲突点交负责人确认；全部冲突解决后才删除旧版文件夹与对比分析文件（git 历史兜底可追溯）。交互原型 v2 单 html 与一览表按**语义级对比**（新增模块=增量，既有模块内容变动=冲突点）。
2. **PRD-review·版本问题清单（确认后才开工）**：基于新版改造中的问题逐条记入 `docs/PRD-review/PRD-<日期>-问题记录.md`（一版一份）；发负责人确认，达成一致的在问题标题标【已解决】，全部解决后文件名标【已解决】（git mv）。
3. 按日改动记录（YYYY-MM-DD.md 三段式）与版本问题清单**并行**：前者记「做了什么」，后者记「待确认的问题」。

**影响面**：docs/ 协作流程规范，本条起生效；现行基准 PRD-20260828 维持至首个新版导入。
