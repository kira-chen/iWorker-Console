# 2026-09-12 改动记录

## 需求 / 问题

岗位详情页「自动化任务」页签前端已实现完整交互（双栏布局、拖拽排序、脏检查、启停开关、引用工具与技能），但 PRD §7 只有简要字段说明，缺少布局结构、交互规则、字段限制等完整规范。

## 方案

根据前端实现 `PositionSampleTaskStage.vue` + `SampleTaskEditor.vue` 补全 PRD §7：

1. **§7.1 页签布局**：
   - 双栏结构：左侧任务列表（240px 宽）+ 右侧编辑区
   - 左侧列表：拖拽排序、缺指令红标、行内删除、软上限 20 条、空态 / 默认选中第一条
   - 右侧编辑区：未选占位 / 选中后展示 4 区表单、切换脏检查、卡头样式（灰底 + 3px 绿条）

2. **§7.2 基本信息**：
   - 任务名称（*）：必填，≤128 字
   - 一句话指令（*）：必填，≤2000 字，发布前后端硬拦（1003）
   - 说明：可选，≤500 字
   - 启用 / 停用开关：仅编辑态展示，位于卡头右侧

3. **§7.3-7.6**：补充调度计划、详细说明（≤8000 字 + 引导文案 + 字数计数）、引用工具（搜索 + 已添加平铺 + 健康度标签 + 弹窗勾选）、引用平台技能（已选 chips + 候选列表默认收起）

4. **§7.7-7.8**：保存 / 创建样例按钮、必填校验、删除二次确认、toast 文案

## 影响面

- **PRD 文档**：`docs/PRD/数字员工管理端PRD/02岗位/岗位/prd.岗位.md` §7 从 6 小节扩充为 9 小节（约 1700 字）

## 需求 / 问题（第二轮，自动化任务需求变更）

岗位自动化任务功能设计变更，涉及三处调整：
1. 「详细说明」改名为「提示词」，定位从通用任务描述改为专门描述任务目标、产出格式和推送方式；

## 方案

差异点列表（仅列不一致处，一致内容略）：

### Q1 【三模块共性】状态标签位置

- **PRD 口径**：MCP §二.1「名称旁展示发布状态标签，不再设置独立状态列」；API §二.1「展示图标、API 名称和状态标签」（嵌在 API 列内）；业务系统 §二.1「展示图标、系统名称、状态标签；不设独立状态列」。
- **代码现状**：三个模块的状态标签均于 2026-09-11 按《列表页UI.png》从名称列拆出为独立「状态」列（代码注释：「2026-09-11 按《列表页UI.png》由名称列拆出独立列」）。
- **差异性质**：代码领先 PRD，三份 md 尚未更新对应描述。
- **建议**：三份 PRD md 各自在列描述处补注「状态作独立列展示，紧跟名称列之后，不在名称行内嵌」。

### Q2 【业务系统编辑器】自动化操作配置展示时机

- **PRD 口径**：§三.5「编辑态展示一个置灰不可编辑的占位输入框」，明确仅编辑态（新建态与查看态不展示）。
- **代码现状**：占位输入框在「基本信息」卡内无状态判断，新建态与查看态也可见（查看态因 `:disabled="readonly"` 被禁用但仍显示；新建态无 `isEdit` 守卫）。
- **差异性质**：代码与 PRD 不符。
- **建议**：用 `v-if="isEdit"` 包裹该 `el-form-item`，与 PRD 对齐。

### Q3 【MCP】发布确认弹窗文案

- **PRD 口径**：§二.3.4（MCP 的发布）未单独列文案，但 §八.保存与关闭 L344「登记成功后提示「已登记」」等文案均指向简洁风格。
- **代码现状**：MCP 发布弹窗文案为「将把「xxx」下全部 N 个工具作为一个整体提交审核，审核通过后才对平台各项服务开放。」；API / 业务系统发布弹窗为「将「xxx」提交审核，审核通过后才对客户端开放。」——三模块发布弹窗文案不统一，且 MCP 文案更长、提到了「工具数」。
- **差异性质**：MCP 发布弹窗文案 PRD 无对应规范，当前为工程决策，建议确认是否需要补入 PRD §二.3.4。

### Q4 【MCP 编辑器】新建/登记按钮文案

- **PRD 口径**：§三.8「登记状态下，底部展示【取消】【登记】」。
- **代码现状**：McpEditor 使用 `DrawerEditor` 组件，但 `DrawerEditor` 的新建确认按钮文案需核对是否传入了「登记」；API 和业务系统均传 `create-text="保存"`，MCP 编辑器对应参数未在本次截图中完整展示，需确认。
- **差异性质**：待复核。

### Q5 【MCP 列表】首次空态文案

- **PRD 口径**：§一.3.1「首次暂无数据：展示「还没有 MCP 服务 · 点「新建 MCP」登记第一个」」。
- **代码现状**：无筛选条件时展示同 PRD 文案 ✓；有筛选条件但无结果时展示「没有符合条件的 MCP 服务」——PRD 只写「展示空结果状态，保留当前搜索和筛选条件」（未提具体文案）。
- **差异性质**：一致，无需变更。
