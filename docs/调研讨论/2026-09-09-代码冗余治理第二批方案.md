## 一、大白话总述（给负责人看）

这一轮要治理的是「同一件事在很多地方各写了一遍」的问题。比如「未发布 / 审核中 / 已发布」这个状态标签，全站十几个页面各自写了一份「状态怎么翻译成中文、用什么颜色」的小抄；时间格式化（把机器时间变成 `2026-09-09 18:30` 这样的人话）也有十几份一模一样的复制品。这些复制品今天显示效果碰巧都一致，但每次改需求都要改十几处，漏一处就出「有的页面叫审核中、有的叫发布审核中」这类不一致——事实上已经在两个兄弟页面里发现了一处潜在的不一致苗头（筛选参数一个拼 `review`、一个拼 `reviewing`）。

治理办法是「收编」：把小抄收进一个公共文件（共享层），各页面都来抄同一份。**本轮铁律是纯搬家、零行为变化**——用户看到的每一个字、每一个颜色、每一步操作都和现在一模一样，只是代码内部从「十几份复制品」变成「一份正本 + 十几个引用」。个别做不到零变化的（比如要不要把两种拼写统一成一种），全部单列出来请负责人拍板，团队不擅自定。

五项里前四项风险低到中、本轮做完；第五项（岗位详情那个 1936 行的大文件拆分）风险最高、收益偏「工程整洁」而非功能，**建议本轮不动、单独立项**。

盘点实数与审计原始数字有出入（审计明细已失传，以下以逐条 grep + 读码的实数为准）：三态映射实数 **13 处映射定义 + 7 处筛选项清单**（审计说 12 处）；底层状态值拼写实数 **10 种**（审计说 9 种）；pendingAction 绕行实数 **5 处**（与审计一致）；「加载失败」未收编实数 **10 个代码块、分三类**（审计说 7 处，口径不同，下文分类说明）。

#### 目标形态

/** 列表/抽屉三态折叠视图（md 口径：在途一律「审核中」）——此前 5 处各自手工覆盖，收编于此 */
export function deriveTriView(kind, source) {
