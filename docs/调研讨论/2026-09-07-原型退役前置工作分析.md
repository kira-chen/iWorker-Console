# 原型退役前置工作分析（2026-09-07）

> 主题：负责人计划把交互原型 html 的内容在前端代码中完全实现，然后弃用原型。本文分析达成目标还差哪些前置工作。结论先行：**这不是一个开发量问题，而是一个"把决策走完、把定义补齐"的问题**。

## 一、最重要的发现：代码比原型更全

我们把原型（4431 行）和前端代码逐模块对了一遍，结果和直觉相反：

- 原型侧边导航一共 15 个入口，其中 **5 个在原型里是"死链"**——点了没反应、没有任何页面定义（驾驶舱、实例与会话、配额与限流、运行规格、用户技能审核）。而这 5 个里的后 2 个，**代码反而已经做出来了**（运行规格、用户技能审核都是完整页面）。
- 代码里还有 **10 多个原型完全没有的模块**：登录页、用户端工作台全套（对话/定时任务/个人空间/设置等）、技能分类管理、两套报表、业务系统凭证托管、效果测试等。
- 真正"原型有、代码没有"的差距只剩两个小点：①MCP 连接器演示数据原型有 11 条、代码只有 1 条；②岗位工作档案的归纳规则策略参数需要做一次字段级复核。

**一句话：弃用这份 html 不会丢失任何已定义的功能；照原型"完全实现"反而是往回退。** 所以"完全实现 html"的正确理解是：把 html 里**有价值且被确认**的细节收进代码和 md，然后安全退役。
