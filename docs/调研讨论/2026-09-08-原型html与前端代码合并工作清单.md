# 原型 html 与前端代码合并工作清单（2026-09-08）

> 主题：负责人问"如果把 `docs/prd/PRD-20260907/数字员工管理端交互原型.html` 和当前 `frontend/` 代码合并，**页面布局和交互完全以 html 为准**，还有哪些工作要做？"本文是 7 路只读比对（原型最终生效态 ↔ 代码现状）的汇总；每路的逐条明细（含原型行号、代码文件行号）在同名子文件夹 `2026-09-08-原型与代码合并工作清单-分路明细/` 里，共 7 份。只做分析，未动代码。

## 一、先说结论

1. **总量约 45–50 人天**（7 路加总 51–57 人天，扣掉几个被多路重复计入的共享组件后约 45–50；含全站截图回归）。这和 09-07 那份"差距很小"的结论不矛盾——那份看的是**功能有没有**（结论：代码是超集），这份看的是**长得像不像、点起来一不一样**，是视觉与交互层面的对齐。
2. **没有一个页面是"代码缺失"级的**，全部是"局部差异"或"结构不同"。差距分布很不均匀：
   - **岗位详情页一个页面就占 18–19 人天**（工作档案、自动化任务、Agent 三个页签是结构性差异，其余页签只差卡片壳和按钮档）；
   - **共享壳层约 8–10 人天**（页面限宽/底色、控件密度、分页器、抽屉壳、图标行、确认弹窗——改一处全站生效，必须先做）；
   - 其余 13 个页面加起来约 20 人天，多是小项（按钮样式档、栅格排布、工具栏缺个按钮之类）。
3. **"完全以 html 为准"不能按字面执行**，有三类东西不能照搬（详见第五节）：原型里 3 层补丁根本没跑起来（加载就报错）、若干处明显 bug（弯引号 class、变量没赋值、旧函数遮蔽新函数）、以及 40 多处原型和 md 说法相反的地方——照原型做就是推翻 md，浦月那边必须同步回改，否则下次导入又核出来。
4. **这份清单的口径和现行铁律是反的**（现行：以 md 为准，md↔原型矛盾等浦月核对结论）。09-07 你拍的三原则之一就是"打架的地方等浦月结论再实现"。所以开工前要先拍一件事：**布局/交互层面原型赢、文字/字段层面 md 赢**——这个"分层口径"是否成立（第六节第 0 步）。

## 五、原型侧缺陷：合并时不能照搬（按 md 或代码现状处理）

1. **岗位详情有 3 层补丁是死代码**：L2087 人格层、L2109 发布校验层、L2346 任务页重绘层——加载时就抛错（底层是闭包，`renderPositionDetail` 等不在全局）。所以原型"最终生效"的自动化任务页是 L2670 那个**静态壳**，不是有数据绑定的版本；照它做是倒退，任务页按 md + 代码现状。
2. **L1985 弯引号 class**（本版新回归）：MCP 检索节交互与样式整体失效。不搬，已记 Q391 转浦月。
3. **`window.positionRows` 从未赋值**（L1598）：岗位管理绑定下拉永远是写死的 4 个岗位。按 md 从岗位列表取。
4. **专家列表【查看】命中的是 L368 旧 viewer**（闭包遮蔽了全局覆写链），无分类/示例问题——按 md + 全局链（= 代码现状）。
5. **API 抽屉保存在原型里是死的**（L2182 删了示例问题，L1419 仍要求 3 条）；L2181 还删了 API 图标（违反 md）——按 md。
6. **岗位编辑抽屉 `openPositionEditor` 在列表页不可达**（被 L1876 拦截直接进详情页），只剩审核中心/我的申请只读态在用；审批表头 HTML 残缺、`?module=positions` 直开报 `pageSlice` 未定义。

8. **用户技能审核层**：`levelClass`/`needsManualAudit` 键名用旧命名（卡片永不上色、触发逻辑无体现）、`SCALE_DESC` 旧模型文案、【取消】不回滚——按 md。
