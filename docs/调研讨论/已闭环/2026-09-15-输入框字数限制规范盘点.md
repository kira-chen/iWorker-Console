# 管理后台输入框字数限制规范盘点（2026-09-15）

> 负责人问「目前对输入框字数长度限制有哪几种规范」，本文是**只盘不改**的全站账本，供逐项销项。
> 盘点范围：一览表《各模块必填选填字段一览表.md》统一规则段 + 各模块 prd md 的字数条款 + `frontend/src/` 的模板 `maxlength` / utils 常量 / mock 层长度校验，三侧交叉比对。
> 每条结论均附 `file:line` 或 md 行号；数值以实际读到的为准，不采信旧文档转述。

## 一、大白话总结论

**纸面上只有两条规则，代码里跑着十七个数字。**

一览表真正定死的只有「名称类 64 / 描述类 2000」两条，外加 7 条写明的例外。但代码里实际出现了 **17 个不同上限**（20/30/32/40/50/60/64/100/128/200/500/1024/2000/4000/8000 等）。多出来的那些不是随便写的——**200 用在 7 处、128 用在 5 处**，它们事实上已经成了第二梯队的隐性统一值（行内备注类、标识符类），却从没进过一览表的规则表。结果是每加一个字段都得重新拍一次数字。

真正对不上的地方有三类：**两份 md 打架 3 处、代码超出 md 6 处、代码内部各写各的 5 组**。其中只有 1 条需要负责人拍口径（知识库名称 100 还是 64），其余要么是补文档、要么是收敛常量。

另有两个和数字无关但同样影响一致性的问题：**错误文案 5 种写法并存**、**计数器 UI 两套写法**。后者已经实际咬人一次——任务名称的计数器写死 `/60` 而输入框实拦 64（2026-09-14 已修，见 §六）。

### 附 · 两个非数值的一致性问题

**错误文案 5 种写法并存**：

| 写法 | 示例 |
|---|---|
| 不超过 N 字 | `positionMock.js:296`「岗位描述不超过 500 字」 |
| 最多 N 字 | `positionApplicationsMock.js:172`「驳回原因最多 500 字」 |
| 最多 N 个字符 | `apiConnectorMock.js:587`「名称最多 64 个字符」 |
| 最多 N 字符 | `apiConnectorMock.js:525`「系统名称最多 64 字符」 |
| 不超过 N 个字符 | `runtimeSpecMock.js:57`「规格名称不超过 64 个字符」 |

`apiConnectorMock.js` 一个文件内部就有三种。建议统一为 md 正文使用的「最多 N 个字符」。

**计数器 UI 两套**：部分用 Element Plus 的 `show-word-limit`（30 个含 maxlength 的文件里有 16 个），部分手写 `{{ x.length }} / MAX`，还有的只写静态提示行。B1 那个 bug 正是手写计数器与 maxlength 分别维护导致的。

## 六、本轮已处理

**任务名称计数器与 maxlength 不同口径**（B1 / C1）——2026-09-14 修复，commit `d97deab`。

成因：执行负责人决策 1（任务名称 60→64）时改了 `maxlength` 与 mock 校验，漏改标签行的手写计数器，注释也还留着「待负责人裁 J6」。表现为用户输到 61 字时计数器显示「61 / 60」像是超限，实际还能继续输到 64。

修法：新增 `NAME_MAX = 64` 常量，计数器与 `maxlength` 共用，消除两处分别维护；用例补两侧断言并做能红验证（把计数器改回 `/60` 即红）。
