### Q11·列表页点【发布】时到底校验什么：md 要求先查岗位名称/描述/示例问题/SOP 四项，原型却只查"有没有关联至少 1 个技能"，且直接跳去版本管理侧栏而不是发布前检查弹窗

争议点有两处，需分别拍板。（一）发布前置条件：选项 A 按 md 只校验四项内容完整性，取消"至少 1 个岗位私有技能"这条硬门槛；选项 B 保留技能≥1 作为额外发布条件并补写进 md（专家 md 已有同类"至少引用 1 个市场技能才能发布"的先例，是否要岗位对齐）；选项 C 两者都要。（二）点击【发布】的去向：md 说打开发布前检查弹窗，原型进版本管理侧栏，而 md §3.7 又写"版本管理入口：列表页【发布】或【版本管理】"——md 自身对两条发布路径的关系没说清，需明确列表页【发布】是走检查弹窗还是走版本管理侧栏，以及详情页【发布岗位】与它是不是同一个流程

**涉及文档**：prd.岗位.md §3.3「发布（首发）」/ §3.7「版本管理」/ §9.1–9.2

### Q25·工作档案 / Agent 与技能两个页签，md 描述的表单字段、按钮和提示与原型做出来的差得比较多（新增入口位置、字段类型可选项、唯一 ID 的控件形式、职责描述是否必填及字数等）

本条已有 09-08 负责人决议"三页签按 md 落地、原型独有细节不追"，但决议未覆盖的字段级取舍仍需确认：①编目信息「字段类型」md 列 6 项（日期/长文本/短文本/整数/小数/是否），原型是 7 项（多一项「标签（枚举）」）——要不要保留这项；②「唯一 ID」md 写复选框，原型是互斥的勾选图标且勾选后自动置为必填——是否采纳"勾选唯一 ID 即自动必填"这条联动；③「抽取方式」md 写"单选『指定触发』，可勾选『自动抽取』"，原型是只读文本+复选框，md 这句本身也读不出到底是不是单选控件，需给准话；④Agent「职责描述」md 写"最多 2000 字符"未标必填，原型是必填且上限 300 字——必填与否、上限取 2000 还是 300 需定；⑤Agent 名称上限 md 64、原型 60，取哪个（一览表口径优先）。另决议提到"编目/规则上限 8 保留代码现状并补写进 md"目前 md §4.2.2/§4.2.3 已各写"最多 8 条"，这部分已闭环

**涉及文档**：prd.岗位.md §4「工作档案页签」（§4.2.1–4.2.3）/ §6.2「新增 / 编辑 Agent」

### Q378·md 写 Agent 最多 20 个、每条泳道最多 20 个技能并置灰，原型现在完全没有上限

上限规则本身 md 已写清、不难实现，但它挂在"泳道"这个形态上（md §6.4 的原话是"每条泳道最多引用 20 个技能…【添加技能】置灰"），而 Agent 与技能页签到底做泳道还是表格尚未定（见 Q383）。需与 Q383 一并拍板：若定表格形态，"每条泳道最多 20 个技能"需改写为"每个 Agent 最多引用 20 个技能"，且技能改在抽屉内勾选后，"达上限置灰"的落点是抽屉里的复选框还是别的位置，需一并明确。Agent 总数 20 的上限本身无争议，可直接保留

**涉及文档**：prd.岗位.md §6.1「Agent 泳道布局」/ §6.4「技能引用」

### Q383·Agent 与技能页签的整体样子：md 描述的是"泳道 + 技能卡片 + 点【＋ 技能】弹窗挑选"，原型做成了"一张表格 + 在 Agent 抽屉里勾技能"

这是页面骨架级的取舍，不是文案差异，必须先定形态再谈细节。选项 A 按 md 做泳道卡片式：每个 Agent 一条泳道，泳道内技能以卡片平铺，卡片显示技能名称/分类/工具数，点【＋ 技能】开弹窗从技能库挑，点技能名跳技能详情页。选项 B 按原型做表格式：Agent 行与技能行在同一张表里平铺，技能通过 Agent 编辑抽屉内的复选框勾选，进技能编辑走行内【编辑】按钮。两者差别涉及：技能的添加入口位置（独立【＋ 技能】按钮 vs 抽屉内勾选）、Agent 行是否展示"关联技能数"、进技能详情的触发方式（点名称 vs 点按钮）。另 md §6.4 内部【＋ 技能】与【添加技能】两个按钮名并存，定形态后需统一为一个

**涉及文档**：prd.岗位.md §6.1「Agent 泳道布局」/ §6.4「技能引用」

## MCP（4 条）

### Q137·stdio 的环境变量到底怎么配：md 是"名称+值"并支持改值/待删除/撤销，原型是一张带"描述、客户端填写"的表格

### Q147·连接状态里的"停用"这一态到底要不要，md 列了四态、原型只有三态

md 二2 写"连接状态展示连接正常、连接异常、未探测、停用"四态；但同一份 md 二1 又说"不再设置独立状态列"、四 状态规则里"停用"是发布状态而非连接状态，原型只实现了三态。争议点：连接状态列是否需要"停用"这一取值。选项 A：保留四态（MCP 停用后连接列直接显示"停用"，不再显示探测结果）；选项 B：连接状态只保留"连接正常/连接异常/未探测"三态，停用信息由名称旁的发布状态标签承担，同步删掉 md 二2 里的"停用"。属枚举取值集合差异，建议 B（与发布状态不混淆）

### Q154·搜索是自动刷新还是要手动点【查询】，MCP 说自动、API 和业务系统都有【查询】按钮

**涉及文档**：MCP/prd-连接器-MCP.md 一 2 交互规则（L24）；API/prd-API.md 一 1 查询按钮（L12）、一 2（L18）；业务系统/prd-业务系统.md 一 1 查询按钮（L12）、一 2（L18）

### Q157·引用情况这一列，MCP 说鼠标悬停看清单，API 和业务系统说点击弹窗看清单，原型 MCP 做的是点击弹窗
