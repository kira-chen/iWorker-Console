## 3. Q137 MCP 环境变量「没看懂」

**背景**：MCP 连接器有两种接法，选 **stdio** 这种时要填三样东西：Command（命令名）、Arguments（参数）、**Environment（环境变量，比如 API 密钥这类）**。争议就在 Environment 怎么填。

**md 现在写的**（prd-连接器-MCP.md §四.2）：一个多行输入框，每行填"名称 和 值"。编辑已有的 MCP 时，出于安全**只显示名称、不回显原值**，每个名称旁给【改值】【删除】；点删除后该行标成"待删除"并出现【撤销】，保存时才真正生效。

**原型做的**：一张四列表格——变量名 / 描述（客户端可见）/ 填写方式 / 平台值。多出两样 md 没有的东西：
- **描述**：给这个变量写句说明，会展示给终端用户看；
- **填写方式**："客户端填写"——勾上之后平台**不存这个值**，改由终端用户在客户端自己填（适合每人一个的私密密钥）。

同时原型**没有**md 的【改值】【待删除】【撤销】那套谨慎流程，就是直接改、直接删。

**需要你定两件事**：

- **（一）要不要"客户端填写"这个能力？** 注意 API 连接器的 API KEY 鉴权在 md 里**已经有**同名能力（一览表 §六 7.3"勾选后参数值由客户端填写"），所以 MCP 这边多半是有意对齐、不是垃圾代码。
- **（二）已配置的变量怎么改？** 选项 A：保留 md 的【改值】+【待删除】+【撤销】（更稳妥，误删可撤）；选项 B：按原型直接改、直接删（更简单）。

**建议**：（一）要，与 API 保持一致，md 补上"描述""客户端填写"两列；（二）选 A 保留撤销机制，密钥类配置误删代价高。
>决策：（一）要；（二）先采纳A，我还不明确影响范围。
