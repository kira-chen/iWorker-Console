## 3. 逐项审查

### Q1.【已解决】模块名称与入口

- PRD依据：模块统一为“实例管理”，取消会话模块。
- 基线代码：`AdminInstances`路由指向统一占位页，菜单与权限树仍显示“实例与会话”。
- 处理：路由改挂`AdminInstances.vue`，菜单、路由标题、权限树和菜单测试统一为“实例管理”；权限mock快照版本升级，旧浏览器快照自动回种子。

### Q2.【已解决】实例信息架构

- PRD依据：页面采用“汇总→明细→详情”三级路径，支持按规格和按岗位查看。
- 基线代码：无实例页面。
- 处理：新增四项运行摘要、三种查看方式、实例明细和右侧详情抽屉；页面明确不展示任务和会话数据。

### Q3.【已解决】运行操作边界

- PRD依据：前端不得依据缺失的任务数自行推断，应使用服务端返回的实例可操作状态。
- 基线代码：无实例API和操作逻辑。
- 处理：新增`instance.js`与`instanceMock.js`，以`operable`/`operationHint`控制重启、重建、回收；mock在执行时二次校验并写操作记录。

### Q4.【已解决】演示与交付资产

- PRD依据：本仓为前端Demo，需要完整表达产品设计。
- 基线代码：实例模块只有`.gitkeep`和占位路由。
- 处理：新增浏览器持久化实例种子、mock行为测试、页面真实挂载测试，以及4张负责人要求随模块交付的页面截图。
