## 目录

| 目录 | 类型 | 放什么 | 会不会归档 |
|---|---|---|---|
| `PRD/` | 正本 | 各模块 prd md + 一览表，**唯一口径**，git 直改 | 不归档 |
| `规范/` | 规范 | 长期有效的参考：`UI/` 设计图（仅视觉参考）、`接口/` 接口规范 | 不归档；被替代时整份删并注明 |
| `产品经理待办任务/` | 台账 | 跨人待办，按人一份（slchen / clcao / dysun / yuepu），序号·状态·发起人·详述 | 不归档；处理完改状态、不删行 |
| `01-PRD改动记录/` | 工作项 | `/prd-import` 阶段一产出（PRD 与代码不同批改时才有） | 闭环即归档 |
| `02-PRD与代码一致性审查/` | 工作项 | `/prd-import` 阶段二产出，Q 编号差异清单；**审查人不得是 PRD 改动者本人** | 闭环即归档 |
| `03-待决策清单/` | 工作项 | 所有等负责人拍板的清单（含测试审计的） | 每条批复且落地后归档 |
| `04-待补需求定义/` | 工作项 | 需产品补 PRD 定义的事项 | 每项补写或裁「不做」后归档 |
| `05-测试用例审计/` | 工作项 | `/test-audit` 报告 | 下一轮开始时归档 |
| `调研讨论/` | 工作项 | 调研与方案稿，`YYYY-MM-DD-主题.md` | 结论被采纳或放弃后归档 |
| `复盘/` | 工作项 | 战役复盘 | 写完即闭环，**不归档** |

不再使用：`PRD-review/`（日记录台账，09-17 停用，改动说明写 commit message）、`update/`、`API迭代需求/`。

## 工作项的生命周期

```text
进行中 ──(最后一条待办销项)──▶ 已闭环 ──(负责人搬出仓库)──▶ 已归档
```

- 每份工作项文件头四行（强制）：`状态 / 责任人 / 闭环条件 / 关联`。闭环条件写不出来的，不是工作项。
- 销掉最后一条待办的人，在同一次 commit 里把状态改「已闭环（日期）」。
- **归档只由负责人做**：`git rm` + 存本机 `Archive/docs-归档/<原目录名>/`（不入库）。合作者要查已归档文件：`git log --follow -- <原路径>` / `git show <commit>:<路径>`。
- 发现需要**别人**处理的事，不要写在自己的文档里等人看——追加到 `产品经理待办任务/<对方>.md`。**按模块分派**（09-17 负责人定）：01 总览、02 岗位、03 能力、05 治理、06 组织 → 浦月 `yuepu`；04 运行 → 曹春林 `clcao`。
