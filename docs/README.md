**新建目录的门槛（2026-09-17 负责人定）**：在 `docs/` 下新建任何文件夹，必须先说明两件事——①**用途**（放什么、谁写谁看）②**和业务流的关系**（在「PRD 修订 → 一致性审查 → 拍板 → 改造 → 测试审计 → 待办」这条流程里处于哪一步、由哪个技能或谁产出、什么时候闭环）——**并经创建者本人确认**后才可以建。没说清就不建；说清后把新目录登记进上表和 CLAUDE.md 目录条。这条对人和 Claude 同样有效。

不再使用：`PRD-review/`（日记录台账，09-17 停用，改动说明写 commit message）、`复盘/`（09-17 并入调研讨论）、`update/`、`API迭代需求/`。

## 工作项的生命周期

```text
进行中 ──(最后一条待办销项)──▶ 已闭环 ──(负责人搬出仓库)──▶ 已归档
```

- 每份工作项文件头四行（强制）：`状态 / 责任人 / 闭环条件 / 关联`。闭环条件写不出来的，不是工作项。
- 销掉最后一条待办的人，在同一次 commit 里把状态改「已闭环（日期）」。
- **归档只由负责人做**：`git rm` + 存本机 `Archive/docs-归档/<原目录名>/`（不入库）。合作者要查已归档文件：`git log --follow -- <原路径>` / `git show <commit>:<路径>`。
- 发现需要**别人**处理的事，不要写在自己的文档里等人看——追加到 `产品经理待办任务/<对方>.md`「待处理」表。**处理完不手改文件**：在完成那次 commit 的说明里写 `关闭待办 yuepu#2`，post-commit 钩子（`npm install` 自动启用）把该行搬到「已处理」并并入该 commit；CI 核验说了关没搬就红；没装钩子用 `node scripts/todo.mjs close-id yuepu#2` 手动补。**按模块分派**（09-17 负责人定）：01 总览、02 岗位、03 能力、05 治理、06 组织 → 浦月 `yuepu`；04 运行 → 曹春林 `clcao`。

## 调研讨论的三条铁规（2026-09-17 负责人定）

1. **有指令才开文档**：只有负责人明确说「就 X 建一个讨论点」才新建 `调研讨论/YYYY-MM-DD-主题.md`；执行任务时冒出的想法、顺手的分析，不得自行开一份——写进 commit message 或待办即可。
2. **过程性记录**：讨论中的重要内容都进文档——关键论据、方案取舍、被推翻的旧结论（保留原文并标「已修改：改成了什么」）、负责人的拍板原话。写完一轮就提交入 git，不攒。
3. **必须有结论才算闭环**：文末固定一段「## 结论」，写清**定了什么**、**去向是哪**（进 PRD 哪个 md / 代码哪个 commit / 规则哪一条 / 转成谁的待办，或明确「放弃」）。没有结论段 = 讨论未闭环。**闭环动作**：文档里所有待办都已解决 → 文件头状态改「已闭环（日期）」→ 同一 commit `git mv` 进 `调研讨论/已闭环/`。讨论文档**不搬本机 Archive**，闭环后留在仓库的「已闭环」子目录供团队回查（与 01–05 工作项不同）。

文件头四行照工作项规则：`状态 / 责任人 / 闭环条件 / 关联`，其中「闭环条件」默认就是「结论段写完且去向落实」。
