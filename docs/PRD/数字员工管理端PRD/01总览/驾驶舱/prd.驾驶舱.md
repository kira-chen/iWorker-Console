# 驾驶舱产品需求

## 一、页面入口与页头

### 1. 功能说明

驾驶舱是管理后台的全局概览页，帮助管理员快速掌握数字员工资产的发布情况、治理待办，以及用户端的使用情况与用户反馈，无需逐个模块查找。页面分「概览」「使用情况」两个页签。

- **页面入口**：侧边栏"01 总览 / 驾驶舱"。总览段定位为全后台概览，拥有驾驶舱页面权限的用户可见。
- **页面标题**：展示"驾驶舱"。
- **页面说明**：文案"查看数字员工资产、治理待办，以及用户端的使用情况与反馈。"
- **更新时间**：页头右侧展示"更新于 HH:MM"（24 小时制，精确到分钟）。
- **刷新按钮**：【刷新】，点击后重新拉取全页数据（两个页签都刷新）。

### 2. 页签结构

页头下方展示两个页签，页签与内容区之间有分隔线（与访问审计、工具调用审计一致）：

| 页签 | 内容 | 谁能看 |
| --- | --- | --- |
| 概览 | 用户端当前下发版本（含升级进度）、异常与待办、各模块发布状态（第二～四节） | 拥有驾驶舱页面权限的全部角色 |
| 使用情况 | 用户端使用量、用户端点踩统计、按用户 / 岗位 / 模型 / 能力的使用明细（第五～九节） | 仅系统管理员（ADMIN） |

- 默认进入"概览"；"使用情况"页签首次切到时才加载数据，之后切换页签不丢失已选的筛选条件与明细表状态。
- 非系统管理员只有"概览"，页面不展示页签栏（用户维度的使用量与 Token 比发布状态敏感，见第十一节待确认事项）。

### 3. 交互规则

- 点击【刷新】：页面整体进入加载态（待办卡片、表格行、下发版本卡片、使用情况页签的概览卡与明细表呈灰色骨架屏动效，约 650ms），期间内容不可点击，同时重新拉取第二节"用户端当前下发版本"与使用情况数据；完成后"更新于"时间刷新为当前时刻，并 toast 提示"驾驶舱数据已刷新"。
- 除第二节"用户端当前下发版本"取自版本管理的实时配置外，页面其余数据均为静态示例数据，用于演示布局与交互，不代表生产环境实际值。

## 二、用户端当前下发版本（概览页签）

### 1. 功能说明

让管理员在驾驶舱直接看到 Windows / Mac 用户端**此刻会被提示升级到哪一版**，这一版更新了什么，以及**有多少用户已经升上来**，无需再进版本管理页查看。取值口径与版本管理页"当前下发概览条"一致（见《prd.版本管理.md》§二"下发中版本"、§3.1）。

- **位置**：概览页签第一个区块（2026-10-09 负责人裁决：原顶部「核心指标卡区」整块删除——已发布岗位 / 领用岗位员工 / 已发布技能 / 已发布专家 / 知识资产 / 已发布模型六张卡——本区块上移占其位置；已发布数量仍可在第四节「各模块发布状态」查看）。
- **区块头**：标题"用户端当前下发版本"，副标题"用户端检测更新时将提示升级到该版本"。
- **两张卡片**：Windows、Mac 左右等宽并排（窄屏下改为上下堆叠），仅展示，卡片不可点击、不提供跳转。
- **卡片字段**：
  - 终端标签：Windows / Mac，使用 accent 强调色标签（与版本管理列表的终端标签一致）。
  - 版本号：展示 `vX.Y.Z`。
  - 发布时间：文案"发布于 YYYY-MM-DD HH:MM"，为该版本最近一次发布审核通过、生效的时间，精确到分钟。
  - **升级进度**（2026-11-02 新增）：版本号行下方一行"已升级 N 人 · 未升到该版本 M 人"，下配一条进度条（已升级占比，强调色）；右侧附占比文案"升级率 xx.x%"。
  - 更新说明：小标题"更新说明" + 更新说明全文，**保留换行**；内容较长时在卡片内滚动，不撑高整页。
- **升级进度口径**：用户端每次检测更新（登录时、手动检测、每 5 分钟轮询）都会上报"终端类型 + 当前版本号"（见《prd.版本管理.md》§二），服务端无需新增采集。**统计对象**为近 7 天内有过检测上报的该终端用户（视为仍在使用该终端）；**已升级**＝上报的当前版本号与下发版本号一致；**未升到该版本**＝不一致。因为用户端只比对"是否一致"、不比大小，下发版本回退时，已升级到更高版本的用户也会计入"未升到该版本"，这是预期行为，所以文案不写"旧版"。
- **无下发版本**：该终端没有下发中版本时，卡片仅展示终端标签与"暂无下发版本"，不展示升级进度，另一终端不受影响。
- **停用审核期间**：该版本尚未停用，仍是下发中版本，卡片照常显示（与版本管理概览条一致）；发布审核中的版本、未发布的版本不显示。

示例取值（版本号、发布时间、更新说明与版本管理种子数据一致；升级人数为静态示例）：

| 终端 | 版本号 | 发布时间 | 升级进度（示例） | 更新说明 |
| --- | --- | --- | --- | --- |
| Windows | v1.2.0 | 2026-08-20 10:30 | 已升级 126 人 · 未升到该版本 35 人（78.3%） | 1. 对话引用来源支持一键复制 / 2. 任务完成后增加桌面通知 / 3. 修复长对话滚动偶尔跳到顶部的问题 |
| Mac | v1.1.0 | 2026-08-20 10:32 | 已升级 44 人 · 未升到该版本 9 人（83.0%） | 与 Windows 端同步：引用来源一键复制、任务完成桌面通知。 |

### 2. 数据来源与联动

- 版本号、发布时间、更新说明**不是静态示例数据**，取自版本管理的实时配置：在版本管理中提交发布 / 停用并经审核中心审核通过后，驾驶舱重新进入或点击【刷新】即显示新的下发版本与更新说明（例如 Windows v1.3.0 发布通过后，卡片由 v1.2.0 变为 v1.3.0）。升级进度的人数为静态示例，不随版本切换联动。
- 打开页面、点击【刷新】时各拉取一次；刷新期间卡片内容呈灰色骨架屏。

## 三、异常与待办（概览页签）

### 1. 功能说明

以卡片形式集中展示当前需要人工介入的待办事项，帮助管理员优先处理。

- **区块标题**："异常与待办"，右侧展示"共 N 项"（N 为下方全部卡片数量之和）。
- **卡片字段**：来源模块（如"审核中心"）、严重度标签（"待审核" / "连接失败" / "高风险" / "待分配" / "待扩容" / "待授权"，前置圆点）、数量、说明文案、行动按钮（如"去审核" / "去处理"）。
- **严重度样式**：中风险（待审核、待分配、待扩容、待授权）为警告色左边框；高风险（连接失败、高风险技能）为危险色左边框。

示例数据：

| 来源 | 严重度 | 数量 | 说明 | 行动 |
| --- | --- | --- | --- | --- |
| 审核中心 | 待审核（中） | 11 | 发布审核 7 / 版本发布 3 / 停用审核 1 | 去审核 |
| 连接器 | 连接失败（高） | 3 | MCP 2 / API 1 | 去处理 |
| 用户技能审核 | 高风险（高） | 2 | 等待人工审核 | 去审核 |
| 岗位管理 | 待分配（中） | 5 | 员工申请岗位，等待分配 | 去分配 |
| 存储空间 | 待扩容（中） | 4 | 员工产物容量不足，等待同意或拒绝 | 去处理 |
| 用户访问权限 | 待授权（中） | 2 | 员工申请开启完全访问，等待通过或驳回 | 去处理 |

### 2. 交互规则（2026-09-17 裁决：由 toast 占位改为真实跳转）

- 六张卡片按每行三列等宽排列（两行各三张）；窗口宽度不足（≤1260px）时改为单列堆叠（与下方「各模块发布状态」的两列同一断点）；点击卡片内的行动按钮，**跳转到对应模块页面**处理，不再是 toast 占位：
  - "审核中心"卡【去审核】→ 跳转审核中心页面（`UnifiedReview`）。
  - "连接器"卡【去处理】→ 跳转连接器页面（`AdminConnector`）。
  - "用户技能审核"卡【去审核】→ 跳转用户技能审核页面（`SysConfigUserSkillReviews`），**进页即将"审核状态"筛选项预置为"待审核"**（2026-10-20 走查调整）。
  - "岗位管理"卡【去分配】→ 跳转岗位管理页面（`AdminPositionAssignments`，待分配申请由此处理），**进页即自动打开"待分配申请"筛选**，列表只展示有待分配申请的用户（2026-10-12 负责人裁决）。
  - "存储空间"卡【去处理】→ 跳转存储空间页面（`AdminStorageSpace`），**直接进"扩容申请"页签并筛选"待处理"状态**（2026-10-12 负责人裁决）。
  - "用户访问权限"卡【去处理】→ 跳转用户访问权限页面（`AdminUserAccess`，权限申请在授权名单里处理，不占单独页签），**进页即自动打开"待处理申请"筛选**，授权名单只展示有待处理申请的员工（同岗位管理的"待分配申请"）。数量取待处理的权限申请数（本机、云端各算一条）。
- 卡片本身不可点击，仅行动按钮响应点击。

## 五、使用情况：筛选与概览（使用情况页签）

使用情况页签回答"用户端到底用得怎么样"：用了多少、谁在用、用什么模型、哪些能力被用起来了，以及用户满意度。它只统计用户端产生的**使用量与反馈计数**，不含任何对话内容（见第八节"数据说明"）。与其他页面的分工：访问审计记录登录与操作事件，工具调用审计记录会话 / 任务里的工具调用过程，本页做的是聚合统计；"活跃"以产生对话为准，**不等于登录**。

### 1. 筛选条

页签顶部一行，对本页签的全部区块（概览卡、趋势图、点踩统计、使用明细）同时生效：

1. **时间范围**：下拉，近 7 天 / 近 30 天（默认）/ 近 90 天；以昨日为终点向前推 N 天（含昨日）；最大近 90 天，与管理端展示窗口一致。
2. **终端**：下拉，全部终端（默认）/ Windows / Mac。
3. **岗位**：下拉，全部岗位（默认）/ 各已发布岗位。

- 调整任一筛选项后立即刷新（区块呈骨架屏约 300ms），无需点击查询按钮。
- 点踩明细弹窗里的样例记录不随筛选条变化（样例集，见第八节）。

### 2. 使用概览卡

四张等宽统计卡，仅展示，不可点击：

| 卡片 | 主值 | 副标题 |
| --- | --- | --- |
| 活跃用户 | N 人 | "活跃率 xx.x%"（活跃用户 ÷ 筛选范围内领用岗位的员工数） |
| 会话数 | N 次 | "人均 x.x 次"（会话数 ÷ 活跃用户） |
| Token 消耗 | 合计，以 K / M 缩写（如 12.4M） | "输入 x.xM / 输出 x.xM" |
| 模型调用失败率 | xx.x% | "失败 N 次 / 共 N 次调用" |

- **较上一周期**：每张卡主值旁展示与紧邻的前一个等长周期相比的变化（如"↑ 5.2% 较上一周期"，上一周期无数据时展示"—"）。活跃用户、会话数、Token 为中性灰色（用量升降本身不分好坏）；模型调用失败率下降为绿色、上升为红色。
- 卡片下方【统计口径】入口，默认收起，展开后说明：
  - **活跃用户**：时间范围内至少产生 1 次对话的用户，不是登录；已领用岗位但时间范围内没有对话的用户计为"沉默用户"。
  - **会话数**：用户端发起的对话会话数。
  - **Token**：以模型返回的用量为准，输入与输出分开累计，失败的调用不计。
  - **模型调用**：每次向模型发起的请求；一轮对话里工具循环可能产生多次调用。失败率 ＝ 失败调用 ÷ 全部调用。
  - 上述口径为产品侧假设，最终以研发数据方案为准（见第十一节）。

### 3. 趋势图

- **指标切换**：分段按钮"活跃用户 / 会话数 / Token"，默认"活跃用户"；切换只换图，不重新取数。
- **图形**：按天一根柱，横轴为日期（间隔标注），纵轴随数据自适应；"Token"为输入、输出堆叠柱，右上角展示两色图例。
- **悬停**：悬停某根柱，图上方的读数行显示该日日期与数值（Token 显示输入、输出、合计）。
- 无数据（筛选后全为 0）：展示"暂无使用数据"。

## 六、用户端点踩统计（使用情况页签）

> 2026-11-10：保留原来的点踩统计（两格），不展示点赞，维持 2026-09-17 负责人裁决"模块收窄为点踩、不再展示点赞数据"。2026-11-02 稿的"点赞回归"（点赞数、点踩数、点踩率、趋势四格）不采用。

### 1. 总览统计

- **区块头**：标题"用户端点踩统计"，副标题"每轮对话均可反馈"，右侧【查看点踩明细】按钮（2026-10-12 负责人裁决：无【导出报表】占位按钮）。
- **两格统计卡**：
  1. **点踩总数**：N 次；副文案"点踩率 xx.x%"，下配点踩率进度条（危险色）和百分比。
     - **点踩率口径（2026-10-12 负责人定）**：点踩率 ＝ 点踩数 ÷（点踩数 ＋ 点赞数）。分母是收到反馈的对话轮次总数，**不含未反馈的轮次**。例：点踩 1,031、点赞 7,420，则点踩率 ＝ 1,031 ÷ 8,451 ≈ 12.2%。点赞数只参与计算，不展示。
  2. **点踩率趋势**：如"↓ 3.1 个百分点 较上一周期"，副文案"上一周期点踩率 15.3%"；下降为绿色、上升为红色，上一周期无数据时展示"—"。
- 两格数值都受筛选条（时间范围、终端、岗位）影响；统计范围最大近 90 天（与展示窗口一致）。原概览页签版本的"本月点踩趋势 / 较上月"随迁入本页签改为"较上一周期"，与筛选条的时间范围对应。

### 2. 交互规则

- 【查看点踩明细】：打开"点踩明细"弹窗（见第八节）。
- 不提供点赞明细：点踩是需要改进的对象，看被点踩的那一轮有价值；点赞明细价值低，还会多暴露用户的对话内容，与"本地对话尽量少回传"的原则相悖。
- 点赞点踩与模型、岗位、用户的交叉见第七节明细表末尾的"点赞 / 点踩 / 点踩率"三列。

## 七、使用明细（使用情况页签）

### 1. 维度切换

区块头标题"使用明细"，右侧分段按钮切换四个维度：**按用户**（默认）/ **按岗位** / **按模型** / **按能力**。四个维度共用页签顶部的筛选条，各自保留排序、翻页状态和搜索词。

- **搜索（2026-11-10 起四个维度都有）**：表上方工具栏左侧放搜索框，按名称模糊匹配，不区分大小写；输入后回车或点击【查询】生效，点输入框里的清除按钮恢复全部。各维度的搜索词分开保存，切换维度不带过去。搜索生效后回到第 1 页。工具栏右侧是各维度自己的开关或提示（见下）。
- 数值列点击列头可排序（首次点击降序，再点切换升序，列头显示"↓ / ↑"）；每个维度有默认排序（见下）。
- 每页 10 条，底部展示"第 X / Y 页，共 N 条"及【上一页】【下一页】；到达首 / 末页时对应按钮置灰禁用。翻页与切换排序后回到第 1 页。
- 无数据时展示"暂无数据"空状态。

### 2. 按用户

- **工具栏**：搜索框（占位"搜索用户名"）；右侧开关"仅看沉默用户"，旁标"沉默用户 N 人"——沉默指已领用岗位、但时间范围内会话数为 0 的用户。
- **列**：

| 列 | 展示规则 |
| --- | --- |

## 八、点踩明细弹窗

### 1. 打开方式

- 点踩统计区块头【查看点踩明细】：打开弹窗，展示管理端可查看范围内（近 90 天，见下"数据留存与展示范围"）的点踩明细样例记录（不支持按岗位预筛）。弹窗里的"时间范围"下拉初始值跟随页签顶部的时间范围。

### 2. 弹窗结构

- **标题栏**：标题"点踩明细记录" + "共 N 条"。
- **筛选行**：
  - **时间范围**：下拉选择"近 7 天 / 近 30 天（默认跟随页签） / 近 90 天"，当前版本仅作展示，不影响列表结果；可选范围最大为近 90 天，与下方展示范围一致。
  - **导出 CSV**：点击后 toast 提示"已生成点踩明细 CSV，正在下载…"（占位，暂无实际文件下载）。
- **表格列**：时间（精确到分钟）、岗位、用户（脱敏，如"张\*\*"）、对话内容摘要（单行省略，悬停查看完整内容）、操作（【查看】）。
- **分页**：每页 10 条，底部展示"第 X / Y 页，共 N 条"及【上一页】【下一页】；到达首 / 末页时对应按钮置灰禁用。

### 3. 数据说明

- **数据留存与展示范围（2026-10-12 负责人定）**：
  - **留存口径**（按对话来源区分）：
    - **云端对话**：对话数据**全量留存**。
    - **客户端本地对话**：不主动回传（数据安全考虑），**只留被点赞 / 点踩的单轮数据**（用户提问 + 被评价的回复），这一轮之前或之后的对话都不留。
    - 点赞 / 点踩数据全部留存，不做过期清理。
  - **采集口径**：**按用户维度采集点踩数据，不区分云端 / 客户端本地**——无论来自哪种对话，点踩记录统一归属到用户、统一为"单轮"形态（用户提问 + 被点踩的回复）进入点踩明细。
  - **管理端展示**：点踩提供明细，点赞不提供明细（见第六节）；展示范围只有**近 90 天**内的记录，更早的记录不在列表中出现，也不能通过时间范围下拉查看；云端留存的完整对话在管理端也不展示，仅展示点踩的那一轮（见第九节）。**第六节的点踩统计随页签筛选条取数，最大近 90 天**（2026-11-02 起不再有"全量留存口径、不受 90 天限制"的总数卡片）。
  - **使用量的采集不含内容**：使用情况页签只统计会话数、Token、调用次数等计数，不回传、不展示对话内容；这与"本地对话不主动回传"的原则一致。
- 示例数据集含 52 条抽样明细，代表点踩数的样例子集，用于交互演示，非逐条对应生产数据。

### 4. 操作

- 行内【查看】：关闭当前"点踩明细"弹窗，打开"对话明细"弹窗（见第九节），展示该条点踩记录的单轮对话。

## 九、对话明细弹窗

### 1. 打开方式

- 从"点踩明细"弹窗表格行内【查看】打开，两个弹窗互斥（打开对话明细时点踩明细自动关闭）。

### 2. 弹窗结构

- **标题栏**：标题"对话明细" + 记录编号（如"D-1031"）。
- **元信息**：岗位、用户、点踩时间三项，横向展示。
- **对话气泡列表**：只展示被点踩的**单轮对话**，共 2 条（2026-10-12 负责人裁决：统一为单轮，不展示前情，不区分云端 / 本地会话）——
  1. 用户发出触发本次点踩的问题（对应点踩明细表格中的"对话内容摘要"）。
  2. 助手给出的回复（即被点踩的消息）。
- **不展示前情的原因**：用户点踩只是对这一条回复表态，这一轮之前的对话他并未表态，可能含与本次反馈无关的敏感内容，故不回传、不展示。
- **气泡样式**：用户消息右对齐、强调色底白字；助手消息左对齐、白底描边；被点踩的助手消息额外用暖色描边 + 浅色底，并在时间戳旁附"点踩"标签。
- 每条消息下方展示发送时间（精确到分钟）。

### 3. 操作

- 【关闭】（含右上角 ×、Esc、点击遮罩）：关闭对话明细，**回到"点踩明细"弹窗**，停留在查看前所在的页码（2026-10-14 负责人裁决，原为返回驾驶舱主页面）。

## 十、异常场景

- **加载 / 刷新中**：异常待办列表、各类表格行、下发版本卡片、使用情况页签的概览卡与明细表呈灰色骨架屏动效，暂不可交互。
- **下发版本加载失败**：第二节"用户端当前下发版本"取自版本管理，取数失败时该区块位置展示"加载失败"和【重试】，点击【重试】重新拉取；不影响驾驶舱其余区块。
- **使用情况加载失败**：使用情况页签取数失败时，页签内容区展示"加载失败"和【重试】（保留页签顶部筛选条），点击【重试】按当前筛选条件重新拉取；不影响"概览"页签。
- **筛选后无数据**：概览卡主值为 0、较上一周期为"—"，趋势图展示"暂无使用数据"，明细表展示"暂无数据"空状态，筛选条保持。
- **无权限**：非系统管理员不展示"使用情况"页签；按页签深链进入时回到"概览"。
- 概览页签其余区块为静态示例数据，恒定成功，无独立加载失败态。
