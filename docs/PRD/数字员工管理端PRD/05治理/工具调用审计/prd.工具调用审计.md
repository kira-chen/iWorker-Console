# 工具调用审计产品需求

> **来源说明**：本模块此前仅存在于已退场的旧交互原型（`数字员工管理端交互原型.html` · 05 治理 / 工具调用审计）中，PRD 正本此前未收录该模块。本篇基于原型的交互内容改写为产品文字稿，作为该模块 PRD 正本的首次落地；原型本身自 2026-09-09/10 起已不再作为对齐依据，此处仅补充需求来源，不代表原型细节自动生效——本篇文字稿与访问审计、实例管理等既有模块的表述如有出入，以本篇及后续修订为准。
>
> **2026-10-09 与研发（梅竹）讨论后改版**：原版以"一次工具调用=一条记录"为单元，研发反馈单次对话可能多次调用工具，按此粒度上报数据量大，存储与分析压力未评估；且单个工具失败、Agent 兜底后整体仍完成时，单纯记该次工具失败意义有限。本次改版把"技能调用""岗位自动化任务"两个页签的记录单元改为**一次技能执行 / 一次任务运行**，工具调用明细收进详情展开，列表只看整体结果（见下方"记录单元"一节）。知识库检索页签的记录单元不受影响，维持"一次检索=一条记录"。

## 一、产品目标与入口

工具调用审计用于记录和查看数字员工在执行技能、岗位自动化任务以及知识库检索过程中，调用外部工具（MCP / API / 业务系统连接器）或第三方知识服务的完整过程，包括发起人、是否需要确认或授权、执行结果，供管理员事后审计与追溯。

- **页面入口**：侧边栏"05 治理 / 工具调用审计"。
- **页面标题**：工具调用审计。
- **页面说明**：追溯每次技能执行 / 任务运行的发起人、确认过程与执行结果。
- 页面只读，不提供修改或删除操作（与访问审计一致）。

### 页签结构

页面顶部展示三个页签，页签与内容区之间有分隔线（与连接器页面、访问审计一致）：

| 页签 | 记录什么 | 记录单元 | 触发方式 | 确认 / 授权 |
| --- | --- | --- | --- | --- |
| 技能调用 | 用户在对话中触发的技能执行，执行过程中调用 MCP / API / 业务系统连接器 | 一次技能执行 | 用户发起，有人在场 | 写操作需用户确认 |
| 岗位自动化任务 | 岗位自动化任务按调度计划触发（周期 / 每间隔 / 单次 / 闲时）的一次运行，运行过程中通过任务的"引用工具"或所引用的技能 / Agent 调用连接器 | 一次任务运行 | 调度触发，无人值守 | 全部操作免授权，不经确认（见 §8.1） |
| 知识库检索 | 用户提问时，岗位 / 专家引用的知识库经 API / MCP 数据源向第三方知识服务发出的检索 | 一次检索请求 | 用户提问触发 | 只读，不需确认 |

- 默认进入"技能调用"页签；切换页签时各页签的查询条件、分页、排序状态相互独立，互不影响。
- 三个页签的统计卡片、列、详情各不相同：**§二 ~ §七 描述"技能调用"页签**，其中 §三 时间范围规则、§六 标签颜色、§七 异常与空状态对另两个页签同样适用；"岗位自动化任务""知识库检索"两个页签只在 §八、§九 写明与它的差异。

### 记录单元

"技能调用""岗位自动化任务"两个页签以**一次技能执行 / 一次任务运行**为记录单元，不是"一次工具调用"：

- **技能调用**：用户对话里每触发一次技能执行就是一条记录。同一次对话里技能被循环调用多次（如 Agent 反复调用同一个技能），**每次调用各自算一条独立记录，不合并统计**——不存在"一次循环=一条记录"这种更粗的聚合。
- **岗位自动化任务**：按调度触发一次任务运行就是一条记录（取代改版前"任务运行编号"把多条工具调用记录串联的做法——记录本身已经是运行级，不再需要额外字段串联）。
- 一次执行 / 一次运行过程中可能调用零到多个外部工具。这些工具调用各自的明细（工具标识、读写性质、技能调用页签的用户确认状态、各自的执行结果、请求参数与响应）展示在该条记录的详情展开里（见 §五、§8.5），**不在列表单独成行**。
- 列表层的"执行结果"是**整体判定**：若记录里有任意一次工具调用仍处于"待确认"（尚未被用户处理），整体记为"进行中"；若全部工具调用都已有最终结果，按技能 / 任务是否完成预期产出判定"成功"或"失败"——哪怕中途有工具调用失败，只要后续被兜底 / 重试成功、整体产出正常，仍记"成功"；原因概要汇总展示具体是哪次工具调用出的问题（见 §四"执行结果 / 原因"）。
- **知识库检索页签不适用本节**：检索本身就是最小单元，一次检索请求对应一条记录，维持改版前口径（见 §九）。

### 模块边界

- 本模块只记录**已发生的技能执行 / 任务运行 / 检索事件**，供事后审计追溯，不提供实时任务队列、运行实例健康度、会话运行状态等运维视图。该边界与 04运行/实例管理 2026-09-16 评审结论保持一致——该评审已明确"本期不再建设会话运行监控"，任务处置、会话汇总等运维职责不在本模块范围，也不在实例管理范围内。
- 本页面不提供工具白名单、确认策略等规则的配置入口；一次工具调用是否需要用户确认、是否命中白名单拦截，由连接器 / 技能 / 岗位相关配置决定，本页仅呈现调用发生时的实际结果。该类配置能力目前尚未在其余模块 PRD 中定义，不在本次改造范围内，记入 `docs/04-待补需求定义/`。岗位自动化任务的写操作是否需要授权已拍板（见 §8.1：全部免授权），不再属于待补事项。
- 本页只记录**经平台连接器 / 知识库数据源、由数字员工发起**的调用。用户绕开数字员工、直接在外部系统内的操作不经过平台，不在本页，以对应外部系统自身的日志为准。
- 管理员在管理端的"测试连接""拉取工具""检索测试"属于管理操作，不在本页；知识库的上传型数据源由平台自身检索，不是外部调用，也不在本页。
- **技能来源与工具类型的上报范围**（自建技能 / 岗位技能 / 服务端下发技能是否全量上报；浏览器操作、代码执行等工具类型是否全量上报）尚未与研发确认，记入 `docs/04-待补需求定义/`；若最终有类型不上报，本节须补一句明确覆盖范围，不能让页面暗示全覆盖。

页面顶部展示 4 个统计卡片，点击卡片按下方 §三 的筛选条件快速筛选列表（不弹窗、不跳转）：

| 卡片 | 说明 | 点击效果 |
| --- | --- | --- |

| 涉及写操作的执行 | "是否涉及写操作"为"是"的记录数，副标题展示"待处理确认 X" | 是否涉及写操作置为"是"，清空执行结果筛选 |

  - 执行耗时统计这次执行里全部工具调用的实际执行时间，不含等待用户确认的时间。
  - "进行中"反映当前仍有工具调用待处理的记录，不是历史累计数量。

## 三、查询区

查询区从左到右展示：

1. **时间范围**：日期区间选择器，规则与访问审计一致（默认展示当前日期向前 90 天，最多可选 30 天跨度，见访问审计 §三）。
2. **执行结果筛选**：下拉，全部结果 / 成功 / 失败 / 进行中；切换后立即刷新列表。
3. **是否涉及写操作筛选**：下拉，全部 / 是 / 否；切换后立即刷新列表。
4. **搜索框**：占位"搜索用户 / 岗位 / 技能 / 工具"，按用户名、岗位名、技能名模糊搜索，或按该次执行详情里出现过的任一工具标识搜索；输入后回车或点击【查询】生效。
5. **查询按钮**：按当前全部条件刷新列表并回到第 1 页。
6. **导出 CSV**（工具栏右侧）：导出当前筛选结果，展示"已导出 N 条筛选结果"。

时间范围、执行结果、是否涉及写操作、搜索框可以组合使用。

| --- | --- |

| 涉及写操作 | 是 / 否标签——本次执行调用的工具里只要有一次是写操作就记"是"（颜色规则见 §六） |
| 待处理确认 | 是 / 否标签——当且仅当执行结果为"进行中"时记"是"，二者含义一致，列表单独给出便于一眼扫出当前还卡着的记录（颜色规则见 §六） |

| 执行耗时 | 本次执行全部工具调用的实际执行耗时合计，不含等待用户确认的时间；进行中的记录展示"进行中，已耗时 X" |
| 操作 | 固定展示【查看详情】按钮 |

## 五、详情

点击【查看详情】从页面右侧打开详情抽屉，展示：

### 5.1 操作摘要

结果标签 + 用户 / 岗位、技能、是否涉及写操作、待处理确认、执行耗时。

### 5.2 工具调用明细

以时间线形式，按实际发生顺序展示本次执行调用的每一个工具（可能零个——技能执行全程未调用外部工具时，展示"本次执行未调用外部工具"）。每一项展示：

- **工具标识**：格式"连接器类型·连接器名称"（如"MCP·文档生成服务""业务系统·Salesforce CRM""API·费控系统"，无分隔空格，与访问审计"知识库·本地产物"的格式一致），与连接器模块的类型口径一致。
- **操作性质**：读 / 写标签。
- **用户确认**（仅该项操作性质为"写"且需要确认时展示）：不需要确认 / 已确认 / 待确认 / 已取消，以标签展示。
- **执行结果**：成功 / 执行失败 / 执行前拦截 / 用户取消 / 待确认，以标签展示；失败 / 拦截 / 取消时附一句原因说明（如"连接超时""不在工具白名单""权限不足""用户取消本次操作"）。
- **执行耗时**：该次工具调用的实际执行耗时；未执行的展示"未执行"。
- 点击该项可展开查看**实际请求参数**与**实际响应结果**：请求参数展示本次调用的参数，敏感字段（如联系方式、操作凭证）脱敏展示；响应结果展示本次调用的返回内容，未执行的调用（执行前拦截 / 用户取消 / 待确认）展示"工具未执行，因此没有实际响应结果"。

每一项工具调用自身仍遵循：调用检查未通过（执行前拦截）则不进入确认与执行阶段；需要用户确认时，确认后才进入执行阶段，待确认或用户取消则该项没有执行结果。这**只影响该项自身**的阶段展示，不影响时间线上**后续其他工具调用**是否发生、是否展示——一次执行可能先成功调用了工具 A，之后调用工具 B 时被拦截，两项都完整展示在时间线里。

### 5.3 结果说明

一句话解释当前整体结果的含义与建议动作，例如：
- 失败：建议对照上方工具调用明细，核对出问题的具体工具的连接器状态或权限，并确认是否已有后续重试记录。
- 进行中：仍有工具调用等待发起人在客户端确认，此页不代替用户确认。
- 成功：本次执行已完成，可在工具调用明细中查看具体过程。

关闭抽屉返回列表原有筛选条件与滚动位置。

## 六、标签颜色规则

列表层（整体判定）与详情层（单次工具调用）的取值不同，分开定义：

**列表层（执行结果 / 是否涉及写操作 / 待处理确认）**：

| 取值 | 颜色 |
| --- | --- |
| 成功 / 是涉及写操作 | 绿色 |
| 失败 | 红色 |
| 进行中 / 待处理确认=是 | 蓝色 |
| 否（不涉及写操作 / 无待处理确认） | 灰色 |

**详情层（工具调用明细：执行结果 / 用户确认）**：

| 取值 | 颜色 |
| --- | --- |
| 成功 / 已确认 | 绿色 |
| 执行失败 | 红色 |
| 执行前拦截 | 橙色 |
| 待确认 | 蓝色 |
| 用户取消 / 已取消 / 不需要确认 | 灰色 |

## 八、岗位自动化任务页签

本节只写与"技能调用"页签（§二 ~ §七）的差异，未提及的规则（时间范围、排序、分页、导出、抽屉形态、标签颜色、异常与空状态）均与之相同。

### 8.1 记录范围与口径

- 记录岗位自动化任务（岗位 PRD"自动化任务"页签）按调度计划触发的**一次任务运行**，运行过程中通过任务"引用工具"或所引用的平台技能 / Agent 调用的全部 MCP / API / 业务系统连接器工具。用户在对话中触发的执行记在"技能调用"页签，不在此重复。
- 记录单元为一次任务运行（见"记录单元"一节），运行中调用的具体工具收在详情（§8.5），不在列表单独成行。
- 任务无人值守，没有实时用户：不存在"用户确认""待确认""用户取消"，也不存在确认或授权环节——**自动化任务的全部操作（含写操作）均免授权、不经任何确认，按调度直接执行**（2026-10-09 与研发讨论后明确：不采用"预授权"机制，无人值守场景下读写一致处理）。执行结果为**成功 / 失败 / 执行前拦截**三类，不存在"进行中"：没有需要等人处理的环节，运行一旦开始就会跑到底。
- 免授权不等于不受任何限制：工具是否可用仍受连接器 / 技能 / 岗位相关配置约束（白名单、权限等，见模块边界），命中限制时同样执行前拦截，与是否写操作无关——"执行前拦截"存在，只是原因里不会再出现"未授权"这一类。
- "用户 / 岗位"展示的是**任务所属用户**（领用该岗位的用户）及其岗位，不是调用发起人；发起方是调度计划，见"触发方式"列。

### 8.2 统计卡片

页面顶部展示 4 个统计卡片，点击卡片按 §8.3 的筛选条件快速筛选列表（不弹窗、不跳转）：

| 卡片 | 说明 | 点击效果 |
| --- | --- | --- |
| 运行总数 | 当前筛选范围内的全部任务运行记录数，副标题展示"成功 X / 失败 X / 拦截 X" | 清空执行结果、是否涉及写操作筛选，仅保留时间范围 |
| 涉及写操作的运行 | "是否涉及写操作"为"是"的记录数，副标题展示"成功 X / 失败 X" | 是否涉及写操作置为"是"，清空执行结果筛选 |
| 执行失败 | 整体判定为失败的记录数 | 执行结果置为"失败" |
| 执行前拦截 | 整体判定为执行前拦截的记录数 | 执行结果置为"执行前拦截" |

卡片下方【统计口径】入口，默认收起，展开后说明：执行结果包含成功、失败、执行前拦截三类，任务无人值守，不存在进行中、用户取消和待确认；全部操作免授权，不区分读写处理；执行耗时统计全部工具调用的实际执行时间。

### 8.3 查询区

从左到右：时间范围（同 §三）→ 执行结果筛选（全部结果 / 成功 / 失败 / 执行前拦截）→ 是否涉及写操作筛选（全部 / 是 / 否）→ 搜索框 → 查询按钮 → 导出 CSV（工具栏右侧）。

- 搜索框占位"搜索用户 / 岗位 / 任务 / 工具"，按用户名、岗位名、任务名模糊搜索，或按该次运行详情里出现过的任一工具标识、触发方式搜索；输入后回车或点击【查询】生效。

### 8.4 列表展示

| 字段 | 展示规则 |
| --- | --- |
| 请求时间 | 本次任务运行触发的时间，同 §四 |
| 用户 / 岗位 | 任务所属用户显示名，副标题展示其岗位名称 |
| 任务 | 触发本次运行的自动化任务名称；该次运行调用过哪些工具不在此列展示，见详情 |

| 涉及写操作 | 是 / 否标签——本次运行调用的工具里只要有一次是写操作就记"是"；免授权不影响这一列的判定 |

| 执行耗时 | 本次运行全部工具调用的实际执行耗时合计 |

### 8.5 详情

点击【查看详情】从右侧打开详情抽屉：

- **操作摘要**：结果标签 + 用户 / 岗位、任务、触发方式、是否涉及写操作、执行耗时。
- **工具调用明细**：时间线形式，按实际发生顺序展示本次运行调用的每一个工具，每项展示：工具标识、操作性质、执行结果（成功 / 执行失败 / 执行前拦截）、原因（失败 / 拦截时）、执行耗时；无用户确认或授权相关字段，读写操作展示规则一致。点击可展开查看该次调用的实际请求参数 / 响应结果，规则同 §5.2。可能为零个，展示"本次运行未调用外部工具"。
- **结果说明**：失败——建议对照工具调用明细，核对出问题的具体连接器状态，并确认是否已有后续重试记录；执行前拦截——请核对该岗位允许使用的工具和任务所属用户权限，任务下次运行时会重新检查。

列表层"是 / 否"标签颜色同 §六列表层；详情层工具调用明细的执行结果颜色同 §六详情层；本页签不额外定义颜色。

## 九、知识库检索页签

本节只写与"技能调用"页签（§二 ~ §七）的差异，未提及的规则（时间范围、排序、分页、导出、抽屉形态、标签颜色、异常与空状态）均与之相同。**本页签不采用"记录单元"一节的技能执行 / 任务运行聚合口径，维持改版前"一次检索=一条记录"**（2026-10-09 与研发讨论后明确保留现状）。

### 9.1 记录范围与口径

- 记录用户提问时，岗位 / 专家引用的知识库通过 **API 或 MCP 数据源**向第三方知识服务发出的检索请求（数据源口径见知识库 PRD §六、§七），每向一个数据源发出一次检索记一条。
- 上传型数据源由平台自身检索，不是外部调用，不在本页；管理端知识库的"检索测试"、数据源的"测试连接"属于管理操作，也不在本页。
- 检索只读、不需确认，执行结果只有**成功 / 执行失败 / 执行前拦截**（如用户无该知识库访问权限）。**检索成功但命中 0 条仍属"成功"**，靠"命中条数"区分，并在统计卡片单列"无命中检索"。
- 审计关心的是"检索词发给了哪个第三方知识服务、命中了哪些内容来源"，因此本页没有操作性质、用户确认两项。
- 检索词按用户提问原文记录并展示。检索词与命中内容是否需要脱敏、是否限制查看，目前产品尚未定义，页面标"【待补充】"，记入 `docs/04-待补需求定义/`。

### 9.2 统计卡片

| 卡片 | 说明 | 点击效果 |
| --- | --- | --- |
| 检索请求总数 | 当前筛选范围内的全部检索请求数，副标题展示"成功 X / 失败 X / 拦截 X" | 清空执行结果、数据源类型、命中情况筛选，仅保留时间范围 |
| 无命中检索 | 检索成功但命中 0 条的请求数 | 命中情况置为"无命中"，清空其余筛选 |
| 执行失败 | 已尝试检索但未成功的请求数 | 执行结果置为"执行失败" |
| 执行前拦截 | 未向数据源发出请求、被拦截的请求数 | 执行结果置为"执行前拦截" |

卡片下方【统计口径】入口，默认收起，展开后说明：检索请求指经 API / MCP 数据源向第三方知识服务发出的检索，包含成功、执行失败、执行前拦截三类结果，上传型数据源不在此记录；命中 0 条属于"成功"，单独统计为"无命中检索"；执行耗时为数据源实际响应时间。

### 9.3 查询区

从左到右：时间范围（同 §三）→ 执行结果筛选（全部结果 / 成功 / 执行失败 / 执行前拦截）→ 数据源类型筛选（全部 / API / MCP）→ 命中情况筛选（全部 / 有命中 / 无命中）→ 搜索框 → 查询按钮 → 导出 CSV（工具栏右侧）。

- 搜索框占位"搜索用户 / 岗位 / 知识库 / 检索词"，按用户名、岗位名、知识库名、数据源名、检索词或请求编号模糊搜索；输入后回车或点击【查询】生效。
- "有命中"指检索成功且命中不少于 1 条；"无命中"指检索成功但命中 0 条；失败和被拦截的检索不属于二者。

| 字段 | 展示规则 |

| 请求时间 | 同 §四 |
| 用户 / 岗位 | 发起提问的用户显示名，副标题展示其当时使用的岗位名称 |
| 知识库 / 数据源 | 被检索的知识库名称，副标题展示数据源标识，格式"数据源类型·数据源名称"（如"MCP·法规库检索""API·情报平台接口"） |

| 执行耗时 | 数据源实际响应耗时；未发出请求的展示"未执行" |

### 9.5 详情

点击【查看详情】从右侧打开详情抽屉，结构同 §五：

- **操作摘要**：结果标签 + 用户 / 岗位、知识库、数据源、检索工具（MCP 数据源展示所选检索工具，API 数据源展示"—"）、命中条数、执行耗时。
- **执行过程**依次展示，被拦截的检索在对应节点停止：①**发起检索**（谁通过哪个岗位提问，引用的知识库向哪个数据源发起检索）；②**调用检查**（未通过则展示拦截原因，时间线在此停止）；③**执行结果**（成功展示命中条数，失败附原因）。
- **结果说明**：执行失败——建议在知识库的"数据源管理"中重新测试该数据源的连接，并检查第三方知识服务状态；执行前拦截——请核对该用户所属岗位是否引用了该知识库，以及用户的知识库访问权限；无命中——检索成功但没有命中内容，可核对检索词与数据源内容是否匹配。
- **请求参数 / 响应结果**两个页签，默认展示"实际请求参数"：
  - **实际请求参数**：检索词（query）、返回条数上限（topK），MCP 数据源多一行检索工具（tool）。页签顶部提示"检索词按用户提问原文记录，脱敏口径【待补充】"。
  - **实际响应结果**：以列表展示命中的内容，列为"标题""来源名称"（对应数据源响应字段映射的 title / sourceName）；命中较多时展示前若干条，并说明"共命中 N 条，展示前 M 条"；命中 0 条展示"检索成功，命中 0 条"；未发出请求（执行前拦截）展示"检索未执行，因此没有实际响应结果"；失败展示失败原因，错误码及原始响应标"【待补充】"。
