# 访问审计产品需求

## 一、产品目标与入口

访问审计用于记录和查看用户登录访问、用户端文件下载与管理端操作的完整行为轨迹，供管理员监控与追溯。

- **页面入口**：侧边栏"05 治理 / 访问审计"。
- **页面标题**：访问审计。
- **页面说明**：记录用户登录访问、用户端文件下载与管理端操作的完整行为轨迹。
- 页面只读，不提供修改或删除操作。

## 二、页签结构

页面顶部展示三个页签，页签与内容区之间有分隔线（与连接器页面一致）：

| 页签 | 说明 |
| --- | --- |
| 登录访问 | 用户登录、登出记录、终端、在线状态与来源 IP |
| 用户端文件下载 | 展示会话产物下载、知识库本地产物下载和知识库我的资料下载情况，含下载结果 |
| 管理端操作 | 管理员在管理端对各模块对象执行的变更操作记录 |

- 默认进入"登录访问"页签。
- 切换页签时各页签查询条件独立，互不影响。

## 三、时间范围筛选（三页签通用规则）

三个页签的查询区均提供时间范围选择器，规则统一如下：

- **默认范围**：保留所有天数记录，但页面仅展示当前日期向前 90 天（含当天），即今天减去 89 天至今天。
- **最大跨度限制**：用户最多可选 30 天的时间跨度。（默认的 90 天是页面展示窗口，30 天是手动选择区间时的跨度上限，二者不矛盾：默认区间由系统给定，不受 30 天约束；用户一旦重新点选，才按 30 天跨度置灰。）
  - 用户点选起始日期后，日期面板中距该日期超过 30 天（前后各 30 天）的日期自动置灰、不可点击；
  - 两端日期均选定后，置灰约束自动解除。
- **实时过滤**：调整时间范围后列表立即刷新，无需点击【查询】按钮。
- **独立状态**：各页签时间范围状态相互独立，切换页签不影响其他页签的已选区间。

## 四、登录访问

### 4.1 查询区

查询区从左到右展示：

1. **时间范围**：日期区间选择器，默认展示过去 90 天（见 §三），调整后列表立即刷新。
2. **搜索框**：占位"搜索用户名"，按用户名模糊搜索；输入后回车或点击【查询】生效。
3. **在线状态筛选**：下拉，全部在线状态 / 在线 / 离线；切换后立即刷新列表。
4. **查询按钮**：按当前全部条件刷新列表并回到第 1 页。

时间范围、搜索框、在线状态筛选可以组合使用。

### 4.2 列表展示

| 字段 | 展示规则 |
| --- | --- |
| 用户名 | 展示账号用户名 |
| 终端 | 仅展示 Windows、Mac 两类，均使用 accent 样式蓝色标签 |
| 登录时间 | 精确到分钟，支持正序 / 倒序切换，列头显示箭头"↓ / ↑" |
| 登出时间 | 在线记录显示"—"；离线记录显示实际时间，支持正序 / 倒序切换 |
| 状态 | 在线为绿色标签，离线为灰色标签 |
| 来源 IP | 展示本次登录来源 IP |

列表根据页面高度动态分页，默认按登录时间倒序展示。

### 4.3 数据规则

- 每条记录对应一次独立登录会话，不按用户名合并。
- 同一账号在不同终端、不同 IP 或不同时间登录时，系统分别记录多条日志。
- 终端枚举仅为 Windows、Mac。
- 当前在线记录的 `logoutAt` 为空；退出后补充登出时间并将状态更新为离线。
- 登录时间和登出时间分别保存，两个字段均可排序；按登出时间排序时，在线记录（无登出时间）统一排在列表末尾。
- 页面不展示登录地点，来源信息仅展示登录 IP。

> **版本管理记录**：客户端版本的发布、停用都必须走审核，因此记录的时机是——发布申请**审核通过、版本生效时**生成一条"发布"记录，停用申请**审核通过、版本停用时**生成一条"停用"记录（操作人均为提交申请的管理员，不是审核人）；管理员在版本管理页或我的申请里**撤回**审核中的申请时生成一条"撤回"记录（操作人为撤回人）。三类记录的变更内容一律为**该版本的更新说明**。提交审核本身、审核驳回、新版本生效引起的旧版本自动回到“未发布”不单独记；版本不可删除，故没有删除记录。操作对象均为"终端 + 版本号"。

> **强制回收记录**：技能、专家、MCP、API、业务系统五个模块的【强制回收】在**二次确认通过、回收立即生效时**生成一条"强制回收"记录（不经审核，故无"提交""通过"环节），操作人为执行回收的管理员，变更内容为回收原因；技能、专家的操作对象名称右侧照常附版本号小标签（回收时的当前版本）。该记录同时是客户端发现能力被回收的来源，客户端需要的字段见 §6.5.1。

> **用户技能审核记录**：管理员在用户技能审核页【通过】【驳回】时各生成一条记录（动作为"审核通过""审核驳回"）；操作对象展示为"提交人用户名 / 技能名称"，审核驳回的变更内容为驳回原因，审核通过的变更内容为空。这两类记录同时是客户端通知"技能审核通过 / 未通过"的来源，客户端需要的字段见 §6.5.2。

> **岗位分配记录**：管理员在岗位管理页为用户分配、修改或批量绑定岗位并保存后，**按用户逐条**生成一条记录（批量绑定 N 名用户生成 N 条）：原来未绑定岗位的记为"分配"，原来已有岗位且换成另一个岗位的记为"变更"；保存前后岗位没变化的不生成记录。处理"待分配申请"本质是一次分配，同样记"分配"。操作对象为被绑定用户的用户名，变更内容为"原岗位 → 新岗位"，操作人为执行绑定的管理员。清除绑定（改回"未绑定"）不属于客户端通知范围，本期不记。这两类记录同时是客户端通知"岗位分配 / 变更"的来源，客户端需要的字段见 §6.5.3。

> **运行规格记录**：只记**个人配置**一类动作——管理员在"配置范围"窗口点击【确认配置】、个人例外立即生效时生成一条记录，操作人为执行配置的管理员，变更内容为"为 N 个用户配置规格「规格名称」"。规格的新建、编辑、删除、岗位配置变更均不生成管理端操作记录（与其余模块删除是否记审计一致，留待统一规则，见 `docs/04-待补需求定义/`）。操作对象为规格名称，不附版本号小标签。

> **存储空间记录**：在"04运行 → 存储空间"页产生，三类动作，操作人均为执行的管理员，操作对象为员工用户名，不附版本号小标签。①**调整容量**：单个调整、批量调整（按员工逐条，N 人 N 条）、恢复默认各生成一条，变更内容为"原总量 → 新总量"（恢复默认记为恢复后的实际总量）；总量没有变化的不生成。**本页展示的存储空间记录只有这一类**。②**同意扩容**、③**拒绝扩容**：在扩容申请页签处理时生成，但**不在本页展示**（该页签自己已有处理人、处理时间、处理结果，这里不重复），只作为数据留给客户端通知读取（同意：变更内容记"原总量 → 新总量"，仅数据层保留，客户端字段只取新总量；拒绝：拒绝原因）。三类都是客户端通知"扩容申请结果 / 管理员调整容量"的来源，客户端需要的字段见 §6.5.4。默认容量固定 5 GB、没有修改入口，因此没有"修改默认容量"记录。

### 6.5 落给客户端的数据

客户端的通知需要感知管理端做过的几类操作（见《客户端通知模块 PRD》第 4.1 节、第 5 章）。管理端不推送、不生成通知、不存已读；客户端在登录时和之后每 5 分钟拉取管理端操作的相关记录（数据层，含页面上不展示的记录），按上次拉取时间之后新增的记录增量处理。本节列出每类记录要给客户端的数据；其余动作的记录（发布、停用、撤回、删除等，包括普通下架）客户端不读取。

**载体口径（与通知 PRD §5.1 对齐）**：通知 PRD 说客户端比对的"审核单、扩容申请单与容量配置、岗位分配记录、回收记录"四类变化，在管理端侧**统一落在本页的「管理端操作记录」这一个来源里**——管理端不另建推送、不另提供四套接口；客户端只读这一个来源，按下表的情形取对应记录。

| 通知 PRD 的情形 | 对应本节 | 管理端记录（模块 / 动作） |
| --- | --- | --- |
| 4.1.1 / 4.1.2 技能审核通过 / 未通过 | §6.5.2 | 用户技能审核 / 审核通过、审核驳回 |
| 4.1.3 / 4.1.4 扩容同意 / 拒绝（仅云端） | §6.5.4 | 存储空间 / 同意扩容、拒绝扩容 |
| 4.1.5 管理员主动调容量（仅云端） | §6.5.4 | 存储空间 / 调整容量 |
| 4.1.6 / 4.1.7 岗位分配 / 变更 | §6.5.3 | 岗位分配 / 分配、变更 |
| 4.1.8 / 4.1.9 / 4.1.10 技能 / 专家 / 连接器强制回收 | §6.5.1 | 技能、专家、MCP、API、业务系统 / 强制回收 |
| 4.2.1 登录时存储 ≥ 90% | 无 | 客户端自己统计，不经管理端（见 §6.5.5） |

**通用规则**：

- 每条记录都带**记录标识**（唯一，用于增量去重，保证同一条只生成一次通知）和**操作时间**（数据层保留到秒，页面仍展示到分钟，同时作为通知上的时间）。
- 页面不展示、但数据层必须保存的**对象标识**（技能、专家、连接器、岗位、用户的唯一标识），客户端据此匹配本地数据，不靠名称匹配。
- 不受页面 90 天展示窗口限制：页面只展示近 90 天，记录本身保留全部天数，客户端增量拉取以数据层为准。
- 客户端在本机第一次登录没有历史基线，以当前已有记录为基线，不补发历史通知。
- 记录只读、不可修改或删除。
- 原因类字段（驳回原因、回收原因、拒绝原因，最长 500 字）**原样、完整**提供，管理端不截断；通知里怎么省略 / 折行由通知 PRD 定。
- 拉取频率与增量方式为产品侧现行假设，最终以研发方案为准（见《客户端通知模块 PRD》第 5 章、第 8 章）。

#### 6.5.1 强制回收（模块：技能 / 专家 / MCP / API / 业务系统；动作：强制回收）

对应客户端通知 4.1.8 ～ 4.1.10：客户端据此把能力从员工处拿走、挂起引用它的自动化，并生成"能力回收"通知。

| 字段 | 取值 | 客户端用途 |
| --- | --- | --- |
| 对象类型 | 记录的"模块"：技能 / 专家 / MCP / API / 业务系统 | 决定从"我的技能 / 我的专家 / 我的连接器"哪里移除，以及通知文案。**通知 PRD 只分三类**：技能 → 4.1.8 技能强制回收，专家 → 4.1.9 专家强制回收，MCP / API / 业务系统 → 统一按「连接器」→ 4.1.10 连接器强制回收 |
| 对象标识 | 被回收对象的唯一标识 | 查找员工已安装 / 已召唤 / 已绑定的本地对象和引用关系，自行算出受影响的自动化 |
| 对象名称 | 记录的"操作对象" | 通知文案"「X」已被管理员回收" |
| 回收原因 | 记录的"变更内容" | 通知文案中的原因 |

不提供：操作人（通知不展示）、影响范围（谁装了它、影响哪些自动化，由客户端按本地安装和引用关系自行计算，通知文案里的「影响 N 个自动化」也是客户端算出来的）、版本号（仅管理端展示）。**普通下架不产生本记录、客户端不读取**（通知 PRD：普通下架不通知，已装的继续用）；岗位技能随岗位变更而回收走 §6.5.3，不算强制回收。

#### 6.5.2 用户技能审核结果（模块：用户技能审核；动作：审核通过 / 审核驳回）

对应客户端通知 4.1.1、4.1.2：客户端据此在提交者的通知里生成"审核通过，已自动安装"或"审核未通过：原因"。只有提交者本人收到，其他员工不受影响。

| 字段 | 取值 | 客户端用途 |
| --- | --- | --- |
| 审核结果 | 记录的"动作"：审核通过 / 审核驳回 | 决定通知文案和落点（通过去"我的技能"，未通过去技能审核页） |
| 审核单标识 | 该次技能审核申请的唯一标识 | 匹配客户端里提交审核的那条记录，同一次审核只发一条 |
| 提交人 | 提交这次审核的用户名（操作对象"提交人 / 技能名"中的提交人，数据层单独保存） | 只发给提交者本人 |
| 技能名称 | 操作对象中的技能名 | 通知文案"「X」审核通过 / 审核未通过" |
| 驳回原因 | 审核驳回的"变更内容"；审核通过为空 | 未通过通知文案"：原因，技能未安装"；原因为空时文案不带后半句 |

不提供：审核人（通知不展示）、四项检测的明细结果（客户端在技能审核页展开记录时另行查看）。员工撤回审核后管理员再操作不产生记录。

#### 6.5.3 岗位分配 / 变更（模块：岗位分配；动作：分配 / 变更）

对应客户端通知 4.1.6、4.1.7：客户端据此切换到该岗位配置，并给被分配的员工生成"已为你分配「X」"或"岗位已由 A 调整为 B"通知。

| 字段 | 取值 | 客户端用途 |
| --- | --- | --- |
| 类型 | 记录的"动作"：分配 / 变更 | 决定通知文案 |
| 用户 | 被绑定用户的用户名（操作对象） | 只发给该员工本人 |
| 用户标识 | 被绑定用户的唯一标识（数据层保存，页面不展示） | 客户端据此匹配本地员工，用户名可能改名，以标识为准 |
| 原岗位 | "变更"时的原岗位名称和标识；"分配"时为空 | 通知文案"由「原岗位」调整为…"，客户端回收原岗位下发的能力 |
| 新岗位 | 新绑定岗位的名称和标识 | 通知文案"「新岗位」"，客户端下发新岗位的技能、专家、连接器、知识和内置自动化，并作为"岗位说明弹窗"的落点 |

不提供：操作人（通知不展示）。

#### 6.5.4 扩容申请与容量调整（模块：存储空间；动作：同意扩容 / 拒绝扩容 / 调整容量）

对应客户端通知 4.1.3 ～ 4.1.5（仅云端版本）。管理端在"04运行 → 存储空间"页处理扩容申请与调整员工容量（见《prd.存储空间.md》），不走审核中心。客户端据此在申请人 / 被调整员工的通知里生成"扩容已同意""扩容被拒绝"或"管理员调整了容量"，只有该员工本人收到。同意 / 拒绝扩容的记录不在访问审计页展示，只供客户端读取（数据层标记为不展示）。

| 字段 | 取值 | 客户端用途 |
| --- | --- | --- |
| 类型 | 记录的"动作"：同意扩容 / 拒绝扩容 / 调整容量 | 决定通知文案 |
| 用户 | 申请人或被调整员工的用户名（操作对象） | 只发给该员工本人 |
| 用户标识 | 员工的唯一标识（数据层保存，页面不展示） | 客户端据此匹配本地员工，以标识为准 |
| 申请单标识 | 同意 / 拒绝扩容时为该次扩容申请的唯一标识；调整容量为空 | 匹配客户端里提交的那条申请，清除"申请中"状态；同一申请只发一条通知 |
| 新总量 | 同意扩容、调整容量后的员工总量（GB） | 通知文案"容量已调整为 N GB"，并触发客户端重新统计 |
| 拒绝原因 | 拒绝扩容的"变更内容"；其余为空 | 显示在员工端存储空间弹窗和拒绝通知中 |

有待处理扩容申请的员工不能在容量分配页被调整，其容量只经申请的同意 / 拒绝改变，所以"同意扩容"只来自扩容申请页签，"调整容量"只记没有待处理申请的员工，同一次变更不会产生两条记录。不提供：处理人（通知不展示）。

#### 6.5.5 客户端自己产生、不经管理端记录的内容

**自动化的执行结果不进通知**（通知 PRD 2026-10-09 修订：送达、失败、部分完成、挂起、因空间不足未执行五种已整块移除，只走自动化自己的侧栏红点和卡片状态），与管理端无关，本页不需要为它们生成记录。登录时存储空间 ≥ 90% 的提醒（通知 PRD 4.2.1）由客户端自己统计、自己生成，同样不经管理端操作，本页不需要生成记录。
