# 访问审计产品需求

## 一、产品目标与入口

访问审计用于记录和查看用户登录访问、用户端文件下载与管理端操作的完整行为轨迹，供管理员监控与追溯。

- **页面入口**：侧边栏"05 治理 / 访问审计"。
- **页面标题**：访问审计。
- **页面说明**：记录用户登录访问、用户端文件下载与管理端操作的完整行为轨迹。
- 页面只读，不提供修改或删除操作。

## 二、页签结构

页面顶部展示三个页签，页签与内容区之间有分隔线（与连接器页面一致）：

| 页签 | 说明 |
| --- | --- |
| 登录访问 | 用户登录、登出记录、终端、在线状态与来源 IP |
| 用户端文件下载 | 展示会话产物下载、知识库本地产物下载和知识库我的资料下载情况，含下载结果 |
| 管理端操作 | 管理员在管理端对各模块对象执行的变更操作记录 |

- 默认进入"登录访问"页签。
- 切换页签时各页签查询条件独立，互不影响。

## 三、时间范围筛选（三页签通用规则）

三个页签的查询区均提供时间范围选择器，规则统一如下：

- **默认范围**：保留所有天数记录，但页面仅展示当前日期向前 90 天（含当天），即今天减去 89 天至今天。
- **最大跨度限制**：用户最多可选 30 天的时间跨度。（默认的 90 天是页面展示窗口，30 天是手动选择区间时的跨度上限，二者不矛盾：默认区间由系统给定，不受 30 天约束；用户一旦重新点选，才按 30 天跨度置灰。）
  - 用户点选起始日期后，日期面板中距该日期超过 30 天（前后各 30 天）的日期自动置灰、不可点击；
  - 两端日期均选定后，置灰约束自动解除。
- **实时过滤**：调整时间范围后列表立即刷新，无需点击【查询】按钮。
- **独立状态**：各页签时间范围状态相互独立，切换页签不影响其他页签的已选区间。

## 四、登录访问

### 4.1 查询区

查询区从左到右展示：

1. **时间范围**：日期区间选择器，默认展示过去 90 天（见 §三），调整后列表立即刷新。
2. **搜索框**：占位"搜索用户名"，按用户名模糊搜索；输入后回车或点击【查询】生效。
3. **在线状态筛选**：下拉，全部在线状态 / 在线 / 离线；切换后立即刷新列表。
4. **查询按钮**：按当前全部条件刷新列表并回到第 1 页。

时间范围、搜索框、在线状态筛选可以组合使用。

### 4.2 列表展示

| 字段 | 展示规则 |
| --- | --- |
| 用户名 | 展示账号用户名 |
| 终端 | 仅展示 Windows、Mac 两类，均使用 accent 样式蓝色标签 |
| 登录时间 | 精确到分钟，支持正序 / 倒序切换，列头显示箭头"↓ / ↑" |
| 登出时间 | 在线记录显示"—"；离线记录显示实际时间，支持正序 / 倒序切换 |
| 状态 | 在线为绿色标签，离线为灰色标签 |
| 来源 IP | 展示本次登录来源 IP |

列表根据页面高度动态分页，默认按登录时间倒序展示。

### 4.3 数据规则

- 每条记录对应一次独立登录会话，不按用户名合并。
- 同一账号在不同终端、不同 IP 或不同时间登录时，系统分别记录多条日志。
- 终端枚举仅为 Windows、Mac。
- 当前在线记录的 `logoutAt` 为空；退出后补充登出时间并将状态更新为离线。
- 登录时间和登出时间分别保存，两个字段均可排序；按登出时间排序时，在线记录（无登出时间）统一排在列表末尾。
- 页面不展示登录地点，来源信息仅展示登录 IP。

## 六、管理端操作

### 6.1 查询区

查询区从左到右展示：

5. **查询按钮**：按当前全部条件刷新列表并回到第 1 页。（筛选条件调整后列表实时生效，【查询】用于回到第 1 页。）
6. **导出 CSV**（工具栏右侧）：点击触发导出，展示"CSV 导出已开始，请稍候…"提示。

时间范围、搜索框、模块筛选、动作筛选可以组合使用。

### 6.2 列表展示

| 字段   | 展示规则                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 操作时间 | 精确到分钟，支持正序 / 倒序切换，列头显示箭头"↓ / ↑"                                              |
| 操作人  | 执行操作的管理员用户名                                                                  |
| 模块   | 操作所属模块，以彩色标签展示（颜色规则见 §6.4）                                                   |
| 动作   | 操作类型，以彩色标签展示（颜色规则见 §6.4）                                                     |
| 变更内容 | 仅七类操作记录说明文字：**审核驳回**时记录驳回原因；**强制回收**时记录回收原因；**删除**无变更内容；**岗位分配**模块的**分配 / 变更**记录"原岗位 → 新岗位"（分配时原岗位为"未绑定"）；岗位 / 专家 / 专家团 / 技能**版本发布**时记录升级说明；**版本管理**模块的记录（发布 / 停用）一律记录该版本的**更新说明**；**运行规格**模块的**个人配置**动作记录"为 N 个用户配置规格「规格名称」"；**存储空间**模块的**同意扩容**、**调整容量**记录"原总量 → 新总量"，**修改默认容量**、**修改磁盘总量**记录"原值 → 新值"，**拒绝扩容**记录拒绝原因；其余操作此字段为空，展示"—"。内容超长省略、悬停展示完整内容。 |
| 操作对象 | 被操作的对象名称。**仅岗位、专家、专家团、技能**四个模块的对象在名称右侧附版本号（灰色小标签，格式如"v1.4.2"）；其他模块不展示版本号小标签；**版本管理**模块的操作对象名称为"终端 + 版本号"（如"Windows v1.2.0"），版本号已在名称内，不再另附小标签；**运行规格**模块的操作对象为规格名称；**存储空间**模块的操作对象为员工用户名（修改默认容量 / 修改磁盘总量的对象为固定名称"默认容量" / "磁盘总量"）。        |
| 操作   | 固定展示【查看】链接按钮，点击跳转至对应模块页（见 §6.3）                                              |

> **版本管理记录**：客户端版本的发布、停用都必须走审核，因此记录的时机是——发布申请**审核通过、版本生效时**生成一条"发布"记录，停用申请**审核通过、版本停用时**生成一条"停用"记录（操作人均为提交申请的管理员，不是审核人）。两类记录的变更内容一律为**该版本的更新说明**。提交审核本身、审核驳回、申请撤回（撤回不记录）、新版本生效引起的旧版本自动回到“未发布”不单独记；版本不可删除，故没有删除记录。操作对象均为"终端 + 版本号"。

> **停用记录**：岗位、专家、专家团、技能、知识库、MCP、API、业务系统、模型九个模块的【停用】都要走停用审核，记录的时机与版本管理一致——停用申请**审核通过、对象变为"未发布"时**生成一条"停用"记录，操作人为提交申请的管理员（不是审核人），变更内容为空，展示"—"。提交停用申请本身、审核驳回、提交人撤回都不记，所以审计里不会留下一条后来没生效的停用。岗位、专家、专家团、技能的操作对象名称右侧照常附版本号小标签（停用申请对应的版本），其余模块不附。勾选了"强制回收"的停用申请不记"停用"，只记下面的"强制回收"记录；版本管理的停用见上一条，规则不变。

> **强制回收记录**：技能、专家、专家团、MCP、API、业务系统六个模块的【停用】申请中勾选了"强制回收"的，在**审核通过、回收生效时**生成一条"强制回收"记录（与其他审核类操作一致，提交审核、审核驳回、申请撤回均不记，也不再另记"停用"记录），操作人为提交申请的管理员（不是审核人），变更内容为回收原因；技能、专家的操作对象名称右侧照常附版本号小标签（回收时的当前版本）。

> **用户技能审核记录**：管理员在用户技能审核页【通过】【驳回】时各生成一条记录（动作为"审核通过""审核驳回"）；操作对象展示为"提交人用户名 / 技能名称"，审核驳回的变更内容为驳回原因，审核通过的变更内容为空。

> **岗位分配记录**：管理员在岗位管理页为用户分配、修改或批量绑定岗位并保存后，**按用户逐条**生成一条记录（批量绑定 N 名用户生成 N 条）：原来未绑定岗位的记为"分配"，原来已有岗位且换成另一个岗位的记为"变更"；保存前后岗位没变化的不生成记录。处理"待分配申请"本质是一次分配，同样记"分配"。操作对象为被绑定用户的用户名，变更内容为"原岗位 → 新岗位"，操作人为执行绑定的管理员。清除绑定（改回"未绑定"）本期不记。

> **运行规格记录**：只记**个人配置**一类动作——管理员在"配置范围"窗口点击【确认配置】、个人例外立即生效时生成一条记录，操作人为执行配置的管理员，变更内容为"为 N 个用户配置规格「规格名称」"。规格的新建、编辑、岗位配置变更不生成管理端操作记录；规格的删除按"删除"统一规则记录（见 §6.2.1）。操作对象为规格名称，不附版本号小标签。

> **存储空间记录**：在"04运行 → 存储空间"页产生，五类动作，**都展示在本页**，操作人均为执行的管理员，不附版本号小标签；前三类操作对象为员工用户名，后两类为固定名称。①**调整容量**：单个调整、批量调整（按员工逐条，N 人 N 条）、恢复默认各生成一条，变更内容为"原总量 → 新总量"（恢复默认记为恢复后的实际总量）；总量没有变化的不生成。②**同意扩容**：在扩容申请页签同意时生成，变更内容为"原总量 → 新总量"（原总量取同意那一刻员工的当前总量）。③**拒绝扩容**：在扩容申请页签拒绝时生成，变更内容为拒绝原因。扩容申请页签自己也保留处理人、处理时间、处理结果（它是申请单的工作台，还有申请说明、事实标签），本页是管理端操作的统一账本，两处各管各的。④**修改默认容量**：容量分配页顶部修改默认容量并保存、值有变化时生成一条（操作对象固定为"默认容量"，变更内容为"原默认 → 新默认"，如"1 GB → 3 GB"）；**只记这一条，不再按员工逐人另记"调整容量"**。⑤**修改磁盘总量**：修改磁盘总量并保存、值有变化时生成一条（操作对象固定为"磁盘总量"，变更内容为"原总量 → 新总量"）。④⑤是全局设置，不涉及单个员工。

> **用户访问权限记录**：在"06组织 → 用户访问权限"页产生，四类动作，**都展示在本页**，操作人均为执行的管理员，不附版本号小标签，操作对象为员工用户名。每条都带**运行环境**（本机 / 云端，授权各算各的，同时授权本机和云端记两条）。①**授权**：在授权名单【设置授权】里勾选、或【批量授权】时，每位员工的每个环境各生成一条，变更内容为"未授权 → 已授权（本机）"。②**收回**：在【设置授权】里取消勾选已授权的环境时每个环境各生成一条，变更内容为"已授权 → 未授权（本机）"。③**通过申请**：在授权名单【处理申请】弹窗点【通过】时生成，变更内容为"未授权 → 已授权（申请通过·本机）"。④**驳回申请**：在【处理申请】弹窗点【驳回】并填原因时生成，变更内容为驳回原因（原样完整）。用户访问权限页不再留已处理申请的列表，处理人、处理时间、处理结果以本页这几类记录为准。

#### 6.2.1 需记录的操作一览

下表是"管理端操作"页签**记什么、记什么内容、什么时候记**的统一口径（上方各条说明是它的展开）。通用规则：操作人一律是**执行动作的管理员**；审核类动作（发布、停用、强制回收）的操作人是**提交申请的管理员**，不是审核人；一件事只记一条，不重复记；**撤回一律不记录**。

| 序号 | 模块 | 动作 | 记录什么操作 | 变更内容 | 记录时机 | 操作对象 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 岗位 / 专家 / 专家团 / 技能 | 发布 | 版本发布 | 该版本的升级说明 | 发布申请**审核通过、版本生效时** | 对象名 + 版本号小标签 |
| 2 | 岗位 / 专家 / 专家团 / 技能 / 知识库 / MCP / API / 业务系统 / 模型 | 停用 | 对象的【停用】 | 空（展示"—"） | 停用申请**审核通过、对象变为"未发布"时**；勾选了"强制回收"的不记本条，改记序号 3 | 对象名；岗位 / 专家 / 专家团 / 技能附停用申请对应的版本号 |
| 3 | 技能 / 专家 / 专家团 / MCP / API / 业务系统 | 强制回收 | 停用申请中勾选"强制回收" | 回收原因（原样完整） | 停用申请**审核通过、回收生效时** | 对象名；技能 / 专家附回收时的当前版本号 |
| 4 | 岗位 / 专家 / 专家团 / 技能 / 知识库 / MCP / API / 业务系统 / 模型 / 运行规格 | 删除 | 对象的【删除】（仅未发布且不在审核中的对象可删） | 空（展示"—"） | 在删除二次确认后**删除成功时**记；被规则拦下（已发布、审核中、被引用等）的不记 | 对象名；岗位 / 专家 / 专家团 / 技能附删除时的当前版本号（有则附） |

### 6.5 与员工通知的关系

员工端收到的管理员操作类通知（技能审核结果、扩容申请结果与容量调整、岗位分配 / 变更、能力强制回收、完全访问申请结果等），由管理端在**管理员执行操作时直接生成**，客户端通过通知接口（`/api/notifications`）拉取并展示，不再从本页的操作记录里自行比对、拼装（2026-10-16 按研发实际做法改口径，原"客户端增量拉取操作记录"方案作废）。

因此本页的操作记录**只服务管理端审计展示**：字段以 §6.2 列表为准，不为客户端额外保存对象标识、申请单标识、秒级时间等页面不展示的数据。哪些操作会给员工发通知、通知写什么，以《客户端通知模块 PRD》为准。
