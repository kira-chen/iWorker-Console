# 版本管理产品需求

## 一、产品目标与入口

版本管理用于配置并下发**用户端（Windows / Mac 客户端）的版本更新**：管理员在管理端维护「版本号、版本包、更新说明」，**提交发布并经审核中心审核通过后**，用户端在登录时、用户手动点击【检测更新】时、每5分钟自动轮询时，发现有更新的下发版本即提示用户升级。

- **页面入口**：侧边栏"05 治理 / 版本管理"，排在"字段字典"之后；仅管理员可见（与 05 治理其余页面一致）。
- **页面标题**：版本管理。
- **页面说明**：管理用户端（Windows / Mac）的版本包与更新说明，发布后用户端检测更新时将提示升级。
- 本期只做「配置、审核与下发」。

> **与既有"版本管理"的区别**：岗位、专家、技能列表里的【版本管理】管理的是**内容版本**（提交审核、生成快照、启停）；本页管理的是**用户端安装包版本**。两者互不关联，但规则相近：**发布、停用都要走审核中心**。本页的特点是——状态只有三种、版本**不可删除**、同一终端同一时间只下发一个版本。

## 二、用户端检测与提示规则（本页配置的消费方式）

本节约定用户端如何使用管理端配置，用户端界面本身不在本 PRD 范围。

**术语**：**下发中版本** = 用户端检测更新时会拿来比对的版本，即该终端**状态为「已发布」的那一条**；若这条正处于**停用审核**中（状态显示"审核中"），审核期间它仍是下发中版本。发布审核中的版本、未发布的版本都不下发。

| 项 | 规则 |
| --- | --- |
| 检测时机 | ①用户**登录成功后**自动检测一次；②用户端**运行期间每 5 分钟自动轮询一次**（后台静默）；③用户在用户端**手动点击【检测更新】** |
| 请求内容 | 用户端上报「终端类型（Windows / Mac）+ 当前版本号」 |
| 比对规则 | 取该终端的下发中版本 V；**只比对版本号是否一致，不比较大小**：V 的版本号与用户端当前版本号**不一致** → 有更新，一致 → 无更新。因此下发的版本号即使**低于**用户端当前版本，也会提示切换（管理端"回退"即靠此实现，见 §六） |
| 该终端无下发中版本 | 视同无更新 |

## 三、页面结构

页面自上而下：**当前下发概览条 → 查询区 → 版本列表**；新建 / 编辑 / 查看使用右侧抽屉。

### 3.1 当前下发概览条

并排两张只读卡片，让管理员一眼看清"用户端此刻会被提示升级到哪一版"：

| 卡片 | 内容 |
| --- | --- |
| Windows | 该终端下发中版本的版本号 + "发布于 {发布时间}"；没有下发中版本时显示"暂无下发版本"。**停用审核期间该版本仍显示**（尚未停用） |
| Mac | 同上 |

点击卡片无操作，仅展示。驾驶舱也展示同一份"当前下发版本"（另附更新说明，见《prd.驾驶舱.md》§五），两处取值一致。

### 3.2 查询区

查询区从左到右展示：

1. **搜索框**：占位"搜索版本号 / 更新说明"，模糊匹配版本号（含终端名，如"Windows v1.2.0"）与更新说明；访问审计【查看】跳转过来时，会把操作对象名称（如"Windows v1.2.0"）自动填入此处。
2. **终端筛选**：全部终端 / Windows / Mac；切换后立即刷新列表。
3. **状态筛选**：全部状态 / 未发布 / 审核中 / 已发布；切换后立即刷新列表。
4. **查询按钮**：按当前全部条件刷新列表并回到第 1 页。
5. **【＋ 新建版本】**（工具栏右侧）：打开新建抽屉。

搜索、终端、状态条件可组合使用。

### 3.3 版本列表

| 字段 | 展示规则 |
| --- | --- |
| 版本号 | 展示 `vX.Y.Z` |
| 终端 | Windows / Mac，均使用 accent 样式蓝色标签（与访问审计终端标签一致） |
| 版本包 | 展示文件名 + 文件大小（如"iWorker-1.2.0.exe · 86.4 MB"）；超长省略、悬停展示完整名称 |
| 更新说明 | 最多两行缩略，悬停展示完整内容 |
| 状态 | **只有三种**：未发布为灰色标签，**审核中为橙色标签**（与全站"审核中"一致），已发布为绿色标签 |
| 发布时间 | 该版本**最近一次发布审核通过、生效的时间**，精确到分钟，支持正序 / 倒序切换，列头箭头"↓ / ↑"；从未发布过的版本显示"—"。**曾发布过的版本即使已回到"未发布"，仍显示上次发布时间**（同时用来标识"曾发布过"） |
| 发布人 | 该版本最近一次**发布申请审核通过（版本生效）时的申请人**，登录用户名（如 xiaomei），不是姓名，也不是审核人；从未发布过显示"—"。**只由发布改写**：之后的停用、被新版本顶替、申请被驳回 / 撤回都不改动它，因此曾发布过的版本回到"未发布"后仍保留。与"申请人"的区别见 §八「人员字段」 |
| 操作 | 见下表 |

**默认排序**：待处理记录（审核中、从未发布过的未发布版本）**始终置顶**，按最近更新倒序；其余按发布时间倒序。点击发布时间列头切换正序 / 倒序只影响置顶区以外的记录。列表根据页面高度动态分页。

**状态与操作按钮对照**：**所有版本都有【查看】【编辑】两个按钮**，第三个按钮随状态变化。

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| 未发布 | 用户端不可见。包括：新建后尚未提交的版本；曾发布过、后被停用或被新版本顶替的版本 | 【查看】【编辑】【发布】 |
| 审核中 | 已提交**发布申请**或**停用申请**，等待审核中心审核；**锁定**，不可编辑 | 【查看】【编辑（置灰）】【撤回】 |
| 已发布 | 已通过审核，用户端检测更新时正在下发 | 【查看】【编辑（置灰）】【停用】 |

**【编辑】的可用规则**：只有**从未发布过的未发布版本**可编辑；其余一律**置灰**，悬停提示原因——

| 情形 | 置灰时的悬停提示 |
| --- | --- |
| 审核中 | 审核中，已锁定不可编辑；如需修改请先撤回申请 |
| 曾发布过（已发布，或已回到未发布的旧版本） | 已发布过的版本不可编辑；如需更正请新建更高版本号的版本 |

任何版本都**没有【删除】**（见 §七）。操作执行期间该行按钮置灰，防止重复提交。

## 四、新建 / 编辑 / 查看版本

三种状态共用右侧抽屉：

- **新建版本**：通过【＋ 新建版本】进入，各字段为空（选好终端后自动生成版本号，见 §4.1），底部【取消】【保存】。
- **编辑版本**：通过可用的【编辑】进入（仅从未发布过的未发布版本），回填当前配置，终端置灰，底部【取消】【保存】。
- **查看版本**：通过【查看】进入（任何状态都可查看），只读，底部仅【关闭】。展示终端、版本号、状态、发布人、发布时间、版本包（文件名 · 大小）、只读的"校验值（SHA-256）"、更新说明；**审核中**的版本另展示"申请类型"（发布 / 停用）、"申请人""申请时间"（**申请人 ≠ 发布人**，区别见 §八「人员字段」）。

### 4.1 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 终端 | ✅ | 单选 Windows / Mac；**创建后不可修改**（版本包与终端绑定），编辑时置灰 |
| 版本号 | ✅ | **自动生成，用户可改**。新建时选好终端后，按该终端已有的最高版本号生成下一个：**次版本号 +1、修订号归 0**（如已有最高 v1.2.3 → 预填 v1.3.0）；该终端还没有任何版本 → 预填 v1.0.0。预填后输入框下方提示"已按该终端已有最高版本号自动生成，可直接修改"。格式为三段数字 `X.Y.Z`，可带前缀 `v`（如 `v1.2.0` 或 `1.2.0`），保存时统一为 `vX.Y.Z`；占位"如 v1.2.0"。**同一终端下版本号不可重复** |
| 版本包 | ✅ | **必须由管理员在本页上传安装包文件**（不支持填写外部下载链接），单个文件；按终端限制格式：Windows 支持 `.exe` / `.msi` / `.zip`，Mac 支持 `.dmg` / `.pkg` / `.zip`；**大小不设上限**。上传交互见 §4.2，校验提示见 §4.3 |
| 更新说明 | ✅ | 多行文本，最多 2000 字符并显示字数统计（属描述类，沿用统一字数规则）；占位"简述本次更新了什么，将展示给用户端用户"；保留换行 |
| 校验值（SHA-256） | — | 版本包上传成功后由系统自动计算，只读，仅在查看抽屉展示，供用户端下载后校验完整性 |

**版本号自动生成的细则**：
- 在**没有手动输入过**版本号时，改选终端会按新终端重新生成；**一旦用户手动输入或修改过**，就不再被自动值覆盖（改选终端也不覆盖）；把输入框清空视同没输入过，之后改选终端可重新生成。
- 只是预填，不做占位保留：保存时仍按"同一终端下不可重复"校验。
- 编辑态不自动生成，保持原版本号；自动生成取不到结果时留空，由用户手填，不弹错误。

### 4.2 版本包上传

版本包区域是抽屉里的核心控件，交互如下：

| 阶段 | 展示与行为 |
| --- | --- |
| 未上传 | 虚线上传区，文案"点击选择或拖拽版本包到此处"，下方灰字提示当前终端支持的格式；未先选终端时上传区置灰，提示"请先选择终端，再上传版本包"（格式因终端而异） |
| 选择文件后 | **立即校验**格式与是否空文件，不通过则不开始上传并提示原因（见 §4.3）；通过则开始上传 |
| 上传中 | 展示文件名、进度条与百分比，提供【取消上传】；上传期间抽屉【保存】置灰 |
| 上传成功 | 展示文件名、文件大小，提供【重新上传】【移除】；系统自动计算 SHA-256 |
| 上传失败 | 展示失败原因和【重试】【移除】，其他已填字段保留 |

- **只能有一个版本包**：【重新上传】选择新文件后替换当前包；【移除】后回到"未上传"，此时【保存】会被"请上传版本包"拦截。
- **改选终端**：新建时若已上传的包与新选终端的格式不符（如 Windows 已传 `.exe`，改选 Mac），提示"已上传的版本包与所选终端不匹配，需重新上传"并清空版本包。编辑状态终端不可改，无此情形。
- **落库时机**：上传的文件在点击【保存】前视为临时文件；取消或关闭抽屉（含二次确认后）则丢弃。编辑时【重新上传】的新包在【保存】后才替换旧包，旧包随即作废。
- **下发**：版本包由平台存储；用户端点【立即更新】时下载的即是本页上传的文件，下载后用 SHA-256 校验完整性。

### 4.3 校验与提示

点击【保存】后先校验，任一不通过则不保存、抽屉保持打开并保留已填内容：

| 场景 | 提示 |
| --- | --- |
| 未选终端 | 请选择终端 |
| 版本号为空 | 请填写版本号 |
| 版本号格式错误 | 版本号格式应为 X.Y.Z，如 v1.2.0 |
| 版本号在该终端下重复 | 该终端下已存在版本 vX.Y.Z（就地显示在版本号字段下，再输入即消） |
| 未上传版本包 | 请上传版本包 |
| 版本包上传未完成时点【保存】 | 【保存】置灰不可点 |
| 版本包格式不符（选择文件时即校验） | Windows 版本包仅支持 .exe / .msi / .zip（Mac 对应 .dmg / .pkg / .zip） |
| 版本包为空文件（0 字节） | 版本包不能为空文件 |
| 更新说明为空（只有空白视同未填） | 请填写更新说明 |

- 保存成功提示"版本已保存"，关闭抽屉并刷新列表；保存期间按钮展示进行中状态，不可重复提交。
- 保存失败保持抽屉打开，提示具体原因或"保存失败，请重试"。
- 新建的版本状态恒为"未发布"。保存前四项必填全部校验通过，因此列表中任何"未发布"记录都是完整的，【发布】无需额外置灰条件。

## 五、发布（必须走审核）

**发布不会直接生效**：点击【发布】只是提交发布申请，版本进入"审核中"，由审核中心审核通过后才真正生效。**任何"未发布"版本都走同一套流程**——不区分从未发布过还是曾发布过；重新启用旧版本同样要提交发布审核，**不能免审**。

点击【发布】弹出"提交发布审核"确认窗：

- 文案：`提交后将进入审核中心，审核通过后 Windows 用户端检测更新时才会提示升级到 v1.2.0。` 该终端已有下发中版本时追加一句：`审核通过后，原已发布版本 v1.1.0 将自动回到「未发布」。`
- 确认按钮【提交审核】，取消或关闭窗口不执行。
- **提交前校验**（不满足则不提交、版本状态不变）：
  - **版本号不限制高低**：不要求高于当前下发中版本——用户端只比对版本号是否一致、不比大小（见 §二），因此可以直接对旧版本【发布】来回退（见 §六）。
  - **同一终端同一时间最多一个版本在审核中**（发布申请、停用申请合计），否则提示"Mac 已有版本 v1.2.0 在审核中，请等待审核结果或先撤回后再提交"。
- 提交成功提示"已提交发布 v1.2.0，进入审核"，版本状态变"审核中"，刷新列表。
- 提交时**审核中心与我的申请各生成一条申请**：业务类型"版本管理"，对象名称为"终端 + 版本号"，申请类型为"新版本发布"（**不区分首次发布**），申请版本为该版本号，提交人为当前登录用户名。
- **审核期间**：版本锁定（不可编辑）；线上下发的版本不受影响，仍是原来的下发中版本；用户端不会收到这个版本的更新提示。

### 5.1 审核结果

| 结果 | 版本页的变化 |
| --- | --- |
| **通过** | 版本变"已发布"，**发布人 = 该发布申请的申请人**，**发布时间 = 审核通过的时间**；**该终端原下发中版本自动回到"未发布"**（保留它的上次发布时间与发布人，内容仍不可编辑；同一终端同一时间只有一个已发布版本，与技能版本"同时只有一个已启用版本"一致）；此后用户端检测更新才会提示升级；访问审计记一条"发布" |
| **驳回** | 版本回到"未发布"；驳回原因在"我的申请"查看。从未发布过的版本可【前往修改】后重新提交，也可直接【重新提交】；曾发布过的版本内容不可改，只能【重新提交】 |
| **撤回** | 见 §5.2 |

### 5.2 撤回

审核中的版本（发布申请或停用申请），可在本页点【撤回】，或在"我的申请"点【撤回申请】：

- 版本页点【撤回】弹出确认窗，**标题、文案随申请类型变化**，确认按钮使用警示样式（橙色）：
  - 撤回发布申请：标题"撤回发布申请"，`撤回后 Mac v1.2.0 将回到「未发布」，可继续编辑或重新提交。确认撤回？`（曾发布过的版本内容不可编辑，此处改为"可重新提交"）。
  - 撤回停用申请：标题"撤回停用申请"，`撤回后 Windows v1.2.0 将回到「已发布」，继续下发。确认撤回？`
- 撤回成功提示"已撤回发布申请"或"已撤回停用申请"：版本回到提交前的状态（未发布 / 已发布），审核中心的待审记录被摘掉，我的申请对应记录变"已撤回"，访问审计记一条"撤回"。
- 撤回前申请已被审核的，按 §九 处理。

## 六、停用（同样必须走审核）

**停用也不会直接生效**：点击【停用】只是提交停用申请，版本进入"审核中"（申请类型"停用"），审核通过后才真正停止下发。仅"已发布"的版本有【停用】。

点击【停用】弹出"提交停用审核"确认窗：

- 文案：`提交后将进入审核中心，审核通过后 Windows 用户端将不再收到 v1.2.0 的更新提示，已升级的用户不受影响，该终端暂无下发版本（不会自动回退到上一个版本）。审核期间该版本继续下发。`
- 确认按钮【提交审核】使用警示样式（橙色）；取消或关闭窗口不执行。
- 提交成功提示"已提交停用 v1.2.0，进入审核"，列表状态变"审核中"。
- 提交时审核中心与我的申请各生成一条申请：业务类型"版本管理"，对象名称"终端 + 版本号"，申请类型"停用"。
- **审核期间该版本继续下发**：概览条仍显示它，用户端检测更新照常；同一终端此时不能再提交别的版本的发布申请（同一终端同一时间最多一个审核中）。

| 结果 | 版本页的变化 |
| --- | --- |
| **通过** | 版本回到"未发布"（**发布人、发布时间不变**，仍是上一次发布的；停用申请人可在访问审计的"停用"记录、我的申请里查到）；该终端**暂无下发版本**，概览条显示"暂无下发版本"，用户端检测更新提示无更新；访问审计记一条"停用" |
| **驳回** | 版本仍是"已发布"，继续下发；可再次提交停用 |
| **撤回** | 同 §5.2，版本回到"已发布"，继续下发 |

### 回退方式（不做自动回退）

- **停用最新版本后，不会自动回退到上一个版本**：停用通过后该终端没有下发版本，用户端检测更新提示无更新，已升级的用户保持现状。
- **需要回退到旧版本时，直接对目标旧版本（在"未发布"）点【发布】即可**：重新启用旧版本同样要提交发布审核，**不能免审**；审核通过后，当前下发的版本自动回到"未发布"，旧版本成为下发版本。**一次审核完成回退，无需先停用**（发布不限制版本号高低，见 §五）。
- **用户端会随之切换**：用户端只比对版本号是否一致、不比大小（见 §二），所以回退后，已升级到问题版本的用户在下一次检测（登录 / 5 分钟轮询 / 手动）时也会收到更新提示，点【立即更新】即切换回该旧版本；不强制。
- 先停用、再发布旧版本（两次审核）同样可行：停用通过到旧版本发布通过之间，该终端暂无下发版本。

## 七、版本不可删除

**版本没有【删除】操作**，所有版本（含从未发布过的）都保留在列表里，以便追溯历史。不再需要的版本保持"未发布"即可，不会被下发，也不影响用户端。

## 八、数据规则

- **唯一性**：(终端 + 版本号) 全局唯一。
- **版本包存储**：版本包文件由平台存储，记录文件名、文件大小、SHA-256；一个版本对应且仅对应一个版本包。
- **状态**：只有 **未发布 / 审核中 / 已发布** 三种。
- **状态流转**：
  - 未发布 →【发布】提交发布审核→ 审核中（发布申请）→ 通过 → 已发布
  - 已发布 →【停用】提交停用审核→ 审核中（停用申请）→ 通过 → 未发布
  - 发布通过时，该终端原已发布的版本 → 未发布（被顶替）
  - 驳回 / 撤回 → 回到提交前的状态（发布申请回未发布，停用申请回已发布）
- **可编辑性**：只有"从未发布过的未发布版本"可编辑；有过发布记录的版本（含已回到未发布的旧版本）、审核中的版本，终端、版本号、版本包、更新说明均不可修改；如需更正，新建更高版本号的版本。
- **下发口径**：用户端只会拿到「该终端的下发中版本」（见 §二），没有则视为无更新；发布审核中的版本不下发。
- **审核**：版本管理是审核中心、我的申请的一个业务类型（详见《prd.审核中心.md》《prd.我的申请.md》）；**发布、停用都走审核**，申请类型为"新版本发布"和"停用"（不区分首次发布）；审核与我的申请里的对象详情复用本页的只读查看抽屉。
- **审计**：以下动作写入访问审计"管理端操作"（详见《prd.访问审计.md》§6）：**发布申请审核通过时记"发布"**、**停用申请审核通过时记"停用"**（操作人均为提交申请的管理员）、**撤回审核中的申请时记"撤回"**（操作人为撤回人）；操作对象为"终端 + 版本号"（如"Windows v1.2.0"），**变更内容一律为该版本的更新说明**。提交审核本身、审核驳回、新版本生效引起的旧版本自动回到"未发布"不单独记录；校验失败的操作不记录。
- **人员字段（申请人 / 发布人 / 审计操作人，勿混）**：
  - **申请人 / 申请时间**：当前在审的那份申请（发布或停用）的提交人与提交时间，**只在"审核中"展示**；审核结束（通过 / 驳回 / 撤回）后不再展示，每提交一次申请就是新的一份。
  - **发布人 / 发布时间**：最近一次**发布申请审核通过**时的申请人与通过时间；**只被新的发布生效改写**，停用、被新版本顶替、申请被驳回 / 撤回都不改动；从未发布过显示"—"。
  - **访问审计的操作人**：发布 / 停用记录 = 对应申请的申请人，撤回记录 = 撤回人。
  - 三者都**不是审核人**（审核人只在审核中心 / 我的申请的审核结果里体现）。
  - 例：Windows v1.2.0 由 li.na 发布 → 发布人 li.na。zhang.wei 随后对它提交停用申请 → 审核中期间：申请类型"停用"、申请人 zhang.wei，发布人仍是 li.na；停用通过后：申请人一栏不再展示，发布人仍是 li.na，访问审计新增一条"停用"记录（操作人 zhang.wei）。
- **权限**：页面权限"版本管理"归属"05 治理"，仅管理员默认开通，可在角色与权限中按需分配。

## 九、异常与空状态

| 场景 | 页面处理 |
| --- | --- |
| 尚无任何版本 | 展示"暂无版本 · 点击「＋ 新建版本」配置首个版本包" |
| 搜索或筛选无结果 | 展示"暂无符合条件的版本"，保留条件 |
| 列表加载失败 | 展示"加载失败"和【重试】 |
| 概览条加载失败 | 概览条位置展示"概览加载失败"和【重试】，不影响下方列表 |
| 版本包上传中关闭抽屉 | 二次确认"版本包正在上传，关闭将中断上传，确认关闭？"；确认后丢弃已上传部分 |
| 版本包上传失败 | 版本包区域展示失败原因和【重试】，已填的其他字段保留（见 §4.2） |
| 点置灰的【编辑】 | 不打开抽屉，悬停可见置灰原因（见 §3.3） |
| 提交发布 / 停用 / 撤回失败 | 保持原状态，提示具体原因或"操作失败，请重试" |
| 撤回时申请已被审核 | 阻止撤回并提示"该申请已被审核，无法撤回，请查看最新审核结果"，刷新列表 |
| 审核通过时版本已被撤回或已脱节 | 审核中心提示"业务对象当前没有与本申请对应的待审事项……"，审核记录保持待审，让提交人重新提交 |
