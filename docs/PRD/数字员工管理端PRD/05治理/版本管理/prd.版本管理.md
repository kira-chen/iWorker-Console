# 版本管理产品需求

> 状态：**草案，待负责人审阅**（2026-09-20 起草）。文末「十、待确认事项」列出需拍板的点，拍板前不进入 `/prd-import` 改造。

## 一、产品目标与入口

版本管理用于配置并下发**用户端（Windows / Mac 客户端）的版本更新**：管理员在管理端维护「版本号、版本包、更新说明」，用户端在登录时或用户手动点击【检测更新】时，发现有更新的已发布版本即提示用户升级。

- **页面入口**：侧边栏"05 治理 / 版本管理"，排在"字段字典"之后；仅管理员可见（与 05 治理其余页面一致）。
- **页面标题**：版本管理。
- **页面说明**：管理用户端（Windows / Mac）的版本包与更新说明，发布后用户端检测更新时将提示升级。
- 本期只做「配置与下发」，不做强制更新、灰度发布、按用户/岗位分批下发（见 §十）。

> **与既有"版本管理"的区别**：岗位、专家、技能列表里的【版本管理】管理的是**内容版本**（提交审核、生成快照、启停）；本页管理的是**用户端安装包版本**，无需审核，两者互不关联。

## 二、用户端检测与提示规则（本页配置的消费方式）

本节约定用户端如何使用管理端配置，用户端界面本身不在本 PRD 范围。

| 项 | 规则 |
| --- | --- |
| 检测时机 | ①用户**登录成功后**自动检测一次；②用户在用户端**手动点击【检测更新】** |
| 请求内容 | 用户端上报「终端类型（Windows / Mac）+ 当前版本号」 |
| 比对规则 | 取该终端当前**已发布**的版本 V；V 的版本号**大于**用户端当前版本号 → 有更新，否则无更新。版本号按 `X.Y.Z` 三段**数值逐段比较**（v1.10.0 > v1.9.0），不做字符串比较 |
| 有更新 | 弹窗展示"发现新版本 vX.Y.Z"、**更新说明全文**，按钮【立即更新】（下载版本包并安装）、【稍后】 |
| 点【稍后】 | 自动检测触发的弹窗：本次登录周期内不再提示，下次登录再提示；手动检测触发的：仅关闭弹窗 |
| 无更新 | 自动检测：不打扰，无任何提示；手动检测：提示"当前已是最新版本" |
| 该终端无已发布版本 | 视同无更新 |
| 检测失败 | 自动检测：静默；手动检测：提示"检测更新失败，请稍后重试" |

## 三、页面结构

页面自上而下：**当前下发概览条 → 查询区 → 版本列表**；新建 / 编辑 / 查看使用右侧抽屉。

### 3.1 当前下发概览条

并排两张只读卡片，让管理员一眼看清"用户端此刻会被提示升级到哪一版"：

| 卡片 | 内容 |
| --- | --- |
| Windows | 当前下发版本号 + 发布时间；该终端无已发布版本时显示"暂无下发版本" |
| Mac | 同上 |

点击卡片无操作，仅展示。

### 3.2 查询区

查询区从左到右展示：

1. **搜索框**：占位"搜索版本号 / 更新说明"，模糊匹配版本号（含终端名，如"Windows v1.2.0"）与更新说明；访问审计【查看】跳转过来时，会把操作对象名称（如"Windows v1.2.0"）自动填入此处。
2. **终端筛选**：全部终端 / Windows / Mac；切换后立即刷新列表。
3. **状态筛选**：全部状态 / 未发布 / 已发布 / 已停用；切换后立即刷新列表。
4. **查询按钮**：按当前全部条件刷新列表并回到第 1 页。
5. **【＋ 新建版本】**（工具栏右侧）：打开新建抽屉。

搜索、终端、状态条件可组合使用。

### 3.3 版本列表

| 字段 | 展示规则 |
| --- | --- |
| 版本号 | 展示 `vX.Y.Z` |
| 终端 | Windows / Mac，均使用 accent 样式蓝色标签（与访问审计终端标签一致） |
| 版本包 | 展示文件名 + 文件大小（如"iWorker-1.2.0.exe · 86.4 MB"）；超长省略、悬停展示完整名称 |
| 更新说明 | 最多两行缩略，悬停展示完整内容 |
| 状态 | 未发布为灰色标签，已发布为绿色标签，已停用为橙色标签 |
| 发布时间 | 精确到分钟，支持正序 / 倒序切换，列头箭头"↓ / ↑"；未发布显示"—" |
| 发布人 | 执行发布的管理员**登录用户名**（如 xiaomei），不是姓名；未发布显示"—" |
| 操作 | 按状态唯一决定，见下表 |

**默认排序**：未发布记录（尚无发布时间）**始终置顶**，其余按发布时间倒序；点击发布时间列头切换正序 / 倒序只影响非未发布记录。列表根据页面高度动态分页。

**状态与操作按钮对照**：

| 状态 | 含义 | 可见操作 |
| --- | --- | --- |
| 未发布 | 已配置、用户端不可见 | 【编辑】【发布】【删除】 |
| 已发布 | 用户端检测更新时正在下发 | 【查看】【停用】 |
| 已停用 | 曾发布过、已不再下发 | 【查看】【发布】 |

## 四、新建 / 编辑 / 查看版本

三种状态共用右侧抽屉：

- **新建版本**：通过【＋ 新建版本】进入，各字段为空，底部【取消】【保存】。
- **编辑版本**：仅"未发布"版本可编辑，回填当前配置，底部【取消】【保存】。
- **查看版本**：已发布 / 已停用版本只读，底部仅【关闭】；额外展示只读的"校验值（SHA-256）""发布人""发布时间""停用时间"。

### 4.1 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 终端 | ✅ | 单选 Windows / Mac；**创建后不可修改**（版本包与终端绑定），编辑时置灰 |
| 版本号 | ✅ | 手动填写，格式为三段数字 `X.Y.Z`，可带前缀 `v`（如 `v1.2.0` 或 `1.2.0`），保存时统一为 `vX.Y.Z`；占位"如 v1.2.0"。**同一终端下版本号不可重复** |
| 版本包 | ✅ | **必须由管理员在本页上传安装包文件**（不支持填写外部下载链接），单个文件；按终端限制格式：Windows 支持 `.exe` / `.msi` / `.zip`，Mac 支持 `.dmg` / `.pkg` / `.zip`。上传交互见 §4.2，校验提示见 §4.3，大小上限见 §十 |
| 更新说明 | ✅ | 多行文本，最多 2000 字符并显示字数统计（属描述类，沿用统一字数规则）；占位"简述本次更新了什么，将展示给用户端用户"；保留换行 |
| 校验值（SHA-256） | — | 版本包上传成功后由系统自动计算，只读，仅在查看抽屉展示，供用户端下载后校验完整性 |

### 4.2 版本包上传

版本包区域是抽屉里的核心控件，交互如下：

| 阶段 | 展示与行为 |
| --- | --- |
| 未上传 | 虚线上传区，文案"点击选择或拖拽版本包到此处"，下方灰字提示当前终端支持的格式与大小上限；未先选终端时上传区置灰，悬停提示"请先选择终端"（格式因终端而异） |
| 选择文件后 | **立即校验**格式与大小，不通过则不开始上传并提示原因（见 §4.3）；通过则开始上传 |
| 上传中 | 展示文件名、进度条与百分比，提供【取消上传】；上传期间抽屉【保存】置灰 |
| 上传成功 | 展示文件名、文件大小，提供【重新上传】【移除】；系统自动计算 SHA-256 |
| 上传失败 | 展示失败原因和【重试】，其他已填字段保留 |

- **只能有一个版本包**：【重新上传】选择新文件后替换当前包；【移除】后回到"未上传"，此时【保存】会被"请上传版本包"拦截。
- **改选终端**：新建时若已上传的包与新选终端的格式不符（如 Windows 已传 `.exe`，改选 Mac），提示"已上传的版本包与所选终端不匹配，需重新上传"并清空版本包。编辑状态终端不可改，无此情形。
- **落库时机**：上传的文件在点击【保存】前视为临时文件；取消或关闭抽屉（含二次确认后）则丢弃。编辑时【重新上传】的新包在【保存】后才替换旧包，旧包随即作废。
- **下发**：版本包由平台存储；用户端点【立即更新】时下载的即是本页上传的文件，下载后用 SHA-256 校验完整性。

### 4.3 校验与提示

点击【保存】后先校验，任一不通过则不保存、抽屉保持打开并保留已填内容：

| 场景 | 提示 |
| --- | --- |
| 未选终端 | 请选择终端 |
| 版本号为空 | 请填写版本号 |
| 版本号格式错误 | 版本号格式应为 X.Y.Z，如 v1.2.0 |
| 版本号在该终端下重复 | 该终端下已存在版本 vX.Y.Z |
| 未上传版本包 | 请上传版本包 |
| 版本包上传未完成时点【保存】 | 【保存】置灰不可点，悬停提示"版本包上传中，请稍候" |
| 版本包格式不符（选择文件时即校验） | Windows 版本包仅支持 .exe / .msi / .zip（Mac 对应 .dmg / .pkg / .zip） |
| 版本包超过大小上限（选择文件时即校验） | 版本包不能超过 N GB（N 取 §十 确认值） |
| 版本包为空文件（0 字节） | 版本包不能为空文件 |
| 更新说明为空 | 请填写更新说明 |

- 保存成功提示"版本已保存"，关闭抽屉并刷新列表；保存期间按钮展示进行中状态，不可重复提交。
- 保存失败保持抽屉打开，提示具体原因或"保存失败，请重试"。
- **新建 / 编辑保存前四项必填全部校验通过**，因此列表中任何"未发布"记录都是完整的，【发布】无需额外置灰条件。

## 五、发布

点击【发布】（未发布 / 已停用版本）弹出"发布版本"确认窗：

- 文案：`发布后，Windows 用户端检测更新时将提示升级到 v1.2.0。` 该终端已有已发布版本时追加一句：`原已发布版本 v1.1.0 将自动变为已停用。`
- 确认按钮【发布】，取消或关闭窗口不执行发布。
- **发布前校验**：待发布版本号须**大于**同终端当前已发布版本号；不满足时不发布，提示"版本号须高于当前已发布版本 vX.Y.Z"。同终端无已发布版本时不受此限制。
- **同一终端同一时间最多一个"已发布"版本**（与技能版本"同时只有一个已启用版本"一致）：发布新版本的同时，该终端原已发布版本自动变为"已停用"。
- 发布成功提示"已发布 v1.2.0（Windows）"，记录发布人、发布时间，刷新列表与概览条。
- 发布失败保持原状态并提示原因。

## 六、停用

点击【停用】（已发布版本）弹出"停用版本"确认窗：

- 文案：`停用后，Windows 用户端将不再收到 v1.2.0 的更新提示，已升级的用户不受影响。停用后该终端暂无下发版本。确认停用？`
- 确认按钮【停用】使用警示样式（橙色，与全站停用确认一致）；取消或关闭窗口不执行。
- 停用成功提示"已停用 v1.2.0"，状态变为"已停用"，概览条对应终端显示"暂无下发版本"。
- **回退方式**：某版本有问题需回退时，先【停用】该版本，再对上一个稳定版本点【发布】（此时该终端无已发布版本，不受"须高于"限制）。注意回退只影响当前版本号低于回退目标的用户；已升级到问题版本的用户不会被降级。

## 七、删除

- 仅**未发布**版本展示【删除】；点击弹出"删除版本"确认窗：`删除后版本 v1.2.0 及其版本包将不可恢复。确认删除？`，确认按钮【删除】使用危险样式。
- 曾发布过的版本（已发布 / 已停用）**不提供删除**，保留历史以便追溯。
- 删除成功提示"版本已删除"，刷新列表。

## 八、数据规则

- **唯一性**：(终端 + 版本号) 全局唯一。
- **版本包存储**：版本包文件由平台存储，记录文件名、文件大小、SHA-256；一个版本对应且仅对应一个版本包，随版本删除而删除。
- **状态流转**：未发布 →【发布】→ 已发布 →【停用】→ 已停用 →【发布】→ 已发布；已发布 / 已停用不可回到"未发布"，也不可编辑（如需更正，新建更高版本号的版本）。
- **不可变**：发布过的版本，其终端、版本号、版本包、更新说明均不可修改。
- **下发口径**：用户端只会拿到「该终端状态为已发布的那一条」，没有则视为无更新。
- **审计**：**发布、停用**成功后各写入一条访问审计"管理端操作"记录（详见《prd.访问审计.md》§6）：模块"版本管理"，操作人为当前登录用户名，操作对象为"终端 + 版本号"（如"Windows v1.2.0"），发布记录的"变更内容"取该版本的更新说明，停用记录为空。发布新版本引起的旧版本自动停用不单独记录（发布记录已体现）；删除（仅限从未上线的未发布版本）与校验失败的操作不记录。
- **权限**：页面权限"版本管理"归属"05 治理"，仅管理员默认开通，可在角色与权限中按需分配。

## 九、异常与空状态

| 场景 | 页面处理 |
| --- | --- |
| 尚无任何版本 | 展示"暂无版本 · 点击【＋ 新建版本】配置首个版本包" |
| 搜索或筛选无结果 | 展示"暂无符合条件的版本"，保留条件 |
| 列表 / 概览条加载失败 | 展示"加载失败"和【重试】 |
| 版本包上传中关闭抽屉 | 二次确认"版本包正在上传，关闭将中断上传，确认关闭？"；确认后丢弃已上传部分 |
| 版本包上传失败 | 版本包区域展示失败原因和【重试】，已填的其他字段保留（见 §4.2） |
| 发布 / 停用 / 删除失败 | 保持原状态，提示具体原因或"操作失败，请重试" |
