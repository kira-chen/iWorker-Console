> 首次编写日期：2026-10-09
> 参考基线：员工端《PRD-知识库》V3.0 第 7 章「存储空间」、`05治理/访问审计` §6.5.4（扩容预留）、`04运行/运行规格`

> **本仓交付边界**：管理端页面与浏览器本地 mock 用于完整表达容量分配与扩容处理的产品交互并供研发参考，不代表容量统计、申请流转后端已实现。用量数据由 mock 种子提供；员工清单与用户模块、岗位分配真联动。演示环境恒为管理员身份，菜单与地址都不做权限拦截（全站通病，非本模块特有）。

## 一、业务背景说明

### 1. 功能定位

员工端（云端版本）的「存储空间」告诉员工"我的数字员工产出的东西还放得下吗"。容量由管理后台按员工分配，满了会拦任务，员工清缓存后仍不够就向管理员申请扩容。本页面是这条链路的管理端一侧，只做两件事：

- **容量分配**：查看每位员工的存储用量，调整单个或批量员工的总量（默认容量固定 5 GB，不提供全局修改入口）。
- **扩容申请**：处理员工提交的扩容申请（同意并设置新总量 / 拒绝并说明原因）。

在 04运行 下的职责边界：运行规格回答"按什么标准运行"，实例管理回答"当前运行得怎么样"，**存储空间回答"员工的产物空间配了多少、够不够"**。

### 2. 容量口径（与员工端一致，不得自行扩展）

- 容量只算**本地产物**：最终产物 + 缓存（预览缓存与过程产物）。
- 知识库「我的资料」是独立库，**不计入、不限制**；岗位知识 / 企业知识为下发内容，不占员工空间。页面名称因此叫「存储空间」，不带"知识库"。
- 仅**云端版本**有容量；客户端是静默功能，没有总量，本页不涉及客户端用户。
- 默认容量固定 5 GB，按员工调整（给某位员工写一个个人设置值）；本页不提供修改默认容量的入口。

### 3. 业务角色

- **平台管理员**：调整员工容量、处理扩容申请。
- **员工**：在员工端查看用量、清理缓存、提交扩容申请；处理结果经通知模块送达，本页不发通知，只产生访问审计记录供通知读取。

### 4. 核心业务规则

- 员工总量 = 个人设置值；没有个人设置值时 = 默认容量，**固定 5 GB**（员工端 PRD：默认 5 GB，管理员按员工调整），本页不提供修改默认容量的入口。要给某位员工更大或更小的容量，就是给他写一个个人设置值；想批量统一调整，用【批量设置容量】。
- 状态按最近一次统计结果判定：已用 ≥ 总量 90% 且未满为「预警」，已用 ≥ 总量为「已满」，其余「正常」。
- 用量由员工端在登录、打开知识库、清理缓存后、管理员调整容量后四个时点统计，本页展示的是最近一次统计结果，**不实时、不轮询**（列表不单独展示统计时间）。本页调整容量后，员工端按"管理员调整容量后"时点重新统计。
- 一位员工同一时间最多一条「待处理」扩容申请（员工端已拦截重复提交）。
- 最终产物不可删除，所以"已满且清不出空间"的唯一出路是扩容。

## 二、页面结构与导航栏

- **页面标题**：「存储空间」。
- **页面说明**：「分配员工产物存储容量，处理扩容申请；仅统计本地产物（最终产物 + 缓存），不含知识库资料」。
- **页签**：【容量分配】【扩容申请】；扩容申请页签标题旁显示待处理数角标，为 0 不显示。
- 无运行管理权限：不展示「04运行 → 存储空间」菜单，也不允许通过地址直接进入。
- 切换页签**不保留**搜索、筛选、页码，每次切回都是该页签的默认状态（容量分配：无筛选；扩容申请：状态「待处理」）。例外是跳转带入的搜索词：访问审计【查看】带员工用户名进容量分配页签、容量分配页点【待处理】带用户名进扩容申请页签，仅首次进入时生效，离开页签后作废。

## 三、容量分配页签

### 1. 顶部默认容量条（只读）

只展示「默认容量：5 GB，未单独设置容量的员工按此值计算，当前 N 人；单个员工的容量请在列表中调整」，**没有任何修改按钮**。

### 2. 搜索与筛选

- 搜索框：占位「搜索用户名或显示名」，忽略前后空格，支持部分匹配。
- 状态筛选：全部状态 / 正常 / 预警 / 已满 / 未统计。
- 申请筛选：全部申请 / 有待处理申请。
- 【查询】按钮；回车同样触发；清空搜索自动刷新。

### 3. 列表

分页展示，默认每页 10 条。

| 列 | 说明 |
|---|---|
| 员工 | 显示名 + 用户名（取用户模块当前值）；无岗位显示「—」于岗位列 |
| 岗位 | 岗位分配里当前绑定的岗位名称，未绑定显示「—」 |
| 已用 / 总量 | 「3.2 GB / 5 GB」+ 进度条；≥ 90% 黄色，已满红色；已用 = 最终产物 + 缓存 |
| 最终产物 | 最终产物大小，提示「不可删除，只能靠扩容释放压力」 |
| 缓存 | 缓存大小，提示「可由员工自行清理」 |
| 状态 | 正常 / 预警 / 已满 标签 |
| 容量来源 | 「默认」或「个人设置」 |
| 操作 | 有待处理扩容申请：显示橙色【待处理】，点击跳转到扩容申请页签并定位该员工的申请，不显示【调整容量】；没有待处理申请：显示【调整容量】。列表不再单设「扩容申请」列 |

排序：状态严重度（已满 > 预警 > 正常 > 未统计）降序，同级按使用率降序；列表不提供按时间排序。

### 4. 调整容量（单个）

弹窗：员工信息、当前已用 / 总量、新总量（正整数 GB，必填，**最小 1 GB**、不设上限）、容量来源提示。**可任意调大调小，不受员工当前容量限制**（例如当前 10 GB 可以直接调到 3 GB）。输入框带上下加减键（点击 ±1，减到下限就不能再减）；填小数不自动取整，提示「容量只能填整数」。批量设置、同意扩容的新总量输入框同此规则（最小 1 GB）。校验提示：空值「请输入正整数」；小数「容量只能填整数」；小于 1「容量不能小于 1 GB」。

- 新总量 ≤ 当前已用：弹出二次确认「调整后 X 的总量不高于已用，将处于已满状态，任务会被拦截，是否继续？」；批量设置提交时同样适用，X 为「其中 N 名员工」。
- **有待处理扩容申请的员工不能在这里调整**：这类员工的行上没有【调整容量】，只有【待处理】入口；他们的容量只能经扩容申请的同意 / 拒绝改变。想改成别的值，先去扩容申请页签处理（拒绝后即可调整）。这样一条申请只有一条处理路径，不会出现「申请还挂着、容量已被改」的状态。
- 提供【恢复默认】：清除个人设置值，回到平台默认容量。

### 5. 批量调整

勾选多名员工后列表上方出现【批量设置容量】，弹窗输入统一新总量并展示将被调整的人数；其中新总量 ≤ 已用的员工数单独红字提示。确认后逐人生效，逐人写审计。**有待处理扩容申请的员工不可勾选**（勾选框置灰，全选也不含他们），批量设置只作用于没有待处理申请的员工。绕过页面直接调用时（mock 层）：单个调整报「X 有待处理的扩容申请，请先在扩容申请页签处理」，批量静默跳过这类员工并返回跳过人数。

### 6. 异常与空状态

- 首次暂无员工：「还没有可分配容量的员工」。
- 无查询结果：「没有符合条件的员工」，提供【清空筛选】（扩容申请页签的「没有符合条件的申请」同样提供）。
- 加载失败：「加载失败」+【重试】。
- 某员工尚无统计结果：已用显示「—」，状态显示「未统计」，仍可调整容量。

## 四、扩容申请页签

### 1. 搜索与筛选

- 搜索框：占位「搜索申请人用户名或显示名」。
- 状态筛选：默认「待处理」，可选 全部状态 / 待处理 / 已同意 / 已拒绝。从容量分配页点【待处理】跳入时带上该员工用户名，状态为「待处理」（见第二节关于跳转词的说明）。

### 2. 列表

| 列 | 说明 |
|---|---|
| 申请人 | 显示名 + 用户名 |
| 岗位 | 提交时的岗位 |
| 申请时用量 | 「已用 5 GB / 总量 5 GB」，固定为提交时快照 |
| 事实标签 | 「缓存已清理」；有被跳过的自动化时多一个「N 个自动化待执行」 |
| 申请说明 | 员工填写的说明（≤ 300 字），超长省略，悬停查看全文 |
| 状态 | 待处理 / 已同意 / 已拒绝 |
| 处理结果 | 同意：「新总量 N GB」；拒绝：拒绝原因（超长省略）；待处理为「—」 |
| 处理人 | 处理该申请的管理员用户名；待处理为「—」 |
| 处理时间 | 精确到分钟；待处理为「—」；列头带排序箭头 |
| 操作 | 待处理：【同意】【拒绝】；其余：【查看】 |

排序：待处理始终排在最前，按提交先后升序（先到先处理，列表不单独展示提交时间，提交时间以「提交于 …」显示在已处理申请的【查看】弹窗中，弹窗另含申请时用量、申请说明、状态、新总量或拒绝原因、处理人与处理时间）；已同意 / 已拒绝的申请按「处理时间」排序，**列头带 ↓ / ↑ 箭头，点击切换倒序 / 正序，默认 ↓ 倒序**（箭头样式对齐专家页「最近更新时间」；箭头只影响已处理的申请，待处理的顺序不变）。

### 3. 同意

弹窗：申请人、申请时用量、申请说明（只读）、当前用量（最新统计）、**新总量**（正整数 GB，必填，最小 1 GB、不设上限，默认预填当前总量 + 5，**必须大于当前总量**——同意扩容只能往大调，想调小请用容量分配页的【调整容量】）。校验提示同调整容量，另加：不大于当前总量「新总量须大于当前总量 N GB」。

- 确认后：员工容量更新为个人设置值；申请状态「已同意」；员工端立即重新统计，拦截解除、申请中状态清除；写访问审计；员工端经通知模块收到同意通知。
- 提示：「已同意 X 的扩容申请，容量调整为 N GB」；拒绝成功提示：「已拒绝 X 的扩容申请」。

### 4. 拒绝

弹窗：申请人、申请说明（只读）、**拒绝原因**（必填，≤ 500 字，与驳回原因、回收原因同口径；占位「请输入拒绝原因，将展示给申请人」）。

- 确认后：申请状态「已拒绝」，员工容量不变、仍处于已满；原因显示在员工端存储空间弹窗里；写访问审计；员工端收到拒绝通知。
- 拒绝后员工可再次提交新申请。
- 为空阻止提交并提示「请输入拒绝原因」；输入框限长 500 字，超出无法继续输入（不再另行提示）。

### 5. 并发与异常

- 打开处理弹窗期间申请已被他人处理（例如另一位管理员先处理了）：提交时提示「该申请已被处理」并刷新列表，不覆盖。
- 员工在申请待处理期间自行清出空间、不再满：申请仍保持待处理，管理员可照常处理；弹窗展示最新用量供判断。
- 暂无申请：「暂无扩容申请」；无筛选结果：「没有符合条件的申请」；加载失败：「加载失败」+【重试】。

## 五、与其他模块的关系

- **员工端知识库 · 存储空间**：员工端读取本页设置的总量；申请、拒绝原因、同意结果与本页双向对应（《PRD-知识库》第 7 章第 17–20 条）。
- **通知模块**：同意 / 拒绝 / 主动调整三种结果由通知读取访问审计记录生成（《PRD-通知模块》§4.1.3–4.1.5），本页不单独发通知。
- **用户**：员工清单、显示名、岗位取自用户与岗位分配；员工被删除后其容量记录与待处理申请一并移除；新增员工显示为「未统计」；停用账号不进清单，重新启用后用量保留；显示名与岗位取当前值，申请上的岗位是提交时的快照。
- **审核中心**：扩容申请不进入审核中心，也不出现在「我的申请」——它是资源申请，由运行侧管理员直接处理，不涉及审核流（与运行规格的个人申请不同）。访问审计 §6.5.4 原"走审核中心与用户管理"的预留已同步改为由本页承接。

## 六、访问审计记录

已同步写入 `05治理/访问审计`（模块：存储空间），本页只列触发口径，字段与展示以访问审计为准。**同意扩容 / 拒绝扩容两类记录只留给客户端通知读取，不在访问审计页展示**——扩容申请页签自己已有处理记录（处理人、处理时间、处理结果）；只有「调整容量」会出现在访问审计的管理端操作里：

| 动作 | 触发 | 变更内容 |
|---|---|---|
| 同意扩容 | 扩容申请页签同意 | 原总量 → 新总量 |
| 拒绝扩容 | 扩容申请页签拒绝 | 拒绝原因 |
| 调整容量 | 单个 / 批量调整、恢复默认（每人一条，总量没变不记；有待处理申请的员工不能被调整） | 原总量 → 新总量 |

## 七、不做什么

- ❌ 按岗位批量分配容量（本期仅按员工 + 全局默认）。
- ❌ 容量使用趋势图、历史用量、超额报表。
- ❌ 删除或清理员工的最终产物、代员工清理缓存。
- ❌ 我的资料 / 知识库容量约束（后续按客户需求在部署配置中做）。
- ❌ 扩容申请的审批流、多级审批、自动同意规则。
- ❌ 客户端用户的容量管理（客户端无容量概念）。
