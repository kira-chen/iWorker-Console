## 一、业务背景说明

### 1. 功能定位

企业员工大部分时间在飞书、钉钉、企业微信里工作。如果只能在 iWorker 网页端或客户端使用数字员工，员工需要来回切换，使用频率和覆盖面都会受限。

渠道用于把 iWorker 接入企业的 IM 平台：管理员在 IM 平台创建企业自建应用，把凭据填到 iWorker，员工即可在 IM 里私聊机器人、把机器人拉进群使用，并接收定时任务结果和告警等主动推送。

渠道属于“04运行”下的二级功能，与相关模块的职责边界如下：

- **渠道**：回答“员工从哪些 IM 入口使用 iWorker，入口怎么收发消息”。
- **岗位 / 岗位分配**：回答“员工拥有哪些岗位私有能力”。渠道不参与分配。
- **专家 / 技能 / 连接器**：回答“有哪些能力、默认给谁”。渠道不参与分配。
- **实例与会话**：回答“会话实际运行得怎么样”。后台投递记录只记录消息元数据，正文随会话走会话权限。
- **05治理 → 访问审计**：记录移出群等敏感操作。
- **统一身份认证 / 用户主数据**（企业现场已有）：IM 通讯录和 iWorker 用户的唯一来源；渠道只按主数据字段匹配身份，不维护账号对应关系。

### 2. 业务角色

- **平台管理员**：接入、编辑、停用机器人；查看与移出群。
- **IM 平台管理员**：在飞书 / 钉钉 / 企业微信后台创建应用、开通权限、发布版本、维护可用范围。通常与平台管理员是同一批人，但操作发生在 IM 平台。
- **员工**：在 IM 里私聊机器人、把机器人拉进群、@ 机器人提问、点击卡片按钮。能力等于其在 iWorker 的全部能力。
- **系统**：保持与 IM 平台的连接；按身份匹配字段识别员工；把运行时产出的标准消息按平台能力适配后投递；执行重试、频控和推送合并。

### 3. 核心业务流程

1. 管理员在 IM 平台创建企业自建应用、添加机器人能力、开通权限并订阅事件。
2. 管理员在 iWorker【新建机器人】中选择渠道，填写应用凭据并选择连接方式；保存时系统验证凭据有效、应用所属组织与本企业一致。
3. 创建成功后机器人状态为“待平台发布”；管理员回到 IM 平台发布应用版本并设置可用范围，系统检测到发布后状态变为“正常”。
4. 员工在 IM 里给机器人发消息：
   - 系统按身份匹配字段（如工号）找到对应的 iWorker 用户，以该用户身份和全部能力处理请求。
   - 找不到对应用户时，回复账号未开通提示卡（请联系管理员），不执行任何能力。
5. 员工把机器人拉进群：立即生效（第一版不提供审批和白名单）；群里每条指令都以发起人本人的身份执行。
6. 定时任务结果、系统告警等按固定规则确定收件人（定时任务推给创建人，群里创建的推到该群），经推送服务找到员工的 IM 身份后，通过对应机器人发给员工或群；同一来源短时间内的多条推送合并发送。详见第七章 2。
7. 可用范围（哪些员工能在 IM 里搜到机器人）由 IM 平台管理员在 IM 开发者后台维护；第一版 iWorker 不提供可用范围比对。

### 4. 核心业务规则

- **每个 IM 平台默认接入 1 个机器人**：上限 N 为部署级配置（默认 1），所有已启用平台都达到上限后，【新建机器人】置灰。
  - 数据模型按“平台 + 组织”存储机器人，不假设“一个平台只有一个机器人”，以兼容集团多组织、测试与正式分开等场景；本期页面按上限 1 设计。
  - 本企业在各平台的组织标识（tenant_key / corpId）是部署级配置，可配多个；新建或更换应用时，凭据所属组织必须在其中。未配置时，以首个验证通过的机器人所属组织为准并写入。
- **员工能力 = 岗位私有能力 + 内置能力 + 市场安装的能力**：
  - 岗位私有能力：员工被分配岗位后获得；未分配岗位的员工没有这部分。
  - 内置能力：所有员工都有。
  - 市场安装的能力：员工在用户端能力市场自己添加的，每人不同。
- **机器人不裁剪、不授予能力**：同一员工在 IM、网页端、客户端的能力完全一致，不存在“把岗位下发到某个 IM”的配置。
- **专家不因机器人而默认可用**：员工点名使用自己还没添加的专家时，机器人以文字回复“你还没有添加专家「{专家名}」，可在 iWorker 网页端或客户端的能力市场添加后使用”，不执行该专家的能力；在群里 @ 时同样以文字回复。机器人不提供在 IM 里直接添加专家的卡片。专家的默认添加范围在“专家”模块配置。
- **身份按统一主数据字段自动匹配**：IM 通讯录与 iWorker 用户来自同一份用户主数据，按部署级配置的匹配字段（如工号）对齐，不使用应用级 open_id；匹配不上或命中多个时不绑定，在主数据源头修正。渠道不提供手动绑定、解绑和冲突处理（见第六章）。
- **群聊执行身份固定为发起人本人**，不提供“以群主身份 / 以机器人身份”执行的选项。
- **群聊能力与单聊一致，不按人单独配置**：每个人在群里能用的能力以他自己的能力为上限（规则见第五章 4.1）。
- **群不绑定岗位**：岗位私有能力只跟人走，不跟群走（评估见第五章 5）。
- **群聊默认规则第一版固定，不提供配置**：入群准入为立即生效、群内响应方式为仅 @ 机器人时响应、群内能力范围为按发起人自己的能力、业务沉淀为需显式指令；在“群聊治理 → 群聊规则”只读展示（见第五章 4）。
- **第一版不提供单个群配置**：所有群按群聊规则执行，管理员只能查看和移出群。
- **可用范围在 IM 平台维护**：iWorker 不代为修改，第一版也不拉取和比对；员工搜不到机器人时，由 IM 平台管理员在 IM 开发者后台把该员工加入可用范围并发布版本。
- **投递记录不保留正文**：后台只保留时间、对象、事件、结果、耗时等元数据，保留 180 天，供运维排查；第一版管理后台不提供投递日志页签（见第八章）。
- 应用凭据中的密钥保存后不回显，编辑时留空表示不修改。
- **快捷指令固定提供，不在后台配置**：单聊和群聊（@ 机器人后输入）都支持以下指令，所有机器人一致；欢迎卡和 /help 回复里列出这些指令。

  | 指令 | 作用 |
  |---|---|
  | /new | 结束当前会话，开启新会话 |
  | /skills | 按员工自己的能力（岗位私有 + 内置 + 市场安装）生成能力清单 |
  | /status | 列出员工正在执行的任务和进度 |
  | /help | 说明机器人能做什么、指令列表和常见问题 |

  不做开关的原因：关闭指令对企业没有管控价值（这些指令只读员工自己的信息、不越权），反而会造成问题——例如关掉 /new 后，员工就没法主动开启新会话。指令的增减属于产品版本变更，由研发统一发布。
- **飞书机器人菜单不在 iWorker 后台配置或展示**：菜单只在飞书开发者后台配置才生效，后台读不到飞书的菜单配置。实施时建议菜单动作选“发送文字消息”，内容填快捷指令（如 /new、/skills、/status），复用快捷指令逻辑，不需要约定事件 Key。

### 5. 平台差异

| 项目 | 飞书 | 钉钉 | 企业微信 |
|---|---|---|---|
| 组织标识 | tenant_key（验证凭据时自动获取） | corpId（验证凭据时自动获取） | CorpID（新建时必填，`ww` 开头） |
| 应用标识 | App ID（`cli_` 开头） | AppKey / Client ID | AgentID（纯数字） |
| 应用密钥 | App Secret | AppSecret / Client Secret | Secret |
| 连接方式 | 长连接（推荐）/ HTTP 回调 | Stream 模式（推荐）/ HTTP 模式 | 仅 HTTP 回调 |
| HTTP 额外字段 | Encrypt Key、Verification Token | 无 | Token、EncodingAESKey，并配置企业可信 IP |
| 机器人菜单 | 在飞书开发者后台配置，iWorker 后台不展示 | 不支持 | 不支持 |
| 群聊 | 支持 | 支持 | 自建应用通常无法进入普通群（需研发确认） |

本表内容由“平台描述配置”维护（见 6），页面按配置渲染，不写死在代码中。

### 6. 配置分层（标品兼容）

渠道作为管理后台标品，需要在不同企业中**只靠配置**完成适配，不改代码。所有可变项按以下四层归属，每一项只在一层维护：

| 层级 | 维护方 | 生效方式 | 内容 |
|---|---|---|---|
| 产品固定 | 产品 / 研发 | 随版本发布 | 会话规则、快捷指令、内置卡片、推送规则（第七章） |
| 平台描述配置 | 产品 / 研发 | 远程配置更新，不发版 | 每个 IM 平台一份，内容见下 |
| 部署级配置 | 实施 / 运维 | 部署或实施时设置，不在管理后台展示 | 网络、域名、上限、组织标识，内容见下 |
| 管理员配置 | 平台管理员 | 机器人抽屉、群聊治理等页面 | 名称、凭据、连接方式等（欢迎卡、群聊开关后续版本开放） |

**平台描述配置**（新增平台或平台规则变化时只改这份配置）：

- 平台标识、名称、开发者后台名称、是否启用（控制【新建机器人】中是否出现该平台卡片）。
- 凭据字段：组织标识（是否需要填写）、应用标识、应用密钥，以及 HTTP 回调的额外字段；每个字段包含名称、占位提示、是否密钥（不回显）、校验规则和错误文案。
- 连接方式及说明（如长连接 / HTTP 回调），哪个为推荐。
- 平台能力：是否支持群聊、话题、卡片原地更新、流式输出（附录 B），决定编辑页是否展示群聊区域和投递时的降级方式。
- 权限与事件清单，以及必需权限的自动检测方式（附录 C）；是否支持批量导入 JSON。

**格式校验原则**：前端只做宽松校验（必填、前缀、字符集、长度范围），不做精确位数校验；凭据是否有效以【验证凭据】和保存时的自动验证结果为准，避免平台调整格式后合法凭据被拦下。

**部署级配置**：

| 配置项 | 说明 | 默认值 |
|---|---|---|
| 开放平台 API 地址 | 各平台接口域名；飞书私有化、Lark 国际版、钉钉专属版等与公有云不同 | 各平台公有云地址 |
| 回调公网域名 | 生成 HTTP 回调地址，如 `https://{域名}/open/im/{平台}/events` | 部署域名 |
| 出口 IP | 展示在企业微信“企业可信 IP”提示和权限清单中 | — |
| 出站代理 | 内网部署时长连接 / Stream / 接口调用经过的代理 | 不使用 |
| 每个 IM 平台的机器人上限 | 控制【新建机器人】置灰和渠道卡片置灰 | 1 |
| 本企业组织标识 | 各平台允许接入的 tenant_key / corpId，可配多个 | 首个验证通过的机器人写入 |
| 重试与频控 | 出站失败重试、待发消息保留时长、令牌桶预留余量（见第八章 2） | 最多 3 次 / 24 小时 / 20% |
| 身份匹配字段 | 每个 IM 平台一组：IM 侧字段 ↔ iWorker 用户字段，如“飞书 user_id ↔ 主数据工号”“钉钉 userid ↔ 主数据账号” | 按实施时的主数据规范设置 |

## 二、导航栏

### 1. 功能说明

- **页面标题**：展示“渠道”。
- **页面说明**：展示“接入飞书、钉钉、企业微信机器人，统一配置单聊与群聊”。
- **页签**：【机器人】【群聊治理】。
- **业务说明条**：每个页签顶部展示一条，说明该页签最关键的规则（见各章节）。
- **查询区**：每个列表页签提供搜索框、下拉筛选和【查询】；页签专属的次级入口（如【群聊规则】【消息设置】）放在查询区右侧。

### 2. 交互规则

- 切换页签时保留各页签自己的搜索和筛选，返回时恢复（两个列表都不分页）。
- 在搜索框按回车或点击【查询】后，列表按当前条件刷新；清空搜索内容后自动刷新。
- 切换下拉筛选后自动刷新。
- 搜索忽略前后空格，支持部分匹配。
- 查询过程中保留当前列表内容并展示加载状态，避免页面整体闪烁。
- 打开或关闭抽屉、弹窗时保留列表当前查询条件；完成保存、停用、移出等操作后按原条件刷新列表。
- 点击侧栏其他菜单时正常跳转（原型中仅提示）。

### 3. 页面状态与异常场景

- **首次暂无机器人**：展示“还没有机器人 · 点「新建机器人」接入第一个 IM 平台”。
- **无查询结果**：展示“没有符合条件的记录”，保留查询条件并提供【清空筛选】。
- **列表加载失败**：展示“加载失败”和【重试】；点击后按当前条件重新加载。
- **无管理权限**：不展示“04运行 → 渠道”菜单，也不允许通过地址直接进入。
- **汇总加载失败**：列表正常展示，底部汇总显示“—”，不阻塞操作。

## 三、机器人

### 1. 列表展示

业务说明条：“每个 IM 平台最多接入 **N 个机器人**；员工在机器人里使用自己的全部能力（**岗位私有 + 内置 + 市场安装**），机器人不裁剪、也不额外授予能力。”

查询区：搜索框（占位“搜索机器人名称或用途说明”）、渠道筛选（全部渠道 / 飞书 / 钉钉 / 企业微信）、状态筛选（全部状态 / 正常 / 连接中断 / 待平台发布 / 已停用）、【查询】；右侧【消息设置】（次级按钮）、【+ 新建机器人】。

- **机器人名称**。
- **用途说明**：单行展示，超长省略并支持悬停查看完整内容；为空时展示“—”。
- **渠道**：飞书 / 钉钉 / 企业微信。
- **连接方式**：按平台名称展示，如“长连接”“Stream 模式”“HTTP 回调”。
- **状态**：
  - 正常（绿色）。
  - 连接中断（红色），第二行展示原因，如“AppSecret 已失效”“缺少必需权限：Card.Instance.Write”。
  - 待平台发布（橙色），第二行展示“{平台}侧未发布应用版本”。
  - 已停用（灰色），第二行展示“员工发消息不会得到回复”。
- **最近更新**：最近一次保存成功的时间，精确到分钟。
- **操作**：【查看】【编辑】【停用】/【启用】。
- **底部汇总**：“N 个机器人 · 已接入 N / M 个 IM 平台”，M 为平台描述配置中已启用的平台数。
- 第一版列表不展示场景、可用范围、今日消息三列：场景所有机器人一致（单聊始终开启、群聊按平台能力）；可用范围在 IM 平台维护，第一版不在管理后台展示；消息量第一版不在管理后台展示。

数据规模说明：机器人数量 = 已启用平台数 × 每平台上限，默认最多 3 条，列表不分页。

**评审步骤 1：进入“04运行 → 渠道”，查看机器人列表、查询区、各列字段和底部汇总。**


### 2. 排序规则

- 默认按最近更新时间由近到远排列。
- 新建成功后，新机器人排在最前。
- 编辑保存、更换应用、停用、启用都会更新最近更新时间。
- 连接状态由系统变化（如凭据失效）时，不更新最近更新时间，只写入操作记录。

### 3. 操作

#### 3.1 操作按钮展示规则

- 【查看】【编辑】始终可用。
- 正常、连接中断、待平台发布状态展示红色【停用】；已停用状态展示【启用】。
- 所有已启用的 IM 平台都达到机器人上限时，【+ 新建机器人】置灰，悬停提示“各 IM 平台均已达到机器人上限（每个 IM 平台最多接入 N 个机器人）”。
- 机器人不提供删除。不再使用时停用；需要换成另一个 IM 应用时，在编辑页【更换应用】。
- 保存、停用等操作进行中时，本机器人的重复操作不可再次提交。

#### 3.2 查看

- 点击【查看】，以只读方式打开机器人抽屉，标题“查看机器人”。
- 打开时展示骨架屏，数据加载完成后展示内容。
- 查看状态展示：时间信息、基本信息、应用凭据（密钥不回显，可展开权限清单）、员工能力、最近 5 条操作记录。
- 所有输入项不可修改，底部仅展示【关闭】。

**评审步骤 2：点击飞书机器人【查看】，先核对骨架屏和基本信息，再向下滚动核对员工能力和操作记录。**




#### 3.3 编辑

- 点击【编辑】，打开机器人抽屉，标题“编辑机器人”，展示当前内容。
- 可修改：名称、用途说明、应用密钥（留空不修改）、连接方式。
- 不可修改：渠道、组织标识、应用标识（App ID / AppKey / AgentID）。需要换应用时点击【更换应用】。
- 连接中断的机器人打开编辑时，顶部展示红色提示，内容按中断原因区分：
  - 凭据失效：“连接中断：{密钥名} 已失效……在下方「应用凭据」填写新的 {密钥名} 并保存即可恢复”，并自动定位到应用凭据区域。
  - 缺少必需权限：“连接中断：缺少必需权限 {权限名}……在{平台开发者后台}开通权限并发布应用版本后，系统会在 10 分钟内自动检测并恢复；可在下方「应用凭据」展开权限清单对照”。不要求填写新密钥。
- 修改应用密钥或连接方式时，保存前弹出“连接配置变更”确认（见第四章 6.2）。
- 保存成功后提示“机器人已保存”，关闭抽屉并刷新列表。

**评审步骤 3：点击飞书机器人【编辑】，核对基本信息、应用凭据、连接方式。**


#### 3.4 可用范围（第一版不提供）

- 第一版机器人列表不提供【可用范围】操作，也不提供“范围比对”“搜不到机器人名单”和导出；iWorker 不拉取 IM 平台的可用范围。
- 可用范围仍然决定哪些员工能在 IM 里搜到机器人，由 IM 平台管理员在 IM 开发者后台维护，修改后需发布应用版本才生效。
- 员工反馈“搜不到机器人”时：由 IM 平台管理员在 IM 开发者后台核对并加入可用范围。
- 后续版本规划：恢复【可用范围】弹窗，比对“iWorker 员工”和“IM 可用范围”两份名单，分为正常可用 / 搜不到机器人 / 未开通账号三类，支持搜索和导出名单；系统每 10 分钟自动拉取。

#### 3.5 停用与启用

- 点击【停用】，弹出二次确认：“停用后，员工在{平台}里给「{机器人名称}」发消息只会收到「机器人已停用」提示，机器人在 N 个群里不再响应，推送暂停（改发站内通知）。不影响网页端和客户端。确认停用？”
- 确认按钮为红色【停用】；取消时不执行。
- 停用成功后提示“机器人已停用”，状态变为“已停用”，操作列变为【启用】。
- 停用期间保留全部配置和群关系；待推送消息不进入重发队列。
- 点击【启用】直接生效，不二次确认；成功后提示“机器人已启用”，系统重新建立连接。

**评审步骤 4：对飞书机器人点击【停用】，核对二次确认的影响说明。**


### 4. 状态规则

| 状态 | 进入条件 | 员工侧表现 | 恢复方式 |
|---|---|---|---|
| 待平台发布 | 新建成功；更换应用成功 | 在 IM 里搜不到机器人 | 在 IM 平台发布应用版本，系统检测到后自动变为正常 |
| 正常 | 连接建立、凭据有效 | 正常使用 | — |
| 连接中断 | 凭据失效、连接持续失败、缺少必需权限或事件（见第四章 5.2） | 消息收不到回复，待发消息进入重发队列 | 凭据失效：编辑填写新密钥并保存；缺少权限：在平台开通并发布版本，系统自动检测恢复；网络恢复后自动重连 |
| 已停用 | 管理员停用 | 只收到“机器人已停用”提示 | 管理员启用 |

- 连接中断时，列表状态第二行展示原因，并在操作记录中写入“连接中断”。
- 状态变为连接中断时，向所有平台管理员发送站内通知（第一版不设机器人负责人）。

### 5. 列表异常场景

- **机器人不存在**：打开或编辑时发现已被其他管理员更换应用或数据变化，提示“机器人信息已变化”并刷新列表。
- **重复提交**：保存、停用、启用过程中重复点击，不重复发送请求。
- **查询超时**：提示请求超时并提供【重试】，保留查询条件。

### 6. 消息设置

点击机器人页签查询区右侧【消息设置】打开弹窗，标题"消息设置"，对全部机器人生效。这是渠道里唯一由管理员配置的消息规则，其余消息规则由产品固定（见第七章）。

**消息合并等待时长**：员工常常连着发几条（先发文件、再补一句要求）。系统收到消息后先等一段时间，**从最后一条算起**，期间连着发来的几条合成一件事处理，等待结束才回「收到」并开始做（员工端《PRD-IM对接》§4.2 第 5 条）。

| 项 | 规则 |
|---|---|
| 必填 | 是 |
| 输入 | 输入框，后缀"秒"；只接受 1–30 的整数 |
| 默认值 | 5（出厂值；弹窗展示的是当前已保存的值） |
| 说明文案 | 字段下方灰字："员工在 IM 里连着发的几条消息，从最后一条算起等这么久，期间发来的合成一件事处理。时长越长，员工收到「收到」越晚。" |
| 校验 | 清空时提示"请填写消息合并等待时长"；不是整数或不在 1–30 之间时提示"请填写 1–30 之间的整数"。点【保存】时校验，不自动取整、不自动拉回范围 |

- 弹窗底部【取消】【保存】；值与已保存的相同时【保存】置灰。
- 保存成功提示"已保存，对全部 IM 机器人生效"并关闭弹窗；失败提示原因，弹窗不关、保留填写的值。
- 保存后立即对全部机器人生效，客户端和网页端下一次判断合并时按新值执行；保存那一刻已经在等待合并的消息按保存前的值走完。
- 打开弹窗时读取失败：弹窗内展示"配置读取失败"与【重试】，不展示可编辑的输入框。
- 不按平台、机器人、群、员工单独设置。
- 群聊里 @ 机器人连发的几条同样按此合并。

## 四、机器人编辑页

### 1. 页面状态

机器人编辑页以右侧抽屉形式展示，宽度 720px，包含“新建、编辑、查看”三种状态。

- **新建**：通过【+ 新建机器人】进入，标题“新建机器人”。
- **编辑**：通过列表【编辑】进入，标题“编辑机器人”；打开时展示骨架屏。
- **查看**：通过列表【查看】进入，标题“查看机器人”，全部只读。
- 点击抽屉外区域不关闭抽屉。
- 点击右上角关闭或【取消】时（按 Esc 不关闭抽屉，沿用全站约定：所有弹窗和抽屉不响应 Esc，避免输入法候选态误关）：新建或编辑状态存在未保存修改，弹出“放弃未保存的修改？”确认（【继续编辑】【放弃修改】）；无修改时直接关闭。
- 编辑或查看状态加载失败时，抽屉保留打开并展示“加载失败”和【重试】。

**评审步骤 5：点击【+ 新建机器人】，核对渠道选择、应用凭据区域；不填写直接点击【创建】，核对必填校验。**



**评审步骤 6：在编辑状态修改任意字段后点【取消】，核对放弃修改确认。**


### 2. 基本信息

- **渠道**：必填。
  - 新建状态以单选卡片展示平台描述配置中已启用的平台（默认飞书、钉钉、企业微信）；已达到上限的平台置灰，卡片说明“已接入「{机器人名称}」”，点击时提示“{平台}已达到机器人上限，每个 IM 平台最多接入 N 个机器人”；字段下方提示“每个 IM 平台最多接入 N 个机器人”。
  - 默认选中第一个未达上限的平台。
  - 切换渠道时清空应用凭据和连接配置，保留名称；用途说明若仍是自动生成的内容，随渠道更新。
  - 编辑和查看状态只读展示“{平台} · {组织标识}”。
- **机器人名称**：必填，2–20 个字，展示字数计数；提示“与{平台}平台上的应用名保持一致”。
- **用途说明**：非必填，最多 60 个字，展示字数计数；给其他管理员看。

### 3. 应用凭据

- 区域标题旁提示“在{平台开发者后台}创建应用后填写”。
- 新建状态展示说明条：“先在{平台开发者后台}创建企业自建应用、添加机器人能力、开通权限并订阅事件；可用范围可以上线后再设置。”，末尾提供【查看权限清单】。
- 编辑和查看状态展示说明条：“缺少必需权限时，系统自动检测并在列表状态显示「连接中断 · 缺少必需权限」。”，末尾同样提供【查看权限清单】，便于管理员自行对照（见 5.2）。
- **权限清单**：点击【查看权限清单】在说明条下方展开，再次点击【收起权限清单】。内容按所选渠道展示，清单明细见附录 C：
  - 分三组：必需权限、按需权限（注明对应哪个功能）、事件订阅；必需权限和事件与后台自动检测的范围一致。
  - 每项展示权限标识、中文说明和“必需 / 按需”标签。
  - 底部提供【复制清单】：复制全部权限和事件，每行格式为“权限标识 ⇥ 中文说明 ⇥ 必需/按需 ⇥ 用于：功能”，事件单独一组，便于对照或粘贴到表格。
  - 飞书额外提供【复制必需权限（批量导入 JSON）】：复制 `{"scopes":{"tenant":[...],"user":[]}}` 格式的必需权限，提示“已复制，在飞书开发者后台「权限管理 → 批量导入权限」粘贴”。按需权限不放进 JSON，避免管理员一次开通不需要的敏感权限。
  - 复制成功提示“已复制到剪贴板”（飞书 JSON 除外，见上）。
  - 清单底部灰字：“权限标识以平台最新文档为准；必需权限缺失时，列表状态显示「连接中断 · 缺少必需权限」；按需权限可以上线后再开通。”
- **组织标识**：是否需要填写由平台描述配置决定。企业微信需填写 CorpID：新建必填，`ww` 开头，提示“用于获取访问凭证，并校验与本企业组织一致”；编辑和查看状态不单独展示，显示在“渠道”字段中。飞书、钉钉在验证凭据时自动获取 tenant_key / corpId，不需要填写。
- **应用标识**（App ID / AppKey / AgentID）：新建必填，按平台描述配置做宽松格式校验（见第一章 6）；编辑和查看只读，编辑时标签右侧展示【更换应用】。
- **应用密钥**（App Secret / AppSecret / Secret）：
  - 新建必填，做宽松格式校验，提示“保存后不再回显”。
  - 编辑时占位“已配置 · 留空不修改”；因凭据失效而连接中断时占位“填写新的 {密钥名}”，且必须填写；因缺少权限而中断时不要求填写。
  - 输入框右侧【显示】/【隐藏】切换明文。
- **【验证凭据】**：可选的提前验证，结果展示在按钮右侧：
  - 验证中：加载图标 +“验证中…”。
  - 通过：“✓ 验证通过 · 所属组织 {组织标识}”。
  - 失败：“✕ {原因}”。
  - 修改组织标识、应用标识或密钥后，验证结果清空。
- **连接方式**：必填，单选卡片（企业微信只有 HTTP 回调，只读展示）。
  - 编辑时切换连接方式，字段下方橙色提示“切换连接方式会短暂中断收消息（约 10 秒），保存前会再次确认”。
- **HTTP 回调字段**（选择 HTTP 时展示）：
  - 平台额外字段（见第一章 5），首次切换为 HTTP 时必填。
  - **回调地址**：只读，由部署级配置的回调公网域名生成，提供【复制】；企业微信同时提示把部署级配置中的出口 IP 加入企业可信 IP。
  - 首次配置 HTTP 时，需要在平台保存回调地址后点击【检测校验】，等待平台发起校验请求并通过，否则不能保存。

#### 3.1 更换应用

- 点击【更换应用】，打开“更换应用 · {机器人名称}”窗口。
- 橙色说明条列出影响：员工在 IM 里看到的是新的机器人会话；open_id 变化，系统按身份匹配字段自动重新识别；已加入的 N 个群需要重新拉入；新应用需要重新设置可用范围并发布版本。
- 填写新应用标识和密钥（均必填），点击【验证新应用】。新应用标识与当前相同时提示“和当前应用相同，无需更换”。
- 验证通过前【更换应用】置灰；新应用必须与原组织一致。
- 点击【更换应用】后再次确认，确认后机器人状态变为“待平台发布”，提示“已更换应用，请在{平台开发者后台}发布新应用版本”。

### 4. 单聊与群聊（第一版不配置）

第一版新建、编辑、查看机器人时都不展示“单聊”“群聊”区域，所有机器人统一按以下规则运行：

| 项目 | 第一版规则 | 后续版本 |
|---|---|---|
| 单聊 | 始终开启 | 不提供开关（原因见下） |
| 首次使用欢迎卡 | 默认发送：员工第一次打开单聊时，按其岗位和安装情况自动生成，每人一次 | 开放“首次使用欢迎卡”开关 |
| 群聊 | 平台支持群聊时始终启用；群内规则见第五章 4“群聊规则” | 开放“启用群聊”开关（关闭后机器人在已加入的群里不再响应，群记录保留） |

- **单聊不提供开关的原因**（后续版本同样不提供）：
  - 群聊的安全规则依赖单聊：敏感知识、个人数据、市场连接器产出在群里只提示“已私信你”，结果发到发起人单聊。
  - 账号未开通提示、连接器授权卡等个人卡片都发到单聊，不适合发在群里。
  - 定时任务结果、系统告警等主动推送和长任务完成通知都通过单聊送达员工本人。
  - 平台侧也无法单独关闭：飞书、钉钉的企业自建应用机器人添加后，员工就能在通讯录里搜到并发起单聊，iWorker 关闭单聊只能做到“收到不回”，体验比开着更差。
- **需要限制使用时**：用“可用范围”控制谁能搜到机器人；不希望机器人留在某个群时，在群聊治理中【移出】；需要整体停止时【停用】机器人。
- **平台不支持群聊**：由平台描述配置声明，该平台机器人只提供单聊。企业微信自建应用通常无法进入普通群，以研发确认结果为准。
- 会话规则、主动推送规则由产品固定，见第七章 1、2。
- **数据层保留字段**：欢迎卡开关、群聊开关按上表取默认值（开启），后续开放配置时只需增加界面，不改数据结构。

### 5. 只读区域

#### 5.1 员工能力

- 只读，标题旁提示“由岗位分配和员工自己的市场添加决定，机器人不裁剪能力”。
- 三行说明：岗位私有能力（已分配岗位的 N 人）、内置能力（所有员工）、市场安装的能力（自己添加了的员工）。
- 不提供任何开关，不链接到岗位分配配置。

#### 5.2 必需权限自动检测（第一版无检测界面）

第一版抽屉中不展示“连接状态”区域，检测由后台自动完成，结果只通过列表状态和通知体现。

- **检测时机**：保存成功后立即检测一次（新建、填写新密钥、切换连接方式、更换应用）；之后每 10 分钟自动检测一次。
- **检测范围**：凭据有效、应用所属组织一致、连接（长连接心跳或回调地址可达）、必需权限与事件（收发消息、读取员工 ID、卡片回调、机器人进出群，见附录 C“必需”项）。按需权限（下载消息中的文件、读取群内全部消息）第一版不检测。
- **检测不通过**：机器人状态变为“连接中断”，列表第二行展示原因（如“缺少必需权限：Card.Instance.Write”）；写入操作记录；向所有平台管理员发送站内通知。
- **恢复**：管理员在平台开通权限并发布版本后，下一次检测通过即自动恢复为“正常”，写入操作记录；不需要在 iWorker 里操作。
- **检测方式**：各平台查询已开通权限的接口，或调用接口探测并按权限错误码判断，需研发逐个平台确认，结果写入平台描述配置。事件订阅缺失如无法主动检测，依赖管理员对照权限清单自查（待研发确认）。
- **第一版不提供**：逐项检测结果、【重新检测】、【复制缺少的权限】、【我已开通】。后续版本可在查看抽屉中恢复“连接状态”区域。

#### 5.3 操作记录

- 仅查看状态展示最近 5 条，包含操作、时间、操作人和变更摘要（如“用途说明：— → 飞书上的统一入口”）。
- 完整记录在“05治理 → 访问审计”查看。

### 6. 保存与关闭

#### 6.1 保存

- 新建状态底部【取消】【创建】；编辑状态【取消】【保存】；查看状态【关闭】。
- 点击【创建】或【保存】时，按“必填 → 格式 → 数值范围 → 唯一性 → 平台权限 → 配置影响”顺序校验。
- 校验不通过时不关闭抽屉，定位并聚焦到第一个错误字段，在字段下方展示原因（替换该字段的提示文字）。修改该字段后错误立即消失。
- 新建或填写了新密钥时，保存时自动验证凭据：按钮展示“正在验证凭据…”；已经手动验证通过的，按钮展示“保存中…”。
- 保存过程中【创建】/【保存】和【取消】不可重复点击。
- 创建成功后提示“机器人已创建，请在{平台开发者后台}发布应用版本并设置可用范围”，关闭抽屉并刷新列表。
- 编辑成功后提示“机器人已保存”，关闭抽屉并刷新列表；连接中断的机器人填写新密钥保存成功后恢复为正常。
- 保存失败时保留全部填写内容，展示失败原因，可修改后重试。

#### 6.2 配置变更影响

- **普通配置变更**（名称、用途说明）：保存后立即生效，不中断连接，不弹确认。
- **连接配置变更**（替换应用密钥、切换连接方式）：保存前弹出“连接配置变更”确认，列出本次变更项，并说明“重连期间约 10 秒收不到消息，平台会重试投递”。取消时不保存。
- 所有保存成功的变更写入操作记录，记录变更摘要。

**评审步骤 7：编辑连接中断的钉钉机器人，填写新的 AppSecret 后保存，核对连接配置变更确认。**

**评审补充：机器人因缺少必需权限而连接中断时，核对列表状态原因和编辑抽屉顶部提示。**




### 7. 时间信息

- 仅编辑和查看状态展示，位于抽屉顶部：创建时间、最近更新。第一版不设机器人负责人，连接中断等通知发给所有平台管理员。
- 精确到分钟，只读。
- 系统检测到的状态变化不更新最近更新时间。

### 8. 编辑页异常场景

- **未选择渠道**：“请选择渠道”。
- **渠道已达上限**：“{平台}已达到机器人上限，每个 IM 平台最多接入 N 个机器人”。
- **名称为空 / 过短**：“机器人名称不能为空”/“机器人名称至少 2 个字”。
- **组织标识为空 / 格式错误**（企业微信）：“请填写 CorpID”/“CorpID 应以 ww 开头，只含字母或数字”。
- **应用标识为空**：“请填写 {标识名}”。
- **应用标识格式错误**：文案来自平台描述配置，如“App ID 应以 cli_ 开头，只含字母或数字”“AgentID 应为纯数字”。
- **应用标识重复**：“该 {标识名} 已被其他机器人使用”。
- **密钥为空 / 格式错误**：“请填写 {密钥名}”/如“App Secret 应为 16–128 位，不含空格”。
- **连接中断未填新密钥**：“连接已中断，请填写新的 {密钥名}”。
- **凭据验证失败**：“凭据验证失败：平台返回 invalid credentials”。
- **组织不一致**：“凭据属于另一个{平台}组织，与本企业不一致，员工身份无法复用”（本企业组织标识见第一章 6 部署级配置）。
- **HTTP 字段为空**：“请填写 {字段名}”。
- **回调未校验**：“请先在平台保存回调地址并完成校验”。
- **并发编辑冲突**：提示“机器人已被其他管理员更新”，提供【加载最新内容】；未经确认不覆盖他人修改。
- **加载失败 / 保存失败**：展示原因和【重试】，保存失败时保留填写内容。

## 五、群聊治理

业务说明条：“群里的每条指令都以**发起人本人**的身份和权限执行；能力以**发起人自己的能力为上限**；所有群按「群聊规则」执行，不单独配置。”

查询区：搜索框（占位“搜索群名称或拉入人”）、渠道筛选、【查询】；右侧主按钮【群聊规则】（与【+ 新建机器人】同样的绿色主按钮样式；本页签没有新建操作）。

- **群**：第一行群名称，第二行“拉入人 {姓名} · {拉入时间}”。
- **渠道**。
- **成员**：人数。
- **最近更新**。
- **操作**：【查看】【移出】。
- **底部汇总**：“N 个群”。
- 第一版入群立即生效、不做外部成员识别，列表中的群都处于生效状态，因此不展示“状态”列和状态筛选。
- **排序**：按最近更新时间由近到远。

**评审步骤 8：切换到【群聊治理】，核对群列表字段和操作。**


### 2. 移出

- **移出**：二次确认“移出后机器人会退出「{群名称}」，群记录保留 30 天，期间重新拉入可恢复。确认移出？”，确认后提示“机器人已移出群”。
- 第一版不提供入群审批和拒绝：员工把机器人拉进群即生效；不希望机器人留在某个群时，管理员【移出】。

### 3. 查看群

- 点击【查看】打开右侧抽屉“查看群”，全部只读，底部只有【关闭】。
- **群信息**：群名称、渠道 / 机器人、成员人数、拉入人；顶部展示拉入时间、最近更新。
- **群内规则**：响应方式“仅 @ 机器人时响应”、能力范围“按发起人自己的能力”、业务沉淀“需显式指令”；标题旁提示“按「群聊规则」执行，所有群一致”。
- 第一版不提供单个群配置。群列表不展示响应方式、能力范围、业务沉淀三列（所有群取值相同）。

**评审补充（步骤 9 前）：对钉钉群点击【查看】，核对群信息和群内规则。**


### 4. 群聊规则

点击【群聊规则】打开右侧抽屉（标题“群聊规则”），只读，作用于所有机器人和群，底部只有【关闭】。第一版群聊默认规则固定，不提供配置界面。

#### 4.1 群聊能力的三层规则

群聊不按人单独配置能力。每个人在群里能用的能力，以他自己在 iWorker 的能力为上限：

| 层级 | 在哪配 | 内容 |
|---|---|---|
| 个人能力（上限） | 岗位分配 + 员工在市场自行添加 | 岗位私有 + 内置 + 市场安装；单聊、群聊、网页端、客户端完全一致 |
| 群聊默认规则 | 第一版产品固定，群聊治理 → 群聊规则只读展示 | 入群准入、默认响应方式、群内能力范围、业务沉淀；另有固定规则 |
| 单个群 | 第一版不提供配置 | 后续版本开放：响应方式、能力范围、业务沉淀只能比默认规则更严 |

方案评估：

| 方案 | 结论 | 原因 |
|---|---|---|
| 个人能力为上限，群只收紧 | 采用 | 不越权；和单聊一致，员工好理解；按群配置，管理成本低 |
| 群聊按人单独配置 | 不采用 | 3 万人 × 场景无法维护；同一员工两套能力，排查困难 |
| 群绑定能力（群岗位、群能力包） | 不采用 | 拉群即可绕过岗位分配；上千个群逐个配置不现实 |
| 个人能力 + 群共享资源（给群挂共享知识库，按成员权限读取） | 暂不做 | 待有真实需求再评估 |

**评审步骤 9：点击【群聊规则】，核对群聊默认规则和固定规则。**



#### 4.2 群聊默认规则（第一版固定，只读）

| 规则 | 第一版取值 |
|---|---|
| 入群准入 | 立即生效：任何已绑定员工把机器人拉进群即可使用 |
| 群内响应方式 | 仅 @ 机器人时响应 |
| 群内能力范围 | 按发起人自己的能力（岗位私有 + 内置 + 市场安装，和单聊一致） |
| 业务沉淀 | 需显式指令（员工说“沉淀到 X”才写入工作档案） |

- **页面上不展示未开放的选项**（不做置灰）：置灰适合“满足条件后可用”的场景；第一版不支持的选项管理员无法启用，展示出来只会引发咨询。
- **数据层保留四个字段**（入群准入、默认响应方式、群内能力范围、业务沉淀），按上表取固定值；后续版本开放配置时只需增加界面，不改数据结构。
- **后续版本规划**（第一版不做）：入群准入增加“管理员审批后生效”“仅白名单群”及对应的审批 / 拒绝、待审批状态和页签角标；响应方式增加“自动响应”（需平台开通“读取群内全部消息”权限）；群聊规则改为可配置的“群聊策略配置”，支持全局收紧为“只用内置能力”“禁止沉淀”；单个群配置（【配置】按钮、群列表的响应方式 / 能力范围 / 业务沉淀列、“按全局策略”提示），单个群可改为仅推送、只用内置能力、禁止沉淀。
- **数据层同样为每个群保留这三个字段**，第一版取默认值，后续开放单个群配置时不改数据结构。

#### 4.3 固定规则（只读，安全底线）

| 规则 | 内容 |
|---|---|
| 执行身份 | 群里每条指令、每个群定时任务，都以发起人本人执行时的身份和能力执行 |
| 结果可见性 | 个人数据（邮件、日程）、个人授权的连接器产出、命中敏感知识库的内容，结果只私信发起人，群里只提示“已私信你” |
| 产物与确认 | 产物下载链接绑定发起人；二次确认卡只有发起人能点 |
| 个人记忆 | 群会话不写入任何人的个人工作记忆 |
| 员工提示 | 能力在群里不可用或结果只能私信时说明原因，如“该内容只能私信你，已发到单聊”；/skills 列出本群可用的能力 |

本版删除的旧配置项：群内有外部成员时、发起人从能力市场安装的能力、4 项群内结果可见性、群会话记忆，均改为上表中的固定规则。

#### 4.4 外部成员（第一版不处理）

- **第一版不做外部成员识别**，群列表和查看群中不展示外部人数，也没有“已拦截”状态。原因：
  - 大多数企业内部群不含外部成员（客户、供应商、合作方）。
  - 企业自建应用机器人通常无法被拉进外部群 / 跨组织群 / 客户群，平台侧已有限制。
- **兜底**：外部成员在群里 @ 机器人时，因匹配不到 iWorker 账号，不会执行任何能力；员工发起的指令仍按“结果可见性”固定规则处理，个人数据、个人授权连接器产出、敏感知识只私信发起人。
- **残留风险**：若某平台允许机器人进入含外部成员的群，员工在群里发起的非敏感问答结果会被外部成员看到。
- **待研发确认**：飞书、钉钉、企业微信的企业自建应用机器人能否加入外部群。如有平台可以加入，后续版本恢复外部成员识别：群里有非本企业 IM 组织的成员时不响应，只回复一次“本群含外部成员，暂不可用”，群列表展示“已拦截”状态和外部人数。

#### 4.5 群定时任务

员工在群里发起的定时任务（如“每周一 9 点在群里发销售周报”）：

- **能力按执行时计算**：每次执行都以发起人当时的身份和能力为上限，并受群内能力范围和固定规则约束。

  | 执行时的变化 | 处理 |
  |---|---|
  | 发起人换岗或岗位被取消 | 按新能力执行；依赖的能力没了则本次失败，私信发起人 |
  | 发起人卸载市场能力或连接器授权过期 | 本次失败，私信发起人去重新添加或授权，群里不报错 |
  | 发起人离职、冻结或停用 | 任务自动暂停，通知群主和管理员；不允许他人接管后沿用原发起人权限 |
  | 发起人被移出群、机器人停用或被移出群 | 任务暂停 |

- **结果可见性**：群里看不了的内容（个人数据、个人授权连接器产出、敏感知识）只私信发起人。创建时先发二次确认卡，说明任务会用到哪些能力、哪些结果会私信。
- **管理**：发起人可修改、暂停、删除；群主可暂停本群任务；管理员可在后台停用。后续可在群详情中展示“本群定时任务”列表，本期原型未包含。
- **结果推送**：执行结果发到该群；群不可用（未生效、机器人被移出）时私信发起人“推送目标群不可用”。
- **额度**：执行消耗计入发起人配额。

### 5. 不提供群岗位

群不绑定岗位，群列表和查看群中都不出现“群岗位”。评估结论如下：

- **与能力模型冲突**：员工能力只来自“岗位私有 + 内置 + 市场安装”，机器人不授予能力。给群绑定岗位后，发起人不持有该岗位时：
  - 允许使用群岗位能力：等于绕过岗位分配，拉个群就能拿到别的岗位的技能、知识库和工作档案。
  - 不允许使用：一个员工最多持有一个岗位，持有该岗位的人本来就有这些能力，群岗位对谁都不起作用。
- **管理成本不成立**：万人企业有上千个群，每个群都要管理员挑岗位，审批变慢且没人维护；群成员岗位变化后，群岗位也会过期。
- **“统一口径”另有承接**：
  - 需要口径统一的跨部门群，后续版本可在单个群配置里选“只用内置能力”。
  - 需要特定领域回答的，由员工 @ 自己已添加的专家。
  - 项目群需要共享上下文的，走业务沉淀（需显式指令写入工作档案），读取时仍按发起人本人的权限。

## 六、身份匹配（后台自动，无管理界面）

企业现场统一对接统一身份认证平台，IM 通讯录和 iWorker 用户都来自同一份用户主数据。渠道只负责按主数据字段把 IM 账号对到 iWorker 用户，不提供身份映射页签，也不提供手动绑定、解绑、冲突处理。

### 1. 匹配规则

- **匹配字段**：部署级配置（见第一章 6），每个 IM 平台一组“IM 侧字段 ↔ iWorker 用户字段”，如“飞书 user_id ↔ 主数据工号”。不同企业主数据主键不同，只改配置，不改代码。
- **匹配时机**：员工首次在 IM 里与机器人交互时匹配，结果缓存；主数据同步后按变化刷新。
- **不使用应用级 open_id**：更换应用后 open_id 变化，按匹配字段重新识别，不影响员工身份。
- **匹配不上**：单聊回复“账号未开通提示卡”（你的账号尚未开通 iWorker 或信息不一致，请联系管理员），不执行任何能力；后台投递记录写入“未匹配到 iWorker 账号”。在群里 @ 机器人时同样不执行，私信发起人该提示。
- **命中多个账号**：不绑定，处理同“匹配不上”，后台投递记录写入“匹配到多个账号”。原则：宁可不用，不能认错人；在主数据源头修正。

### 2. 生命周期（随主数据）

- 主数据标记离职或停用：机器人立即停止为其执行，不等账号删除；主动推送跳过。
- 岗位分配、换岗或取消：匹配关系不变，岗位私有能力随之变化。
- 员工被移出 IM 可用范围：匹配关系保留；主动推送因平台返回失败而改发站内通知。

### 3. 管理员如何排查“某人用不了机器人”

- 员工在 IM 里搜不到机器人：不在 IM 可用范围内，由 IM 平台管理员在 IM 开发者后台加入。
- 员工在 IM 里收到“账号未开通提示卡”，即说明未匹配到账号或匹配到多个账号。
- 需要进一步确认时，由运维在后台投递记录中按人员查询原因（第一版管理后台不提供查询界面）。
- 处理方式：在统一用户主数据中开通或修正账号，同步后员工再次发消息即可使用。

### 4. 待研发 / 实施确认

- IM 通讯录是否也由同一主数据同步，以及工号等匹配字段落在 IM 的哪个字段（飞书 user_id、钉钉 userid 可在同步时设为工号；放在扩展字段时可能需要额外的通讯录读取权限，需补进附录 C 权限清单）。
- 是否存在不走主数据的人员（外包、临时账号）；如有，需在主数据中补录后才能使用。

## 七、消息规则（产品固定，不在后台配置）

渠道模块不提供“消息设置”页签。会话、推送、卡片相关的规则都由产品统一固定，写在本章，供研发和实施参考；管理后台不展示、不配置。**唯一例外**是消息合并等待时长：员工端要求管理员可配，放在机器人页签的【消息设置】弹窗（见第三章 6）。

### 1. 会话规则

| 规则 | 固定值 | 说明 |
|---|---|---|
| 消息合并等待时长 | 管理员配置，默认 5 秒 | 见第三章 6；连发的几条从最后一条算起等满这个时长再合成一件事处理 |
| 单聊会话切分 | 空闲 30 分钟后开启新会话 | 员工可随时发送 /new 主动开启新会话 |
| 群聊会话切分 | 平台支持话题时按话题切分；不支持话题的群按空闲 30 分钟切分 | 飞书按话题；钉钉、企业微信按空闲时长 |
| 长任务回执 | 15 秒未完成先发任务回执卡，完成后异步回帖 | — |
| 兜底提示 | 10 分钟仍未完成发进度提示 | — |

**评估结论**（原“会话默认值”配置删除）：
- **单聊会话切分**：与机器人抽屉中的配置重复；员工随时可以用 /new 开启新会话，企业没有必要统一改切分方式。
- **群聊会话切分**：取决于平台是否支持话题，属于适配层技术规则，管理员选了也可能不生效。
- **回执时长、兜底提示**：属于产品交互体验参数，由产品根据实际任务耗时统一调优，不同企业分别配置反而难以维护。

### 2. 主动推送链路

#### 2.1 推送链路

```
推送来源（产生事件） → 推送服务（找人、合并） → 渠道适配（渲染卡片） → IM 平台接口 → 投递记录（后台）
```

**推送来源**：来源模块只产出一条标准推送事件（收件人为 iWorker 用户 ID 或群 ID、类型、摘要、详情链接、是否告警），不关心发往哪个 IM。

| 来源 | 触发点 | 收件人由谁决定 |
|---|---|---|
| 定时任务结果 | 定时任务执行完成，如“每周一 9 点生成销售周报” | 固定规则：推给任务创建人本人；在群里创建的任务推到该群。任务上不提供通知对象配置 |
| 系统告警 | 连接器授权过期、任务失败、配额将满等 | 固定规则：告警涉及的员工本人或管理员 |
| 沉淀告知 | 群会话内容写入工作档案后 | 沉淀发起人 |

**推送服务**：
1. **找 IM 身份**：按身份匹配字段找到员工的 IM 账号。未匹配、已离职或停用、机器人已停用时，只发客户端和网页端站内通知，并在后台投递记录写入“已跳过”及原因；员工不在 IM 可用范围时平台会返回发送失败，同样改发站内通知。
2. **选渠道**：同时接入多个 IM 时，发到员工最近一次使用的机器人，不重复发送。
3. **推送到群**：群须在“群聊治理”列表中（未被移出），且机器人仍在群里，否则改为私信任务创建人“推送目标群不可用”。内容按固定规则的“结果可见性”处理：群里看不了的内容只提示，完整结果私信发起人。
4. **合并**：同一来源在 1 分钟内发给同一员工或同一群的多条推送，合并为一条卡片发送；告警同一内容 1 小时内只发一次。

**渠道适配与平台接口**：
- 按内置“推送卡”渲染，平台不支持卡片时降级为文本加链接。
- 发送前不检查任何后台开关，机器人正常且平台权限满足即发送。
- 以企业自建应用机器人身份主动发送：飞书按 user_id 发单聊消息或批量发送、按群 ID 发群消息；钉钉用机器人批量发送单聊消息接口、按群会话 ID 发群消息；企业微信用应用消息接口按 userid 发送。企业微信自建应用通常无法进入普通群，推送到群的能力需研发确认。
- 各平台单次人数上限、频率限制以平台文档为准；推送服务按机器人令牌桶限速（见第八章 2）。

**结果处理**：成功、失败、合并、跳过均写入后台投递记录（只记元数据）；失败按重试策略重试；员工点击推送卡“不再提醒”后，写入个人订阅偏好，该任务不再推送给此人。

#### 2.2 不提供“推送规则”配置（评估结论）

原型曾提供机器人上的“启用主动推送”开关，以及每人每日上限、企业免打扰、员工个人免打扰三项配置，评估后删除：

- **推送开关只能拦截，无法决定推给谁**：收件人已由固定规则决定（创建人 / 创建所在的群），开关关闭时唯一效果是把 IM 里建的任务结果改发站内通知，员工会以为任务没跑；群里建的任务无法用站内通知替代，等于静默失效。
- **新建默认关闭容易漏开**：上线后首批反馈多为“任务结果收不到”。
- **“推送”与“回复”在平台侧无法区分**：飞书、钉钉机器人的每条消息都是主动调用接口发送，长任务完成通知、进度提示、群里“已私信你”之后的私信是否受开关控制，需要逐条定义，研发和测试容易理解不一致。
- **与单聊不设开关的理由一致**：关掉后体验比开着更差（见第四章 4）。
- **原有诉求均有承接**：试点期用可用范围控制人群；某个任务刷屏由员工点“不再提醒”、创建人暂停或管理员在后台停用该任务；员工嫌打扰在 IM 里设会话免打扰；平台未开通发消息权限由后台自动检测发现（列表状态显示连接中断），发送失败写入后台投递记录并发站内通知；紧急止损停用机器人，如需更细粒度，由运维在系统层处理，不进入管理后台。
- **频率在来源处已经决定**：推送多不多，取决于定时任务的周期。真正刷屏时应该改任务，而不是在出口处截断。
- **每日上限会误伤重要结果**：第 21 条之后合并成摘要，员工可能漏看关键的任务结果；管理员也很难判断 20 条还是 50 条合适。
- **免打扰已有更合适的承接**：员工可以在 IM 里对机器人会话设置免打扰，飞书、钉钉、企业微信都支持；也可以在推送卡上点“不再提醒”退订某个任务。企业统一免打扰与这两者重叠，还需要额外的延迟队列。
- **系统兜底保留**：同一来源短时间内的多条推送自动合并、告警去重（见 2.1 第 4 条），不需要管理员配置。

### 3. 卡片（产品内置，不在后台配置）

卡片由 iWorker 渲染后调用平台接口发送，技术上后台改了会生效，但不开放给管理员配置：

- **卡片带交互逻辑和安全规则**：二次确认卡“仅发起人可点”、产物交付卡“签名链接绑定发起人”、授权卡的链接时效，都是安全设计的一部分。管理员改文案可能删掉关键信息（如确认卡里的操作和金额），改时效会直接影响安全。
- **三个平台都要验证**：卡片在飞书、钉钉、企业微信的渲染和降级各不相同，后台只能预览一个平台，改完无法保证三端都正常。
- **与产品升级冲突**：企业改过的文案不会随产品版本更新，后续卡片增加字段或按钮时容易错乱。
- **企业没有强需求**：员工关心的是卡片能不能用，不是措辞；品牌化诉求可以后续以“机器人名称 / 头像”在 IM 平台侧满足。
- **渠道能力矩阵同理**：它是研发的适配说明，管理员看了也无法操作，移到本文档附录。

内置卡片清单和平台降级规则见附录。

## 八、投递记录与重试频控（后台运行，无管理界面）

第一版管理后台不提供【投递日志】页签，也不提供【重试与频控】配置。系统照常记录投递过程并执行重试和限速，供运维和研发排查。

### 1. 后台投递记录

- 记录每条入站、出站消息的元数据：时间、机器人、方向、会话、事件、结果（成功 / 已降级 / 重试成功 / 已拦截 / 已跳过 / 失败及原因）、耗时。
- 不保留消息正文；正文随会话走会话权限，在“实例与会话”中查看。
- 元数据保留 180 天，由运维通过日志系统按人员、群、消息 ID 查询。
- 典型用途：员工反馈“机器人没回复”“没收到推送”时，定位是未匹配到账号、机器人被移出群、平台频控还是凭据失效。

### 2. 重试与频控（部署级配置，默认值如下）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 出站失败重试 | 指数退避，最多 3 次 | 可选最多 5 次或不重试 |
| 凭据失效期间的待发消息 | 进入重发队列，保留 24 小时 | 可选 72 小时或直接丢弃 |
| 预留余量 | 20% | 0–50%；按机器人令牌桶限速，比平台上限低该比例 |

- 以上参数属于部署级配置（见第一章 6），由实施 / 运维按客户 IM 平台的配额调整，不在管理后台展示。
- 后续版本如有客户需要自助排查，再恢复【投递日志】页签（列表、查看投递过程、导出）。

## 九、规模与性能约束

- 员工规模按 3 万人以上设计；原型示例企业 32,580 名员工，其中已分配岗位 28,750 人。
- 第一版管理后台没有人员名单类页面（可用范围名单、身份映射、投递日志均不提供），不涉及大名单加载和导出。
- 批量推送按令牌桶限速，不因单个平台频控导致其他平台积压。
- 列表查询 P90 不超过 1 秒；抽屉打开到内容可见不超过 1 秒（期间展示骨架屏）。

## 十、访问审计

机器人抽屉的“操作记录”只展示最近 5 条，完整记录在“05治理 → 访问审计 → 管理端操作”，模块为“渠道”，操作人为执行的管理员，不附版本号：

| 动作 | 记录时机 | 操作对象 | 变更内容 |
|---|---|---|---|
| 新建 | 机器人创建成功 | 机器人名称 | 渠道 · 连接方式 |
| 编辑 | 编辑保存成功 | 机器人名称 | 变更摘要，如"用途说明：— → 飞书上的统一入口"；密钥只记"App Secret 已更新"，不记内容 |
| 停用 | 停用成功 | 机器人名称 | 空 |
| 启用 | 启用成功 | 机器人名称 | 空 |
| 更换应用 | 更换应用确认成功 | 机器人名称 | "原应用标识 → 新应用标识" |
| 移出群 | 群聊治理【移出】成功 | 群名称 | 空 |
| 修改配置 | 消息设置保存成功且值有变化 | 固定"消息合并等待时长" | "原值 → 新值"，如"5 秒 → 8 秒" |

系统检测到的状态变化（连接中断、恢复正常、平台已发布）只写机器人操作记录，不进访问审计。访问审计里点【查看】跳到渠道页：机器人相关记录注入机器人名称作为搜索关键词并切到【机器人】页签；移出群记录注入群名称并切到【群聊治理】页签；修改配置记录不注入关键词。

## 十一、待决策事项

1. 员工首次在 IM 使用时，是否需要一次性确认“授权 iWorker 读取 IM 身份”。
2. 连接中断的站内通知是否同时通过其他 IM 平台的机器人发给管理员。
3. 后台投递记录的保留期是否需要按企业合规要求可配置。
4. 岗位上由管理员预置、所有持岗员工都执行的定时任务，结果推给执行任务的每位员工还是预置人；待岗位模块确认后补充到第七章 2.1。
5. 是否有客户合规要求“机器人不得主动给员工发消息”；如有，由实施 / 运维在系统层按企业关闭，不在管理后台提供开关。
6. 每个平台机器人上限大于 1 时（集团多组织、测试与正式分开），列表、身份匹配、推送选渠道如何区分同平台的多个机器人；本期上限固定为 1，数据模型先按“平台 + 组织”预留。
7. 钉钉主动推送和工作通知是否还需要 RobotCode / AgentId（需研发确认）；如需要，在平台描述配置中加为凭据字段，不改页面。
8. 企业微信自建应用是否支持群聊；结论写入平台描述配置的“是否支持群聊”。
9. **与员工端《PRD-IM对接》V5.0 的口径对齐**：员工端按员工**个人**机器人设计（员工在客户端「IM 设置」自己接飞书、钉钉、微信，写明企业机器人本版不做；会话一个机器人一条、永不切分；只支持单聊），本模块按**企业**机器人设计（管理员统一接入；单聊空闲 30 分钟切分、支持 /new；支持群聊）。需要确定本期以哪种为准，或两种并存时各自的范围。本文按企业机器人写；消息合并等待时长两种口径都适用。
10. 消息合并等待时长的取值范围（暂按 1–30 秒整数）与下发字段；客户端、网页端读取失败时是否按 5 秒兜底（研发确认）。
