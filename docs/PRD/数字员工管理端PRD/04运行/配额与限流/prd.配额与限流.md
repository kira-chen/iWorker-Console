## 一、业务背景说明

### 1. 功能定位

本页放平台级的运行参数：对全部员工统一生效、不按岗位或员工单独设置的数值。本期只有一项「IM 消息处理 · 消息合并等待时长」，其余配额与限流项后续再补。

在 04运行 下的职责边界：运行规格回答"按什么标准运行"，实例管理回答"当前运行得怎么样"，存储空间回答"员工的产物空间配了多少"，**配额与限流回答"平台统一的运行参数是多少"**。

### 2. 消息合并等待时长是什么（与员工端一致，不得自行扩展）

员工可以把自己的飞书、钉钉、微信机器人接到数字员工，在 IM 单聊里发消息派任务。员工常常连着发几条（先发文件、再补一句要求），系统收到消息后先等一段时间，**从最后一条算起**，期间连着发来的几条合成一件事处理，等待结束才回「收到」并开始做。

- 等待时长由本页配置，默认 5 秒。
- 时长越长，连发的消息越不容易被拆成两件事，但员工收到「收到」也越晚。
- 对全部员工的全部机器人（飞书、钉钉、微信）生效，客户端和网页端都按这个值执行。
- 不按岗位、员工、机器人单独设置。

员工端 IM PRD 里另有几个暂定数字：做满 3 分钟补一次「还在做」、等确认超过 30 分钟放弃、各平台文件大小上限。这些**不在本页配置**，按员工端口径执行。

### 3. 业务角色

- **平台管理员**：查看、修改消息合并等待时长。
- **员工**：不感知配置本身，只感知连发几条后多久收到「收到」。

## 二、页面结构

- **页面入口**：侧边栏"04 运行 / 配额与限流"。
- **页面标题**：配额与限流。
- **页面说明**：平台统一的运行参数，保存后对全部员工生效。
- 页面主体为一张设置卡片「IM 消息处理」，本期只有一个字段。

## 三、IM 消息处理

### 1. 消息合并等待时长

| 项 | 规则 |
|---|---|
| 字段名 | 消息合并等待时长 |
| 必填 | 是 |
| 输入 | 输入框，后缀"秒"；只接受 1–30 的整数 |
| 默认值 | 5（出厂值；页面展示的是当前已保存的值） |
| 说明文案 | 字段下方灰字："员工在 IM 里连着发的几条消息，从最后一条算起等这么久，期间发来的合成一件事处理。时长越长，员工收到「收到」越晚。" |
| 校验 | 清空时提示"请填写消息合并等待时长"；不是整数（含小数、非数字）或不在 1–30 之间时提示"请填写 1–30 之间的整数"。校验在点【保存】时触发，提示展示在输入框下方，不自动取整、不自动拉回范围 |

### 2. 保存

- 卡片右下【保存】。输入值与当前已保存的值相同时置灰（含输入"05"这类与已保存值数值相等的写法）。
- 点击后按钮进入加载态；校验不通过时不提交。
- 保存成功提示"已保存，对全部员工的 IM 机器人生效"，页面展示的已保存值随之更新。
- 保存失败（网络等原因）提示失败原因，输入框保留管理员填写的值，可再次保存。
- 不走审核，不生成版本。

### 3. 生效规则

- 保存后立即对全部员工、全部机器人生效，客户端和网页端下一次判断合并时按新值执行。
- 保存那一刻**已经在等待合并的消息，按保存前的值走完**；之后收到的消息按新值等待。

### 4. 页面状态

- **加载中**：卡片区域展示加载态，【保存】不可点。
- **读取失败**：卡片区域展示"配置读取失败"与【重试】，不展示可编辑的输入框（避免在不知道当前值的情况下覆盖）。

## 四、访问审计

保存成功且值有变化时，写一条访问审计「管理端操作」记录（见《prd.访问审计.md》§6.2）：

| 项 | 内容 |
|---|---|
| 模块 | 配额与限流 |
| 动作 | 修改配置 |
| 操作对象 | 固定"消息合并等待时长" |
| 变更内容 | "原值 → 新值"，如"5 秒 → 8 秒" |
| 操作人 | 执行保存的管理员 |

访问审计里点【查看】跳到本页，不注入搜索关键词（本页没有列表）。

## 五、与员工端的衔接

| 员工端用途 | 管理端字段 | 备注 |
|---|---|---|
| IM 消息合并窗口 | 消息合并等待时长（秒） | 客户端、网页端都读；读取接口与字段名待研发确认 |

- 客户端、网页端读取失败时按 5 秒执行（待研发确认）。

## 六、不做什么

- ❌ 按岗位、员工、机器人单独设置等待时长。
- ❌ 在本页配置「还在做」提醒时点、等确认时长、文件大小上限。
- ❌ 在本页管理员工的 IM 机器人绑定（绑定由员工在客户端「IM 设置」里自己完成）。
- ❌ 修改记录列表：改动历史以访问审计「管理端操作」为准。
