# 专家团产品需求

> 本文是管理端「专家团」的配置、发布与下线规则，对应客户端《PRD-专家团》（V4.0）§7「管理后台」一节。专家团的运行机制（有无团长两条路、过程展示、收口与交付）是客户端与云端的事，本文只写**管理员怎么建团、怎么发、怎么收回**，以及哪些字段会被客户端消费。
>
> 专家团与专家同属「专家」页，**发布、审核、版本、停用、强制回收的流程全部沿用《prd.专家.md》**，下文只写差异；与专家完全相同的规则以引用方式给出，不重复。

## 零、模块口径

1. **一个团 = 一组已发布的专家 + 可选的团长。**成员只能是已发布的专家；技能、连接器不是团员，团本身也不引用技能（所以发布不要求"至少引用 1 个市场技能"）。
2. **团类型与专家类型对齐**：岗位团 / 市场团 / 通用团，创建后不可更改。三类团的下发方式与专家一致——岗位团随岗位下发，市场团上架市场供员工召唤，通用团对全员开放。
3. **有无团长是唯一影响执行路径的结构**：设了团长，拆解、分发、把关、汇总都交给团长这位专家，员工无需确认安排；没设团长，由系统按「团队协作关系」拆解，员工确认安排后开始。管理员在这里决定走哪条路。
4. **三段文字是执行时的提示词来源，不是介绍**：团长职责（仅有团长时）、团队协作关系、成员的"团内负责什么"。写得越具体，拆得越准。**团介绍与示例问题是给员工看的，不进提示词。**
5. 专家定义只有一份。专家在专家页更新后，引用它的团同时生效；团只给成员加一层"在这个团里负责什么"，不改专家本身。

## 一、导航栏

### 1. 功能说明

专家页页头下方增加页签：**「专家 | 专家团」**（样式同工具调用审计页签），默认「专家」。与客户端专家页的切换同构；左侧导航不新增入口，专家团沿用专家页的页面权限，无权限的账号两个视图都不可见。

- **页面标题**：展示"专家"；切到专家团后页面说明改为"平台全部专家团 —— 通用团 / 岗位团 / 市场团 统一管理"。
- **搜索框**：占位"搜索团名、介绍或分类"，支持按团名、团介绍或分类搜索。
- **团类型筛选**：默认"全部团类型"，可选"岗位团、市场团、通用团"。
- **团分类筛选**：默认"全部分类"，选项与专家分类相同，由 05 治理 / 字段字典「专家」分组下的"专家分类"统一维护。
- **状态筛选**：默认"全部状态"，可选"未发布、审核中、已发布"。
- **查询按钮**：按当前搜索内容和筛选条件刷新列表。
- **新建入口**：右侧展示【＋ 新建专家团】，从页面右侧打开专家团编辑抽屉的新建状态；切回「专家」视图时恢复为【＋ 新建专家】。

### 2. 交互规则

- 搜索与三个筛选可组合；点击【查询】或在搜索框按回车后刷新，清空搜索后按剩余条件刷新；切换筛选项后列表立即刷新。
- 「专家 / 专家团」两个视图的搜索与筛选条件各自独立保存，来回切换不互相清空。
- 点击【＋ 新建专家团】保留列表当前筛选条件；关闭编辑抽屉或版本管理侧栏后返回原列表位置。

### 3. 页面状态与异常场景

- **加载中**：列表区域展示加载状态。
- **首次暂无数据 / 无查询结果**：统一展示"还没有专家团，点击「新建专家团」创建第一个"，无查询结果时保留搜索与筛选条件。
- **加载失败**：展示"加载失败"和【重试】。

## 二、专家团列表

### 1. 列表展示

列表支持分页，每页条数按窗口高度动态计算，与平台其余列表页同一套分页策略。

- **团名**：图标 + 团名称（专家团没有背景色字段，图标用默认底色）。
- **状态**：独立列，标签【未发布】【审核中】或【已发布】，紧跟团名列。已发布且存在**缺员**时，在状态标签旁追加红色小标签"缺员 N"（N 为不可用成员数），悬停列出成员名及原因（已停用 / 已回收 / 已删除），口径见 §四。
- **团介绍**：超长缩略，悬停查看完整内容。
- **团类型**：岗位团 / 市场团 / 通用团，普通文本样式。
- **分类**：所属专家分类（所有团都有）。
- **成员**：成员图标叠放（最多 5 个，超出显示"+N"）加"N 位成员"文字；悬停展示成员名单。
- **团长**：团长的专家名；未设团长展示"未设团长"（灰色）。
- **引用情况**：岗位团展示"N 个岗位引用"（N 为所属岗位数），点击弹出岗位清单；未绑定岗位展示"暂无引用"；市场团、通用团显示"—"。
- **最新版本**：最近一次审核通过并正式发布的版本号；尚无版本显示"—"；不展示待审核版本号。
- **最近更新时间**：最近一次保存的时间，精确到分钟；支持点击列头排序。
- **操作**：按状态动态展示【查看】【编辑】【发布】【撤回】【停用】【强制回收】【版本管理】【删除】。

### 2. 排序规则

默认按最近更新时间由近到远排列，点击列头切换升降序；保存配置、提交审核或撤回提交后，按新的最近更新时间重新排列。

### 3. 操作

#### 3.1 操作按钮展示规则

列表只展示"未发布、审核中、已发布"三态，不设"草稿"。

| 状态 | 固定按钮 | 状态按钮 |
| --- | --- | --- |
| 未发布 | 【查看】【编辑】 | 【发布】【删除】 |
| 审核中 | 【查看】【编辑】（置灰） | 【撤回】 |
| 已发布 | 【查看】【编辑】 | 【停用】【强制回收】【版本管理】 |

审核中【编辑】置灰并提示"审核中不可编辑"。

#### 3.2 查看 / 编辑

- 【查看】从右侧打开只读抽屉，展示全部信息与时间信息，底部仅【关闭】。
- 【编辑】从右侧打开编辑抽屉并回填；未发布和已发布（无审核中操作）可编辑。

#### 3.3 发布

- 【发布】用于"未发布"的团，点击后先做发布前检查（§三.8），通过后打开版本管理侧栏，与编辑抽屉内【发布】同一流程；从编辑抽屉点击时抽屉先自动收回，页面同一时间只保留一个右侧抽屉。
- 检查未通过时不打开侧栏，按 §三.8 提示具体原因。
- 侧栏内填升级说明（必填），点击【提交发布 v1.0.0】后状态变为"审核中"，配置锁定；通过后变为"已发布"并生成 v1.0.0 快照；拒绝或撤回回到"未发布"。详见 §五。

#### 3.4 撤回

规则同《prd.专家.md》§二.3.4：仅"审核中"展示；确认窗口"「团名」当前处于审核中。撤回后回到修改前状态。"；待审发布撤回后，首次发布回"未发布"，已有版本号的新版本发布回"已发布"（已停用 / 已强制回收后重新提交发布再撤回，回"未发布"）；待审停用撤回维持"已发布"；撤回时清理 `pendingAction`、`pendingVersion`、`pendingReleaseNotes`；成功提示"审核申请已撤回"。

#### 3.5 停用

- 【停用】在"已发布"且无审核中操作时展示。确认窗口"停用「团名」需提交审核。审核通过前客户端仍可使用。"，按钮【提交停用审核】。
- 确认后状态变为"审核中"；通过后团变为"未发布"，停止向员工开放；拒绝或撤回恢复"已发布"。
- 停用不影响成员专家，也不受引用拦截。

#### 3.6 强制回收

用于安全风险、团异常等紧急处置，与【停用】并列；正常退役仍走【停用】。规则与《prd.专家.md》§二.3.5.1 一致，差异如下：

- **回收弹窗**：标题"强制回收专家团"；红色警示"强制回收立即生效且不可撤销：已召唤该专家团的员工将立即失去它，委派对象为该团的自动化将被挂起。成员专家不受影响。正常退役请使用【停用】"。其余（回收原因必填、最多 500 字、占位、两次确认、成功提示"已强制回收"）同专家。
- **回收后**：状态变为"未发布"，版本快照与最近发布时间保留；列表状态列追加红色小标签"已回收"，悬停展示原因、操作人和时间；编辑 / 查看抽屉顶部红色提示条"该专家团已于 {时间} 被强制回收：{原因}"。
- **审计**：写入访问审计"管理端操作"（模块=专家团，动作=强制回收，变更内容=回收原因），客户端据此移除团并挂起相关自动化；管理端不推送通知（客户端所需字段见"八、与其他模块的衔接"）。
- **恢复**：重新走【发布】审核，通过后回到"已发布"、"已回收"标记清除；此前被回收的员工不会自动恢复，需重新召唤。
- **异常**：状态已变化提示"专家团状态已变化，请刷新后重试"；重复点击展示进行中状态，不重复提交。

#### 3.7 版本管理

【版本管理】在"已发布"且无审核中操作时展示，打开版本管理侧栏，详见 §五。

#### 3.8 删除

- 仅"未发布"且无审核中操作时展示。二次确认"删除「团名」后会解除 N 位成员专家的引用，专家本体不受影响。确认删除？"，按钮【删除】用危险样式。
- 删除成功提示"专家团已删除"，从列表移除。
- 已回收或已停用的团（状态为"未发布"）可以删除；删除不删除员工已有的任务记录。

### 4. 状态规则

与专家一致：

- **未发布**：不对员工开放；允许编辑、发布、删除。
- **审核中**：配置锁定，仅允许查看和撤回。
- **已发布**：已向员工开放；允许编辑、提交新版本、提交停用、强制回收。
- 首次发布审核通过后"已发布"；新版审核期间当前版本继续可用，通过后新版本生效；停用审核通过后回到"未发布"。

### 5. 列表异常场景

- **发布前检查未通过**：不打开侧栏，提示具体原因（见 §三.8）。
- **审核中编辑**：【编辑】置灰，查看抽屉为只读。
- **审核中删除或停用**：按钮隐藏；**已发布删除**：【删除】隐藏，需先完成停用审核。
- **操作进行中**：按钮展示进行中状态，不重复提交。
- **单项操作失败**：保留当前团和原状态，提示具体原因。

## 三、专家团编辑页

### 1. 页面状态

专家团编辑页为右侧抽屉，宽度与专家编辑抽屉一致，包含"新建、编辑、查看（只读）"三种状态。

- **新建**：标题"新建专家团"，内容为空，底部【取消】【创建专家团】。
- **编辑**：标题"编辑专家团"，回填已保存内容，底部【取消】【发布】【保存】。
- **查看**：标题"查看专家团"，全部只读，底部仅【关闭】。
- 抽屉顶部说明："专家团由多位已发布的专家组成。专家保持引用关系，专家更新后团同步使用最新内容。"
- 点击抽屉外区域不关闭；点击右上角关闭或【取消】退出，未保存修改不保留。

抽屉自上而下分五个区块：基本信息 → 团队成员与团长 → 团队协作关系 → 团队帮你做（示例问题）→ 时间信息。

### 2. 基本信息

- **团类型**：必选，**分段选择**"岗位团 / 市场团 / 通用团"（放在最前），下方提示"团类型建成后不可更改。"；新建必选，编辑时置灰。**团类型决定团员的候选范围（见 §三.3），因此未选团类型时，成员区块置灰并提示"请先选择团类型"；它同时决定下面的分类与所属岗位是否出现。**
- **团名称**：必填，最多 64 字符，占位"如 合同会审团"；未填提示"请填写团名称"。**同名校验**：管理端创建的全部专家团（不分类型）不可重名，保存时校验，命中时字段标红提示"团名称已存在"；与专家重名、与客户端员工自建团重名均允许。
- **分类**：必选，取"专家分类"；仅用于客户端「专家团 · 市场」的分类筛选条（带计数），不在团卡片和详情上展示。未选提示"请选择专家分类"。
- **所属岗位**：仅团类型为"岗位私有"时展示，多选已发布岗位，一个团可绑定多个岗位；未选显示"未绑定岗位"（不强制）。绑定后该团随岗位下发给该岗位员工，卸任即回收。所属岗位可在编辑时增减（审核中锁定期间不可改）。
- **图标**：必填，规则同《prd.专家.md》§三.2 图标统一规则。**专家团没有背景色字段**，图标使用默认底色。
- **团介绍**：必填，最多 2000 字符，占位"介绍这个团能解决什么问题（不用写怎么协作）"；用于客户端团卡片（缩略为一句）与团详情，**不进提示词**。右上角【AI 生成】，按钮规则见 §三.7。成员首次凑满 2 位且团介绍为空时，自动填入一版（等同点击一次【AI 生成】），之后成员再变不自动覆盖（客户端 PRD §7 第 3 条：默认按成员能力汇总生成，可改）。

> 团介绍只讲能力，不讲协作方式（客户端 2026-09-28 决策：不露协作方式标签）。

### 3. 团队成员与团长

#### 3.1 选成员

- 区块上方展示候选区：搜索框（按专家名、简介、分类）、专家分类筛选条（带计数）、专家卡片三列点选，点击打勾加入、再点取消；卡片展示图标、专家名、分类、一句简介，右下角标专家类型，**带「可带团」标记的专家加徽章**（见 §三.3.2 和《prd.专家.md》「带团分工说明」）。
- **候选范围 = 已发布的专家，且按团类型限定**：

| 团类型 | 候选专家 | 原因 |
| --- | --- | --- |
| 通用团 | 通用专家、市场专家 | 团下发或召唤时，缺的市场专家随团一起进"我的专家" |
| 市场团 | 通用专家、市场专家 | 员工召唤团时，缺的市场专家随团一起进"我的专家" |
| 岗位团 | 通用专家、市场专家、岗位私有专家 | 随岗位下发，缺的市场专家随团进员工的"我的专家"；岗位私有专家须绑定了本团的**全部**所属岗位（见 §三.8 检查），否则该岗位员工拿不到它 |

- 草稿、审核中未上架、已停用、已回收的专家不进候选。没有任何可选专家时候选区显示"没有可选的已发布专家"。
- 已选列表展示"N/20"，**顺序即团内排位**（用于客户端展示排序，以及没设团长时系统拆解的先后参考），可上下调整、可移除；至少 2 位、上限 20 位。
- 已选行展示：专家图标与名称、**团内负责什么**（必填输入，最多 200 字符，占位"这位专家在团里负责什么，如：条款风险与合规口径"）、【设为团长】开关、【移除】。
- **团内负责什么**由管理员写，客户端团详情逐行展示，执行时与专家人设一起交给该成员；客户端员工自建团不写这一格（系统拿专家分类顶替），管理端必须写。

#### 3.2 定团长

- 已选成员行内点【设为团长】选一位，再点取消；**可选，最多一位，团长只能是已选成员**。区块说明："设了团长，由团长按其专业口径拆解、分发、把关、汇总，员工无需确认安排；不设团长，由系统按「团队协作关系」拆解，员工确认安排后开始。"
- 成员被移除时，若其为团长，团长随之清空（团长职责区隐藏，已填内容保留在草稿中、不丢失，重新设团长时回填）。
- 团长候选展示顺序：带「可带团」标记的专家优先，其余按成员排位。

#### 3.3 团长职责

- 设了团长才出现，紧跟团长所在行下方；**必填**，最多 2000 字符，占位"描述这个团按团长的口径怎么拆、怎么分，谁先谁后"。
- 设团长时，若职责为空：团长专家填有「当团长时怎么分工」（《prd.专家.md》「带团分工说明」）则自动回填该段；没有则留空，等管理员填写或点【AI 生成】。
- 运行时，团长职责与团长专家本身的人设、团的协作关系、成员清单拼在一起交给团长；**以专家人设为底，团长职责只定分工口径**，两者冲突时人设优先（与客户端 §8 第 9 条现行假设一致）。
- 右上角【AI 生成】，规则见 §三.7。

### 4. 团队协作关系

- **团的用途**：选填，最多 200 字符，占位"一句话说明这个团用来干什么，如：把一份合同从法律、税务、履约三个角度一起看一遍"；不填则按成员专业自动写一句。**拆解依据之一，员工端不展示**：有团长时和团长职责一起给团长，没团长时系统靠"用途 + 团队协作关系 + 任务本身 + 成员专业"来拆（客户端 PRD §2.1 / §2.3）。
- **团队协作关系**：描述任务到了这个团后怎么分工、谁先谁后、谁要看谁的结果。**拆解依据，不是介绍，员工端不展示。**设了团长时进团长提示词；没设团长时系统完全照这段拆。
- **没设团长：必填；设了团长：选填**。最多 2000 字符，占位"任务到了这个团后怎么分工？谁先谁后，谁要看谁的结果？如：先由法律专家看条款风险，税务专家同时看付款与发票，两边都出结论后供应链专家再核对履约可行性"。未填且未设团长时提示"请填写团队协作关系"。
- 右上角【AI 生成】，按已选成员的人设写，规则见 §三.7。
- **【试跑拆解】**（见 §三.9）放在本区块标题右侧，没设团长的团发布前建议先试跑。

### 5. 团队帮你做（示例问题）

- 必填，固定 3 条输入行，每条最多 300 字符；对应客户端团详情「团队帮你做」，员工点击后带着团回到首页输入框。
- 区块标题右侧【AI 生成】，一次生成 3 条全部填入，重复点击覆盖当前内容；团名称或团介绍为空时置灰，悬停"请先填写团名称和团介绍"。

### 6. 时间信息

编辑和查看状态底部展示：创建时间、最近更新时间、最近发布时间、最新版本，均只读；新建状态不展示。

### 7. AI 生成按钮（统一规则）

沿用平台统一规则（见《各模块必填选填字段一览表》「AI 生成按钮样式与交互」与《AI生成按钮Prompt规范》）：常规字重不加粗；静态文案「AI 生成」，生成中「生成中…」；生成耗时 500ms；来源字段不足时置灰并悬停提示；只读态置灰；失败或返回为空时回落到字段名拼的模板句并提示"已用默认模板，可自行修改"。本模块四处：

| 位置 | 生成内容 | 置灰条件（悬停提示） |
| --- | --- | --- |
| 团介绍 | 一段介绍团能做什么的文字 | 成员不足 2 位（"请先选择至少 2 位成员"） |
| 团长职责 | 按团长专家的专长写分工口径 | 未设团长时区块不出现 |
| 团队协作关系 | 分工、先后、依赖 | 成员不足 2 位（同上） |

### 8. 保存、发布前检查与关闭

**保存**（【创建专家团】/【保存】）校验：团类型、团名称、分类、图标、团介绍、示例问题 3 条必填；成员 2～20 位且每位"团内负责什么"已填；设了团长时团长职责必填；没设团长时团队协作关系必填。示例问题未全填单独提示"请填写 3 条"团队帮你做"示例问题"并聚焦首个空行；成员不足时成员区块标红提示"至少 2 位成员"；其余未通过时对应区域标红并提示"请先补齐必填项"。

- 【保存】只保存当前配置，不生成快照、不改最新版本号、不自动提交审核。
- 创建成功提示"专家团已创建"，保存成功提示"专家团配置已保存"，关闭抽屉并刷新列表；保存期间按钮展示进行中状态；失败时抽屉保持打开、保留填写内容并提示原因。
- 编辑状态底部【发布】：先自动保存（不提示），再做发布前检查，通过后打开版本管理侧栏；新建状态不展示【发布】。

**发布前检查**（【发布】点击后、打开侧栏前，任一未通过则阻断并提示，不保存不打开侧栏的规则同专家）：

| # | 检查项 | 提示 |
| --- | --- | --- |
| 1 | 保存校验的全部必填项 | 同保存 |
| 2 | 每位成员均为**已发布**状态（未被停用、强制回收、删除） | "成员「专家名」已停用 / 已回收 / 已删除，请移除或替换后再发布" |
| 3 | 岗位团：岗位私有成员须绑定了本团全部所属岗位（团未绑定岗位则不检查） | "成员「专家名」未绑定岗位「岗位名」，该岗位员工将无法使用，请调整" |
| 4 | **没设团长且自最近一次修改成员、团长或协作关系后未试跑过** | 不阻断，仅提醒：弹窗"「团名」没设团长，拆解质量完全取决于「团队协作关系」。建议先试跑一次。"，按钮【去试跑】（回到编辑抽屉并滚到试跑入口）【直接发布】 |

### 9. 试跑拆解

没设团长的团，拆解质量全靠协作关系这段文字，管理员发布前需要一个"看一眼系统会怎么拆"的手段。

- 入口：协作关系区块标题右侧【试跑拆解】；成员不足 2 位或（没设团长时）协作关系为空时置灰，悬停说明原因。设了团长的团也可以试跑，口径一致。
- 点击弹窗：输入"试跑任务描述"（最多 300 字符，默认预填第 1 条示例问题，可改，不可为空）→【开始试跑】。
- 试跑结果展示**安排预览**：一行一位成员，列出"负责什么 · 先后（先做 / 同时 / 等谁完成后）"，口径与客户端「安排卡」一致；设了团长的团顶部标"由团长 X 按其职责拆解"，没设团长的标"由系统按团队协作关系拆解"。
- 弹窗底部固定说明："仅为拆解预览，不会真正执行，不产生任务记录。"
- 失败提示"试跑失败，请稍后重试"，加载中按钮展示进行中状态。
- 试跑成功后记录"已试跑"状态；成员、团长、团长职责或协作关系任一被修改后清除。该状态仅用于发布前检查第 4 项的提醒，不进版本快照。

### 10. 查看态

全部字段只读：成员区块不展示候选区，仅展示已选列表（含团内负责什么、团长徽章）；【AI 生成】【试跑拆解】置灰；已强制回收的团顶部展示红色提示条。

## 四、与专家的联动

团引用的是专家，专家状态变化会影响团。以下规则同步写入《prd.专家.md》。

| 专家侧操作 | 对团的影响 |
| --- | --- |
| 专家**更新并发布新版本** | 引用它的团同时使用新版本，团不需要重新发布 |
| 专家**停用**（审核通过后） | 不拦截。停用确认窗口追加提示"该专家被 N 个专家团引用（点击查看清单），停用后这些团在客户端将标「缺员」"；团在管理端列表显示"缺员 N"；该团的下次发布被检查 2 阻断 |
| 专家**强制回收** | 不拦截。回收弹窗的影响范围追加"已被 N 个专家团引用"；团引用关系保持不动，团成员行改红色"已回收"标签（悬停展示原因）；团列表显示"缺员 N"；管理员事后手动在团里移除 / 替换 |
| 专家**删除**（仅未发布专家可删） | **拦截**：被专家团引用时不删，提示"该专家被 N 个专家团引用（引用清单），需先从团中移除后再删除" |
| 岗位私有专家**减少所属岗位** | 不拦截；若该岗位下的岗位团引用了它，团下次发布被检查 3 阻断 |
| 岗位被**卸任 / 删除** | 岗位团随岗位回收（客户端口径），不属缺员 |

> **缺员**只是管理端的提示，团的发布状态不因缺员自动改变；客户端对缺员团标"缺员"并禁止发起任务，详情指出缺谁（客户端 PRD §4.1 功能点 6）。管理员处理方式：替换成员后重新提交发布，或停用 / 强制回收该团。

## 五、版本管理侧栏

沿用《prd.专家.md》§四：列表页【发布】/【版本管理】与编辑页【发布】进入同一个侧栏，同一版本表单、校验与提交逻辑；首次发布固定预生成 v1.0.0；非首次支持修订 / 功能 / 重大更新，版本号自动预生成不可改；升级说明必填（最多 2000 字，显示字数）；提交后只创建待审核版本 `pendingVersion`，状态"审核中"，编辑抽屉锁定，线上版本继续生效；审核通过才生成不可变快照、写入版本历史并设为唯一启用版本；拒绝 / 撤回不生成快照；审核中展示"审核中，已锁定不可修改。可撤回本次提交后继续编辑"及【撤回提交】；版本历史支持启用 / 禁用，最后一个启用版本不可禁用（提示"当前版本是该专家团最后一个启用版本。如需停止对外提供，请先整体下架专家团"）。

差异：

- **提交前提**不再是"至少引用 1 个市场技能"，改为 §三.8 的发布前检查。
- **版本快照内容** = 团的全部配置：团名称、团类型、所属岗位、图标、分类、团介绍、用途、成员（专家 id、顺序、团内负责什么）、团长、团长职责、团队协作关系、示例问题。**快照只存对专家的引用（专家 id），不复制专家内容**，专家的更新随引用自动生效。"已试跑"状态不进快照。
- 提交发布、停用、版本启用 / 禁用均写入访问审计（模块=专家团，操作对象名称右侧附版本号小标签，变更内容记升级说明）。

3. **专家停用不拦截**：沿用客户端"缺员"口径，停用只提示不拦截；专家删除则拦截。若希望与技能一致（被引用即不可停用），需改 §四。
4. **客户端 §7 第 4 条"引导提示与开场"**：其中"开场"客户端没有单独定义，本文按团介绍处理，未另设字段。
5. **试跑拆解**为预览，不执行、不记任务；是否需要保留试跑历史由研发评估。
6. **缺员判定**在管理端为实时计算（成员状态非"已发布"即缺员），不落库。
