> 首次编写日期：2026-10-13
> 参考基线：员工端《PRD-访问权限》V4.0（2026-10-13）、`04运行/存储空间`（同类「按人配置 + 员工申请 + 管理员处理」范式）、`05治理/访问审计` §6.5

> **本仓交付边界**：管理端页面与浏览器本地 mock 用于完整表达「完全访问」授权与申请处理的产品交互并供研发参考，不代表授权同步、申请流转后端已实现。员工清单与用户模块、岗位分配真联动；演示环境恒为管理员身份，菜单与地址都不做权限拦截（全站通病，非本模块特有）。

## 一、业务背景说明

### 1. 功能定位

员工端输入框工具条上有一颗「访问权限」，员工可以开启「完全访问」，让数字员工处理任务时不再逐步征求同意、直接操作所在运行环境（本机或云端）。这是一项放大风险的能力，**不是人人默认都有，由管理端按人授权**：有权限的员工自行开关，没有权限的员工点开会被拦住，只能向管理员提交申请，审批结果通过员工端通知送达。

本页面是这条链路的管理端一侧，只做两件事：

- **授权名单**：一位员工一行，查看他在本机、云端两个运行环境下是否拥有完全访问权限；在弹窗里勾选授权给本机、云端或两者，或收回已授予的权限，也可以批量授权。
- **处理权限申请**：员工提交的申请也在授权名单里处理（通过 / 驳回并说明原因），**不占单独页签**——工具栏有「待处理申请」按钮，行上有【处理申请】，同岗位管理处理「待分配申请」的范式。

在 06组织 下的职责边界：用户回答"有哪些员工账号"，角色回答"能进管理端的哪些功能"，**用户访问权限回答"员工能不能放开数字员工对自己运行环境的每步确认"**。它管的是员工端能力，与管理端角色权限互不相干。

### 2. 权限口径（与员工端一致，不得自行扩展）

- 权限只有**有 / 没有**两态，不分档：不按操作类型拆开授权。
- **完全访问放开的权限范围**：与员工端开启确认框同一组 **4 项**（员工端已确认，名称与说明沿用员工端），共同覆盖客户端 agent 执行中原本要弹窗二次确认的全部场景（附录第一节 #1–#5，不漏）：
  - **读写文件**（读取、新建、修改、删除员工的文件和文件夹）：原本弹窗的是**删除文件 / 目录**，删除后无法恢复（附录 #1）；
  - **执行命令**（运行命令、安装依赖、更改运行环境）：原本弹窗的是**危险命令 / 脚本**，如递归删除、写系统或敏感路径、`curl | sh`、`chmod 777`（附录 #2）；
  - **操作业务系统**（替员工在业务系统里提交、保存、发布、审批等操作）：原本弹窗的是**浏览器提交类点击**与**SOP 回放提交步**，数据会真实写入业务系统（附录 #3、#4）；
  - **联网与连接器**（访问网站、通过已启用的连接器读写外部系统数据）：原本弹窗的是**连接器 API 对外写操作**，对外生效（附录 #5）。
  - 员工开启后，上面列出的弹窗场景不再逐次弹「确认执行操作」；每项里其余操作（如读取、新建文件）本来就不弹窗，不受授权影响。毁灭级命令、`sudo -S` 猜密码、命中管理规则（`approvals.deny`）的命令始终被客户端直接拦截（被拦截的会在「操作记录」里记一条「已拦截」，见第四之二节），员工自己发起的删除 / 卸载确认也照常。**管理端页面顶部（默认折叠的「完全访问权限口径」，展开可看每项下原本会弹窗的具体场景）和授权弹窗里都要把这个范围标注清楚**，让管理员授权前知道放开的是什么。
- **按运行环境授权**：数字员工有本机（客户端）和云端两个运行环境，员工端两个环境各开各的，所以管理端也**各授权各的**——可以只授权本机、只授权云端，或两个都授权。授权了某个环境，员工才有资格在该环境的运行方式下开启完全访问；开不开，由员工自己在员工端决定。
- **开关本身的开 / 关状态只存员工本机，不上传**，管理端看不到、不展示"当前是否已开启"。管理端只管"有没有资格"。
- 权限一经授予**长期有效，直到管理员收回**，没有有效期。
- **默认没有**：所有员工账号（含新建账号）初始都是「未授权」。
- 权限只影响数字员工对运行环境的操作，不改变知识红线、代答红线等其他权限。

### 3. 业务角色

- **平台管理员**：授权 / 收回，处理员工的权限申请。
- **员工**：在员工端提交申请、开关完全访问；处理结果经通知模块送达，本页不发通知，只产生访问审计记录供员工端读取。

### 4. 员工的权限状态

状态按（员工 × 运行环境）各算各的，一位员工有两份（本机一份、云端一份）。**管理端授权状态只有两态：已授权、未授权**，没有「审核中」这类中间状态：

| 状态 | 含义 | 员工端表现（在该环境的运行方式下） |
|---|---|---|
| 未授权 | 该环境没有权限 | 开关灰着，提示"你没有完全访问权限，去申请"；已提交申请且未处理时，员工端提示"完全访问权限申请中，等管理员审批"，开关点不动 |
| 已授权 | 该环境由管理员授予或申请已通过 | 开关可用，按员工端流程开启 |

**有待处理申请不是一个授权状态**，只是未授权环境上的一个标记：授权名单里该环境显示「未授权」，旁边加一个橙色「待处理」小标签（同岗位管理「未绑定」旁的「待分配」）。员工端自己的面板在这种情况下显示「申请中」，管理端不另起状态名，免得被误解成走了审核中心。

状态切换规则（每个环境各自独立）：

- 未授权 →（员工在该环境提交申请）→ 仍是未授权，但带「待处理」标记 →（通过）→ 已授权；（驳回）→ 未授权，标记消失，员工可再次申请，**驳回不是永久封掉，没有冷却期**。
- 未授权 →（管理员授权）→ 已授权；已授权 →（管理员收回）→ 未授权，员工可再次申请。
- 某环境**有待处理申请的，不能被直接授权或收回该环境**，只能经【处理申请】的通过 / 驳回改变（与存储空间"有待处理申请的员工不能直接调整"同一思路：一条申请只有一条处理路径，不出现"申请还挂着、权限已被改"的状态）。同一位员工另一个环境不受影响，仍可授权。
- 一位员工在同一个环境同一时间最多一条「待处理」申请（员工端已拦截重复提交）；本机、云端可以各有一条。

## 二、页面结构与导航栏

- **页面标题**：「用户访问权限」。
- **页面说明**：「管理员工能否开启「完全访问」，让数字员工直接操作运行环境、不再逐步确认；处理员工提交的权限申请」。
- **页签**：【授权名单】【操作记录】两个。权限申请不再单独占页签：授权名单工具栏的「待处理申请」按钮显示待处理数徽标，为 0 不显示。
- 菜单位置：06组织 下，排在「用户」「角色」之后。
- 切换页签**不保留**搜索、筛选、页码，每次切回都是该页签的默认状态（授权名单：无筛选；操作记录：默认时间范围、无其他筛选）。例外是跳转带入的条件：授权名单中有授权的员工的【查看】带员工用户名进操作记录页签（两个环境的记录都能看到）；访问审计【查看】——授权 / 收回 / 通过申请 / 驳回申请四类记录都带员工用户名进授权名单页签；驾驶舱待办【去处理】进授权名单并直接打开「待处理申请」筛选（只看有待处理申请的员工）。仅首次进入时生效，离开页签后作废。

## 三、授权名单页签

**一位员工一行**（不按运行环境拆成两行：同时授权本机和云端不用搜两次），本机、云端的授权状态在行内各占一列。

### 1. 搜索与筛选

- 搜索框：占位「搜索用户名或显示名」，忽略前后空格，支持部分匹配。
- 运行环境筛选：全部运行环境 / 本机 / 云端。
- 状态筛选：全部状态 / 已授权 / 未授权。**没选运行环境 = 任一环境是该状态的员工**（如「已授权」列出本机或云端至少有一个已授权的员工）；**选了运行环境 = 只看该环境的状态**（如「云端 + 已授权」只列云端已授权的员工）。要找有待处理申请的员工，用旁边的「待处理申请」按钮。
- **待处理申请**按钮（在【查询】左边，样式同岗位管理的「待分配申请」）：带待处理申请总数的橙色徽标（0 不显示）；点击后只看**任一环境有待处理申请**的员工，按钮高亮，再点一次还原全部；空态「暂无待处理的权限申请」。
- 【查询】按钮；回车同样触发；清空搜索自动刷新。

### 2. 列表

分页展示，每页条数按页面高度自动计算（同全站列表，不固定 10 条）。

| 列 | 说明 |
|---|---|
| 用户名 | 加粗，取用户模块当前值 |
| 显示名 | 取用户模块当前值 |
| 岗位 | 岗位分配里当前绑定的岗位名称，未绑定显示「—」 |
| 本机授权 | 该员工本机的状态标签：已授权（绿）/ 未授权（灰）；本机有待处理申请的，未授权旁多一个橙色「待处理」小标签；已授权的鼠标悬停显示「授权来源 · 授权时间 · 授权人」（来源为「管理员授权」或「申请通过」） |
| 云端授权 | 同上，云端的状态 |
| 操作 | 【设置授权】每行都有；任一环境有待处理申请多一个橙色【处理申请】，点击弹出「处理权限申请」弹窗（见下）；任一环境已授权多一个【查看】，点击跳转到操作记录页签并按该员工搜索 |

排序：任一环境有待处理申请的员工在最前，其次有授权的员工（按最近一次授权时间倒序），最后两个环境都未授权的员工（按用户名升序）。列表不提供手动排序。

### 3. 设置授权（单个员工）

点【设置授权】弹窗「设置完全访问授权」：员工信息、说明「授权后员工可在员工端对应的运行方式下自行开启完全访问，数字员工将不再逐步征求其确认。本机、云端各授权各的。」，下面**本机、云端各一个勾选框**（旁边显示当前状态标签），按当前授权预勾选。

- **勾选 = 授权，取消勾选已授权的 = 收回**，按与打开时的差异提交，一次可以同时授权本机和云端、或一边授权一边收回。
- 没有任何修改时【确定】置灰。
- 某环境有待处理申请：该环境的勾选框置灰，旁边提示「有待处理的申请，请先在【处理申请】里通过或驳回」；另一个环境照常可操作。
- 已授权的环境被取消勾选时，旁边红字提示「取消勾选将收回，已开启的完全访问会立即关闭」。
- 提交时**含收回的**先二次确认：「确认收回 X 在本机、云端的完全访问权限？X 在……已开启的完全访问会立即关闭，之后需重新申请或由管理员重新授权」；只有授权的不再额外确认（弹窗本身就是确认）。
- 成功提示：「X：已授权在本机、云端使用完全访问」「X：已收回本机的完全访问权限」，两者都有时用逗号连接。
- 每个被改动的环境各写一条访问审计（授权 / 收回，带运行环境），见第六节。
- 整体提交：任一环境状态不符（该环境已有待处理申请、已授权还要授权、未授权还要收回），整体拒绝、都不改，避免半成功。

### 4. 批量授权

工具栏右侧有【批量授权】按钮（样式同岗位管理的「批量绑定」：白底描边，勾选员工后高亮并带数量徽标 N；没勾选就点击提示「请先勾选要批量授权的员工」，不弹窗），勾选多名员工后点击，弹窗「批量授权」：「将为所选 N 名员工授权完全访问，请选择运行环境」，**本机、云端两个勾选框，默认都勾上**，至少勾一个才能点【授权】。已授权、有待处理申请的（员工 × 环境）自动跳过，逐项写审计。

- **勾选框**：两个环境都已授权或有待处理申请的员工（没有可授权的）置灰，全选也不含他们。
- 成功提示「已完成 N 项完全访问授权」（N = 实际新授权的（员工 × 环境）数，授权 2 名员工的两个环境算 4 项）；有被跳过的，另提示「另有 M 项因已授权或有待处理申请已跳过」。
- 批量**不提供收回**（收回有立即关闭的后果，请逐个员工在【设置授权】里确认）。

### 5. 异常与空状态

- 首次暂无员工：「还没有可授权的员工」。
- 无查询结果：「没有符合条件的员工」，提供【清空筛选】。
- 加载失败：「加载失败」+【重试】。
- 并发：打开设置弹窗期间员工在某环境提交了申请：提交时提示「X 有待处理的本机权限申请，请先处理该申请」，关闭弹窗并刷新列表，行上随即出现【处理申请】。

## 四、处理权限申请（授权名单内，不单独占页签）

员工在员工端提交的权限申请，管理员在授权名单里处理：任一环境有待处理申请的员工行有【处理申请】；也可以点工具栏「待处理申请」只看这些员工。申请不进审核中心，也不出现在「我的申请」。

### 1. 处理申请弹窗

点【处理申请】弹出「处理权限申请」弹窗，顶部是员工信息（显示名、用户名、岗位）。下面**列出该员工所有待处理的申请**（本机、云端各最多一条），每条一张小卡：

- 运行环境标签（本机 / 云端）+「申请完全访问」+ 提交时间（精确到分钟，靠右）；
- 申请理由（选填，≤ 300 字），未填显示「（未填写申请理由）」；
- 操作：【通过】【驳回】。

处理完一条后弹窗刷新；该员工**没有待处理申请了就自动关闭**，授权名单随之刷新。**通过 / 驳回后，授权名单清掉当前筛选（该员工可能已不在「待处理申请」里），把这位员工置顶并高亮整行**，让管理员一眼看到处理后的状态（同岗位管理分配后的做法）；高亮是一次性的，下次点【查询】、改筛选或翻页时取消。已处理的申请不在本页留列表，处理结果在访问审计里查（授权 / 收回 / 通过申请 / 驳回申请四类都记）。

### 2. 通过

点【通过】弹二次确认：「确认通过 X 的本机完全访问权限申请？通过后 X 即可在员工端的本机运行方式下开启完全访问」。确认后：申请状态「已通过」，员工在**该申请的运行环境**变「已授权」（另一个环境不变），授权来源「申请通过」，写访问审计；员工端经通知模块收到"申请已通过"通知。提示「已通过 X 的本机完全访问权限申请」。

### 3. 驳回

点【驳回】弹窗：申请人及「申请本机完全访问」（运行环境）、申请理由（只读）、**驳回原因**（必填，≤ 500 字，与存储空间拒绝原因、驳回原因、回收原因同口径；占位「请输入驳回原因，将展示给申请人」）。

- 确认后：申请状态「已驳回」，员工在该环境回「未授权」；原因随通知展示给员工；写访问审计；员工端收到驳回通知。
- 驳回后员工可再次提交新申请。
- 为空阻止提交并提示「请输入驳回原因」；输入框限长 500 字，超出无法继续输入（不再另行提示）。
- 提示：「已驳回 X 的本机完全访问权限申请」。

### 4. 并发与异常

- 打开处理弹窗期间申请已被他人处理：提交时提示「该申请已被处理」并刷新弹窗与授权名单，不覆盖；申请已不存在（申请人账号被删）：提示「申请不存在」，同样刷新。
- 弹窗加载失败：「加载失败，请关闭后重试」。

## 四之二、操作记录页签

员工开启完全访问后，数字员工在会话里做了哪些操作，由员工端上传留痕，这里**只读查看、备审计**。记录方式模仿工具调用审计的「会话调用」：**记录单元是一次开启了完全访问的会话任务**，一个会话一行，会话里的具体操作在详情里看（对应客户端 PRD §3 功能点 12：客户端不展示，后台备审计）。本页签没有任何写入口，记录不可改删。

**不记会话任务名**：客户端本地对话不主动回传（数据安全考虑，同驾驶舱点赞 / 点踩口径），任务名来自对话内容，本机拿不到；**也不展示会话 ID**（工具调用审计的会话调用也没有会话标识）；一个会话的操作由客户端**打包成一条记录**上传，行标识由管理端自己生成；管理员靠「谁、什么时候、哪个环境、做了哪些操作」审计。

**记两类操作**：① 原本需要用户二次确认的操作，即上面 4 项权限下原本会弹窗的场景（附录 #1–#5），开了完全访问后免确认直接执行，结果为「成功」或「失败」；② **被客户端直接拦截的命令**——三种：毁灭级命令（`rm -rf /`、mkfs、dd 写裸盘、关机重启、fork 炸弹、`kill -1`）、`sudo -S` 猜密码、命中管理规则 `approvals.deny` 的命令（来源：附录「不弹窗的情况」第一条）；它们没有弹窗、任何人无权放行，**没有执行**，结果为「已拦截」，拦截原因写明属于哪一种。**它们的权限类型是单独一类「被拦截命令」**——不并入「执行命令」等 4 项（那 4 项只是完全访问放开的范围，毁灭级命令等不在其中，也不会因为开了完全访问而放行）。记拦截是为了让审计看到有没有人在反复尝试危险操作。读文件等本来就不弹窗的操作不记。

### 1. 筛选

- 时间范围：按会话开启时间；默认展示今天向前 90 天（含当天），单次最多可选 30 天跨度，规则与访问审计、工具调用审计一致。**管理端只展示近 90 天**：日期选择器不能选 90 天之外的日期，也不会列出更早的记录（数据后端全部留存，见第四之二节「数据口径」）。
- 运行环境：全部 / 本机 / 云端。
- 权限类型：全部 / 读写文件 / 执行命令 / 操作业务系统 / 联网与连接器 / 被拦截命令（前 4 项是完全访问放开的权限，「被拦截命令」是**单独一类**，不属于完全访问）；会话里至少有一次该类型的操作即命中。
- 搜索框：占位「搜索员工 / 操作对象」，可搜用户名、显示名、操作对象，回车或点【查询】生效。

### 2. 列表

分页展示，**按会话开启时间排序**，列头带 ↓ / ↑ 箭头，点击切换，默认 ↓ 倒序。

| 列 | 说明 |
|---|---|
| 会话开启时间 | 精确到秒 |
| 用户名 | 加粗，取用户模块当前值 |
| 显示名 | 取用户模块当前值 |
| 运行环境 | 本机 / 云端标签 |
| 免确认操作 | 会话内免确认**真正执行**的操作次数（不含被拦截的），只显示次数（成功 / 失败在详情的操作明细里看） |
| 已拦截操作 | 会话内被客户端直接拦截的操作次数，没有显示「—」，有则橙色 |
| 涉及权限类型 | 会话内出现过的权限类型，去重后顿号分隔 |
| 操作 | 【查看详情】 |

空态：「没有符合条件的操作记录」；加载失败：「加载失败」+【重试】。

### 3. 详情抽屉（只读）

点【查看详情】打开抽屉「会话详情」，分三块：

- **会话摘要**：用户（显示名 + 用户名）、运行环境；**免确认操作与已拦截操作的次数并排在同一行**（没有拦截时显示 0 次，版式不跳动）。**会话开启时间不放在摘要里，放抽屉底栏左下角**（「会话开启时间：2026-10-13 16:41:18」，右侧是【关闭】），同其他详情抽屉的底栏范式。
- **操作明细**：时间线，按发生顺序列出会话内每一步操作——权限类型标签、执行结果标签（成功 / 失败）、操作对象（命令原文、文件路径、「域名 · 点击元素」、「接口 · 入参」等，同客户端审批弹窗里展示的内容）；失败的带原因。**不展示单次操作的具体时刻**，时间线只体现先后顺序。
- **操作对象为脱敏后的内容**（规则见下面「数据口径」的脱敏规则）：路径只保留前两级目录，接口入参只保留参数名，不含参数值、表单内容与密钥口令；说明收在下面的 ? 浮层里。
- **口径说明收进「操作明细」标题旁的 ? 图标**，点击浮层显示三条：这些操作原本都需要员工逐次二次确认、该会话开启了完全访问所以直接执行并留痕；毁灭级命令、`sudo -S` 猜密码、命中管理规则的命令始终被客户端直接拦截、未执行，也记在这里并标「已拦截」；操作对象为脱敏后的内容。

### 4. 数据口径

- 只有在某个环境拥有完全访问资格的员工才会在该环境产生记录（如只授权了本机的员工没有云端记录）；员工被收回权限后，已产生的历史记录仍保留。
- 会话内一次操作都没有的（开启了完全访问但没触发过需确认的操作），不产生记录。
- 员工显示名随用户模块；**员工被删除后记录保留**（审计留存，与授权、申请随用户删除一并移除不同）。
- **留存与展示**：后端**全部留存**，管理端只展示近 90 天（更早的数据不展示、也不提供入口，需要时由后台直接查询）；员工被删除、被收回权限后的历史记录同样遵循这一口径。
- **操作对象只传脱敏后的内容**，规则（具体实现由客户端定，这里是产品口径）：文件路径只保留前两级目录，其余用 * 代替（如 `D:/客户回访/*`）；命令保留命令名与开关参数，参数里的路径按路径规则处理，疑似密钥 / 令牌 / 口令一律替换为 `***`；浏览器 / SOP 提交只记域名与点击的按钮文字，不记页面内容与表单值；连接器接口只记接口名、请求方式与路径，入参只保留参数名、不传值。管理端「操作对象」展示的就是这份脱敏内容，不再提供原文。
- 记录由员工端上传，管理端不生成、不修改；本仓用浏览器本地 mock 种子演示。

## 五、与其他模块的关系

- **员工端 · 访问权限**：员工端读取本页的授权状态决定开关是否可用；申请、驳回原因、通过结果与本页双向对应（《PRD-访问权限》§3 功能点 11～11d）。
- **通知模块**：申请通过 / 驳回由员工端通知读取本页产生的记录生成，本页不单独发通知。**这些记录就是本页要传给员工端的数据，字段与触发口径见第六节。**
- **用户**：员工清单、显示名、岗位取自用户与岗位分配；新增员工显示为「未授权」；员工被删除后其授权与申请一并移除；停用账号不进清单，其申请（含待处理）同样不展示、不计入角标、不能处理，重新启用后授权与申请一并恢复；显示名与岗位取当前值，申请上的岗位是提交时的快照。
- **访问审计**：授权、收回、通过申请、驳回申请四类动作都展示在访问审计「管理端操作」列表里（模块：用户访问权限）；审计 PRD 需同步增加该模块的记录说明与 §6.5 落给客户端的数据（本文第六节为字段来源）。
- **驾驶舱**：待办区增加「完全访问权限申请待处理」卡片，数量取待处理申请数，【去处理】进本页授权名单并打开「待处理申请」筛选（只看有待处理申请的员工）。
- **工具调用审计**：留痕不进工具调用审计。完全访问下的操作记录在本页「操作记录」页签查看（第四之二节），与工具调用审计（连接器工具调用的事后审计）各管各的。
- **审核中心**：权限申请不进入审核中心，也不出现在「我的申请」——它是员工能力申请，由管理员在本页直接处理，不涉及审核流（与存储空间扩容申请同口径）。

## 六、需要传给客户端的数据

本页与员工端之间有两个方向的数据。**管理端 → 员工端**的数据下面单独写清；管理端不推送、不生成通知、不存已读，只把结果记下来，员工端登录时和之后定期拉取，按上次拉取时间之后新增的记录增量处理。

### 1. 管理端 → 员工端

**授权状态**：员工端需要随时知道自己在当前运行环境下是「已授权 / 未授权」（未授权时还要知道有没有待处理申请，由员工端自己提交的申请记录得知），据此决定开关是否可用。以访问审计记录为准增量同步，用户标识 + **运行环境**为匹配键。

**处理结果与授权变动**落在访问审计的「管理端操作记录」里（模块：用户访问权限；字段定义与客户端用途以《prd.访问审计.md》为准，这里列出本页产生它们的时机和内容）。**四类记录同时展示在访问审计的「管理端操作」列表里**，员工端读的是同一批记录；本页不再留已处理申请的列表，处理人、处理时间、处理结果以访问审计这几类记录为准（申请单本身的状态、理由仍由管理端保存，供员工端按申请单标识对应）。

| 动作 | 本页触发 | 传给员工端的数据 | 员工端据此做什么 |
|---|---|---|---|
| 通过申请 | 处理申请弹窗点【通过】 | 动作「通过申请」、员工用户名与**用户标识**、**运行环境**、**申请单标识**、操作时间（秒级）、记录标识 | 铃铛通知「你的完全访问权限申请已通过…」；状态变已授权，开关可用 |
| 驳回申请 | 处理申请弹窗点【驳回】并填原因 | 动作「驳回申请」、员工用户名与用户标识、**运行环境**、**申请单标识**、**驳回原因**（≤ 500 字，原样提供）、操作时间、记录标识 | 铃铛通知带原因；状态回未授权，可再申请 |
| 授权 | 授权名单【设置授权】里勾选授权，或【批量授权】（每人每个环境一条） | 动作「授权」、员工用户名与用户标识、**运行环境**、申请单标识为空、操作时间、记录标识 | 状态变已授权，开关可用；本期不发通知，只同步状态 |
| 收回 | 授权名单【设置授权】里取消勾选已授权的环境（每个环境一条） | 动作「收回」、员工用户名与用户标识、**运行环境**、申请单标识为空、操作时间、记录标识 | 状态变未授权，立即关闭已开启的完全访问；本期不发通知，只同步状态（收回后员工端立即关闭） |

**不传**：处理人（通知不展示）。**员工靠用户标识匹配**（用户名可能改名），**同一申请只发一条通知靠申请单标识 / 记录标识去重**。记录保留全部天数，不受访问审计页"近 90 天"展示窗口限制，且只读、不可改删。

### 2. 员工端 → 管理端：权限申请

员工在员工端申请框提交时传给管理端的数据，本页授权名单里的【处理申请】弹窗展示和处理它：申请人（用户名、用户标识）、岗位（提交时的快照）、**运行环境**（本机 / 云端，员工按他当前的运行方式申请）、申请理由（选填，≤ 300 字）、提交时间。**员工端不上传开关的开 / 关状态**。

**操作留痕**：员工在某会话任务里开启完全访问后，员工端按**会话**上传一条记录供「操作记录」页签展示——员工（用户名、用户标识）、运行环境（本机 / 云端）、会话开启时间（秒级）、会话内的操作列表（原本需要二次确认的操作，外加被客户端直接拦截的命令，按发生顺序；每项含：权限类型（上述 4 项之一，被拦截的为单独一类「被拦截命令」；技能回放的提交步归「操作业务系统」，操作对象里标明来自技能回放）、操作对象、执行结果（成功 / 失败 / 已拦截）、失败或拦截原因）。

### 3. 触发口径与访问审计展示

| 动作 | 触发 | 变更内容（访问审计展示用） | 访问审计页是否展示 |
|---|---|---|---|
| 授权 | 授权名单设置授权 / 批量授权（**每位员工的每个环境一条**，如同时授权本机和云端 = 2 条） | 「未授权 → 已授权（本机）」 | 是 |
| 收回 | 授权名单设置授权里取消勾选已授权的环境（每个环境一条） | 「已授权 → 未授权（本机）」 | 是 |
| 通过申请 | 处理申请弹窗通过 | 「未授权 → 已授权（申请通过·本机）」 | 是 |
| 驳回申请 | 处理申请弹窗驳回 | 驳回原因（运行环境在记录的运行环境字段里） | 是 |

## 七、不做什么

- ❌ 分档授权（只放开文件 / 只放开联网等），只有有 / 没有两态。
- ❌ 按权限类型（上述 4 项）拆开授权：授权只分有 / 没有；操作记录里的权限类型只用于给留痕分类。
- ❌ 按岗位 / 角色批量授权（本期仅按员工，外加列表多选批量授权）。
- ❌ 授权有效期、到期自动收回。
- ❌ 展示员工当前"是否已开启完全访问"（开关状态只存员工本机，不上传）。
- ❌ 在操作记录里改动、删除或导出员工的操作留痕（只读备审计；导出等需求后续另议）。
- ❌ 权限申请的多级审批、自动通过规则。
